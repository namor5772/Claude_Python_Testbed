## Architecture (SelfBot.py)

**Single class design** — The `App` class contains all UI, API, tool execution, and persistence logic. No separate modules.

**Model picker & per-model parameters** — The Provider is fixed to Anthropic. `_fetch_available_models` pulls the live `models.list()` and hides deprecated / soon-to-be-retired ids via `DEPRECATED_MODEL_PREFIXES` (Opus 4.1, the dated 4.0 ids `claude-(opus|sonnet)-4-20…`, and every Claude 3.x / 2.x) so newer models appear automatically and only the retiring ones drop out; Opus 4.5 / Sonnet 4.5 stay (still active). Capability detection is **version-parsed**, not a hardcoded set — `_parse_claude_major_minor(mid, families)` yields a `(major, minor)` tuple (Claude 5 ids dropped the minor, so `claude-sonnet-5` → `(5, 0)`; dated snapshots keep working because the date lands in the minor slot), and the helpers apply per-family thresholds: `_is_adaptive_model` (Opus/Sonnet 4.6+ + always-on) picks the **Thinking-mode combobox** over the manual checkbox+budget; `_anthropic_mode_values` builds the combobox list per model — Fable/Mythos 5 and 5.1 drop **Off** (always-on: an explicit disable is HTTP 400; prefix-matched via `ALWAYS_ON_THINKING_PREFIXES`, so `claude-fable-5-1` needed no entry), **Xhigh** needs Opus 4.7+ / Sonnet 5+, **Max** needs Opus 4.6+ / Sonnet 4.6+; `_rejects_temperature` (Opus 4.7+ / Sonnet 5+ / Fable-Mythos) keeps the temperature spinbox disabled and never sends the param (HTTP 400 otherwise); `_thinking_on_by_default` (Opus 5+ / Sonnet 5+ / always-on) makes "Off" send an explicit `thinking={"type":"disabled"}` so the model doesn't silently think against the non-thinking cap. `MANUAL_THINKING_PREFIXES` (Opus/Sonnet 4.5, Haiku 4.5) keep the checkbox + `budget_tokens` UI; `claude-3-5-sonnet` is deliberately absent (extended thinking arrived with 3.7/4 — a thinking block to a 3.5 model is HTTP 400). Both request builders — the live `stream_worker` `api_kwargs` and the debug `_payload_for_display` — funnel through the shared `_apply_thinking_params(kwargs)` so they never drift; adaptive thinking is sent as `{"type":"adaptive","display":"summarized"}` so the Show Thinking pane isn't blank on Fable / Opus 4.7+ (their default became `"omitted"`). For the Fable/Mythos class the same builder adds Fable 5.1's `thinking.block_binding` and a `fallbacks` value (see **Claude Fable 5.1 harness surface** below); `fallbacks` sits in the kwargs under its wire name so the debug dump shows it, and `stream_worker` moves it into `extra_body` because anthropic 0.84.0 has no typed kwarg for it. A reactive `self._no_temperature` set (populated by the `stream_worker` BadRequest handler on a 400 naming temperature) backstops any future rejecting model the version parser doesn't know yet; `self._anthropic_unsupported` does the same for the two Fable beta surfaces. Model + all thinking params persist via `app_state.json` (last-live-state) and the system-prompt bundle; `_on_model_selected` re-coerces a stale saved mode (e.g. an unsupported `Max`/`Xhigh` → `High`, `Off` on an always-on model → `Adaptive`).

**Tool system** — Global tool lists define API tool schemas:
- `TOOLS` — Core tools always sent to the API (`run_command`, `csv_search`); Anthropic server-side `web_search`/`code_execution` are appended in `stream_worker`
- `DESKTOP_TOOLS` — 13 pyautogui-based tools, conditionally included when Desktop checkbox is enabled
- `BROWSER_TOOLS` — 11 Playwright/CDP tools, conditionally included when Browser checkbox is enabled
- `SELFBOT_META_TOOLS` — 2 meta tools (`manage_skills`, `manage_prompts`), included when the Meta checkbox is enabled
- `GOOGLE_TOOLS`/`PROTON_TOOLS`/`OUTLOOK_TOOLS`/`MCP_TOOLS` — imported from `myagent.constants`, included when the Google/IMAP/Outlook/MCP checkboxes are enabled (see the tool-subsystems note below)
- `_get_tools()` assembles the final tool list dynamically based on UI toggle state

**Adding a new tool** requires three changes:
1. Add schema dict to the appropriate tool list (`TOOLS`, `DESKTOP_TOOLS`, or `BROWSER_TOOLS`)
2. Add a `do_<tool_name>()` method to the `App` class
3. Wire it up in the `_execute_tool()` method's tool dispatch block (`elif block.name == "..."`)

**MyAgent tool subsystems (Meta / MCP / Google / IMAP / Outlook)** — SelfBot reuses MyAgent's native MCP + mail mixins **by inheritance** (not reimplementation): `class App(MCPMixin, GmailMixin, ProtonMailMixin, OutlookMixin)`, imported optionally at the module top (`try: from myagent… except:` → empty-class stubs), gated by `_HAS_MYAGENT_TOOLS` plus per-provider `_HAS_MCP`/`_HAS_GOOGLE`/`_HAS_PROTONMAIL`/`_HAS_OUTLOOK` (from `myagent.constants`). The mixin order matches MyAgent's so Proton/Outlook's helper-prefix anti-shadowing (vs Gmail's unprefixed `_header`/`_extract_bodies`) holds. These tools are **Anthropic-only** (SelfBot has no other provider) and each subsystem's checkbox is `state=DISABLED` when its lib is absent (Meta needs none; Proton is labelled **IMAP**).
- **Host contract** (all the mixins need): `self.root`, `self.queue`, and `self._disabled_confirm_patterns` (a `set`, added in `__init__` — empty means every destructive mail action confirms). `__init__` also calls `_init_mcp_state()`/`_google_init_state()`/`_proton_init_state()`/`_outlook_init_state()` to seed connection caches. MCP is the only subsystem that eagerly connects — `root.after(100, self._connect_mcp_servers)` at startup **regardless of the checkbox** (like MyAgent; the checkbox only gates whether the tools are *offered*), and it is torn down in `_finish_close` via `_disconnect_mcp_servers()`.
- **Toggles**: five `BooleanVar`s (`meta_enabled`/`mcp_enabled`/`google_enabled`/`proton_enabled`/`outlook_enabled`) in a **second checkbox row** (grid row 7, directly under the Debug/display-toggle row 6) that also holds the **Desktop** and **Browser** toggles (moved down from the Debug row) and the SelfBot-native **Pause** toggle; the eight tool toggles thus share one row. Both rows are left-aligned (`sticky="w"`) and `attach_label` sits at row 8. Persisted in `app_state.json` (keys `meta_enabled`…`outlook_enabled`) and restored only when the corresponding lib is present (a saved-on flag can't re-enable a disabled checkbox). **Convo is deliberately NOT wired** (irrelevant to SelfBot).
- **`_get_tools()`** appends `SELFBOT_META_TOOLS` (Meta), the runtime-populated `MCP_TOOLS`, and deep-copied `GOOGLE_TOOLS`/`PROTON_TOOLS`/`OUTLOOK_TOOLS` with each tool's `account` enum patched from `_get_google_account_names()`/`_get_proton_account_names()`/`_get_outlook_account_names()`.
- **`_execute_tool()`** routes (before the native chain): MCP by `block.name in self._mcp_tools_by_name` → `do_mcp_call(name, input)`; mail by `startswith(("gmail_","proton_","outlook_"))` → dynamic `getattr(self, f"do_{name}")(input)`; Meta → `do_manage_skills`/`do_manage_prompts`.
- **Meta is SelfBot-native**, not MyAgent's `META_TOOLS`: MyAgent's `manage_instructions`/`run_instruction` are tied to its agent-instruction system, which SelfBot lacks. `SELFBOT_META_TOOLS` = `manage_skills` (the shared `skills/` SKILL.md tree, identical to MyAgent) + `manage_prompts` (CRUD `system_prompts.json`, SelfBot's analog of `manage_instructions`). `do_manage_skills`/`do_manage_prompts` live on the App; UI refreshes (`_update_skills_button`) are scheduled via `root.after(0, …)` for thread safety.
- **Queue types**: the mail mixins emit `{"type": "warning"}` on confirm-bypass — `check_queue` renders it in the red `error` tag, always shown (independent of Activity). MCP emits `{"type": "tool_info"}` (already handled).

**Pause/rest tool (`pause_conversation`)** — the duo's hang-up button that isn't a shutdown. Auto-chat re-injects every completed turn into the peer forever, so a duo conversation had no way to genuinely END except killing a process (observed: given `run_command`, duo chats *always* ended in a model-driven graceful taskkill — the only exit in the action space). `PAUSE_TOOLS` (one tool, optional `reason` param) is gated by the **Pause** checkbox in the tool row (no lib needed; wired like MyAgent's Convo toggle — a per-environment behavioural affordance). `do_pause_conversation` is the model-callable analog of clicking Auto: OFF: it marshals the Tk work onto the main loop via `root.after(0, …)` (the streaming worker never touches widgets) — `_auto_chat` off, `_auto_chat_user_off=True` (stops `_poll_for_peer` instantly re-arming), `_send_delay=0`, button repaint (instance 1 only; instance 2 has no `_auto_chat_btn`) — and posts a ⏸ `{"type": "warning"}` notice (always shown). The `_pause` callback runs long before the turn's `complete` event (the model still has a final API round to write its closing note), so that closing reply is held as `_pending_injection` rather than delivered; it also resets `_current_response_text`, because a *silent* pause (empty closing text emits no `label` event, which is what resets the accumulator) would otherwise leave the PREVIOUS reply latched as the pending injection and a later Auto: ON would re-send that stale text to the peer as a duplicate (observed live 2026-07-13). The peer instance keeps running: the duo-shutdown watchdog only fires when a *window* disappears, so a paused duo just goes quiet with both windows open. **The pause is a rest, not a latch** — `_model_paused` (cleared by any manual `_toggle_auto_chat`) marks it as model-initiated, and `_resume_from_model_pause()` (called at the top of `send_message`, the single funnel for BOTH human-typed and peer-injected messages) re-arms auto-chat on the next fresh message, dropping the held closing reply (AUTO_MSG_FILE is single-slot; the fresh reply carries the conversation) and posting a ▶ resumed notice. A human's manual Auto: OFF is never auto-resumed — only a model pause is. This matters because instance 2 has no Auto button: before the auto-resume, a model-pause on instance 2 made the duo unresumable from the UI (observed live: each new human message got exactly one reply that was composed but never delivered back). Auto: ON on instance 1 still works as a manual resume and flushes the held reply. NOT in `PARALLEL_SAFE` (mutates shared auto-chat state). Persisted as `pause_enabled` in `app_state.json`, bundled as `pause` in the system-prompt environment (`_capture_prompt_settings`/`_apply_prompt_settings`/`_PROMPT_TOGGLE_KEYS` + a `manage_prompts` param). The tool description is deliberately **neutral** (states what it does, not when to prefer it over closing) so duo runs measure the model's own choice of exit — added 2026-07-13 to test whether the always-self-taskkill pattern was just "the only door out of the room".

**Threading model** — API calls run in a background `stream_worker` thread. A `queue.Queue` passes events (text, thinking, tool info, errors) to the main thread, polled every 50ms via `root.after()`. `_ensure_newline()` guarantees each new output block starts on a fresh line; an `ensure_newline` queue event between loop iterations prevents text merging when Activity is off.

**Thinking accumulator lifecycle** — `_current_thinking_text` is reset at `thinking_start` (not at `label`), so the accumulated thinking text survives past the label event and is available when `complete` fires to inject into the peer instance.

**Show Thinking checkbox** — The `show_thinking` BooleanVar (defaults False) gates display of thinking blocks in `check_queue` and `_poll_auto_msg`. This is separate from `thinking_enabled` which controls whether the API generates thinking blocks. Both must be on for thinking to appear in the output.

**Save Thinking checkbox** — The `save_thinking` BooleanVar (defaults False) controls whether thinking and redacted_thinking blocks are preserved in saved chat JSON files. When enabled, Anthropic thinking blocks (including cryptographic signatures) are kept during `_serialize_messages()`, allowing loaded chats to continue with full reasoning context. When disabled, thinking blocks are stripped to reduce file size. Has no effect for OpenAI models, whose reasoning summaries are display-only and never stored in messages. Persisted in the app's state file.

**Dual geometry persistence** — State files store `geometry` (solo mode) and `duo_geometry` (duo mode via `--no-geometry` flag) independently. `_duo_mode` is set in `__init__` from `sys.argv` before any save can occur. On save, the app reads the existing state file to preserve the other mode's geometry key. **Second-instance cascade (solo mode)** — a manually-opened instance 2 restores the *same* saved solo `geometry` as instance 1 (a fresh instance 2 even bootstraps its geometry from instance 1's `app_state.json` in `_load_last_state`), so it would land pixel-perfectly on top of instance 1 and look like nothing opened / a crash. `_load_last_state`'s solo branch detects this by comparing instance 2's restored position against instance 1's saved position (read from `APP_STATE_FILE`) and, only when they nearly coincide (<30 px), cascades instance 2 down-right by `CASCADE_OFFSET` (60 px), clamped on-screen. Cascade-only-on-collision preserves deliberate manual placement and prevents drift across launches (once offset, it no longer collides). The duo path is unaffected — it already tiles side-by-side. This is only reachable because the launcher (`SelfBot_Win.ps1` / `SelfBot.app`) is always-launch-fresh, not launch-or-focus, so double-clicking the shortcut twice genuinely opens the self-chat pair.

**Shared-store sync** — `PROMPTS_FILE` and `SKILLS_DIR` resolve through `myagent.datapaths` (try-imported with repo-root stubs when the package is absent) to **`<OneDrive>/MyAppShare/`**, shared with MyAgent — see CLAUDE_MYAGENT.md's datapaths + skills-tree blocks for the full semantics (one-shot repo→OneDrive migration, atomic saves, conflict-fork absorption, never-overwrite-unparseable). Since 2026-08-07 skills are the per-skill `skills/<Name>/SKILL.md` tree (`_load_skills` → `_load_skills_tree`, `_save_skills` → diff-aware write-only `_save_skills_tree`, deletes explicit via `_delete_skill_tree_entry` at both delete callsites); the no-myagent stub fallbacks (`_sb_skill_*`) mirror the exact same file format minus OneDrive fork healing, so a standalone SelfBot.py stays store-compatible. `_load_saved_prompts` is the prompts absorb point; a corrupt/half-synced prompts file now yields a session-only Default instead of the pre-2026-07-19 crash (`json.load` was unguarded). `STORES_SYNCED` appends "— synced" to the title — appended, not prepended, so Windows peer detection's "Claude SelfBot" substring match still holds.

**Skills system** — Three modes: disabled, enabled (injected into system prompt), on-demand (retrieved via `get_skill` tool). Each skill may carry an optional `description` (what it does + when to use it): `_format_on_demand_listing` (an in-file copy of SkillsMixin's staticmethod, like `_trim_history_for_context`) renders on_demand skills as a bulleted name — description index in the system prompt — the Agent-Skills-style routing signal; undescribed skills list by bare name. `do_manage_skills` accepts `description` on create/update ("" clears it; >1024 chars warns but saves), and both editors' SAVE paths **merge into the existing entry** rather than whole-entry replace, so fields one surface doesn't show survive a save from the other. Managed through `_build_system_prompt()` and `_get_tools()`. Contract unit-tested in `tests/test_skills_description.py` (against the mixin; SelfBot can't be imported under test). The **Skills Manager** dialog (`open_skills_editor`) is brought to parity with MyAgent's `skills_mixin`: an expanding Skill Name entry with SAVE / DELETE / NEW hugging the right edge, a "Cycle Mode" button (and the `<space>` key) above a `width=40` listbox that shows each skill's mode via a `[ON]`/`[OD]`/blank prefix plus green/blue coloring, and a content editor on the right. **Geometry persistence** follows MyAgent's withdraw→build→restore→deiconify pattern: on open it applies the saved geometry through `_sanitize_geometry(min_w=400, min_h=300)` (or defaults to `900x500`); the `WM_DELETE_WINDOW` handler captures `win.geometry()` into `_last_skills_dialog_geometry` and calls `_save_last_state`, which persists it in `app_state.json` as `skills_dialog_geometry` (also captured live by the 5-second periodic save while the dialog is open). `_post_skill_ui_refresh()` marshals tool-driven edits (`do_manage_skills`, which runs on the streaming thread) onto the Tk main thread via `root.after(0, …)`, repainting both the Skills button label and an open dialog's listbox through the stored `_skills_refresh_list` closure. SelfBot has **no per-instruction `skill_modes`** (it has no instruction system — MyAgent's `_restore_skill_modes` is deliberately not ported); the `skills/` tree is the single sticky global store.

**Command safety / confirm patterns** — `run_command` accepts an optional `timeout` (clamped 5–600 s at dispatch, default 30); `run_powershell(command, timeout)` is Popen-based and on expiry `_kill_process_tree` kills the whole process tree (`taskkill /T /F` on Windows, `killpg` + `start_new_session` on POSIX) before a bounded final pipe read — the MyAgent fix of 2026-07-23 ported verbatim (a timed-out nested shell used to hold the inherited stdout/stderr pipes and block the post-kill `communicate()` forever; see CLAUDE_MYAGENT.md). `run_powershell` gates every `run_command` through `_check_command_safety`, a two-tier check against platform-specific regex lists (`COMMAND_BLOCKED` → rejected outright; `COMMAND_CONFIRM` → needs approval). Brought to parity with MyAgent's safety mixin: a **"Safety" button** (in the main toolbar, next to Skills) opens the **Safety — Confirm Patterns** dialog (`_open_ps_safety_dialog`) — a scrollable list of checkboxes (one `tk.Checkbutton` per pattern embedded in a `tk.Text` for reliable scrolling), where **checked = confirm required, unchecked = bypass**. Sections: the shell `COMMAND_CONFIRM` regex patterns, plus Gmail / IMAP(Proton) / Outlook destructive-tool names (each gated by `_HAS_GOOGLE`/`_HAS_PROTONMAIL`/`_HAS_OUTLOOK`) — the *same* `self._disabled_confirm_patterns` set is consulted by both `_check_command_safety` and the mail mixins' `mail_common.confirm_action`. Toggling a box calls `_toggle_confirm_pattern` (discard/add to the set, refresh the button label, `_save_last_state`). When a matched pattern is bypassed, `_check_command_safety` returns `"skipped"` and `run_powershell` posts a `{"type": "warning"}` ⚠ notice (rendered in red by `check_queue`, always shown regardless of Activity) instead of popping the confirm dialog; the confirm dialog itself (`_request_confirmation`) shows a red "Triggered by: <pattern>" line naming the matched pattern. The Safety button label shows a bypass count (`Safety (N bypassed)`) via `_update_ps_safety_button`. **Persistence**: `_disabled_confirm_patterns` is stored in `app_state.json` as `disabled_confirm_patterns` (a sorted list ↔ set) and the dialog geometry as `ps_safety_dialog_geometry` — both **top-level**, not per-instruction (SelfBot has no instruction system; MyAgent stores them per-instruction). Both warning sources (`run_powershell` and `mail_common`) put the ⚠ sign in the message content, so `check_queue` renders it verbatim. Note: the bare-switch `COMMAND_CONFIRM` entries for `-Force` / `-Recurse` are anchored with a `(?<!\S)` negative-lookbehind (`(?<!\S)-Force\b` / `(?<!\S)-Recurse\b`), so they match when the flag sits at a line start or after whitespace. The earlier `\b-Force\b` / `\b-Recurse\b` form (inherited verbatim from MyAgent) was a latent no-op — a leading `\b` can't assert a word boundary before `-` when it's preceded by a space (both are non-word chars) — and was corrected in commit `758e20b`.

**System prompt = environment bundle** — Each saved system prompt in `system_prompts.json` bundles a full main-screen environment, analogous to MyAgent's per-instruction settings. Entries are `{name: {text, my_name, my_friend, model, temperature, thinking_enabled/effort/budget/mode, desktop, browser, meta, mcp, google, proton, outlook, pause, skill_modes, disabled_confirm_patterns}}` — everything on the main screen EXCEPT the Debug/display-toggle row (Debug / Tool Calls / Activity / Show Thinking / Save Thinking), which stays global. `_load_saved_prompts` migrates the legacy flat `{name: "text"}` format to the dict form eagerly on launch (called unconditionally from `_load_last_state`, idempotent); `_prompt_entry_text(entry)` reads the text from either form (named to avoid colliding with the `_prompt_text` editor widget). **Save** (`_save_prompt` / the editor's SAVE button) snapshots the current live main screen via `_capture_prompt_settings()` and writes `{"text": …} + settings`. **Load** (selecting a prompt in the editor combo → `_on_prompt_selected`) restores the whole environment via `_apply_prompt_settings(entry)`, which applies only keys present in the entry — so a legacy text-only prompt leaves the current environment untouched. Skill modes apply **session-only** via `_restore_skill_modes` (does NOT rewrite the skills store, the sticky global source of truth — matching MyAgent; skills absent from the snapshot fall back to disabled for that session). The tool-row toggles (now including Desktop/Browser) and the Safety confirm-bypass set are also persisted independently in `app_state.json` as last-live-state, which serves as the startup baseline (and covers the no-prompt case plus non-bundled keys — Save Thinking, delay, geometry). **On startup the current system prompt is authoritative**: after the independent last-live-state restores, `_load_last_state` re-applies the remembered prompt's full bundle via `_apply_prompt_settings(prompts[last_system_prompt_name])`, so the **skills AND the rest of the layout reflect the current prompt** — not a session that drifted a toggle without re-saving. This is what closes the gap where `_restore_skill_modes` was never called at launch (skill modes previously came only from the skills store); it stays session-only (still does not rewrite the skills store), the 2nd-instance name swap survives (names are guarded inside `_apply_prompt_settings`), and a legacy text-only prompt is a safe no-op (no bundled keys). The `manage_prompts` meta-tool is **bundle-aware** (brought to parity with SelfBot's environment-bundle prompts, mirroring MyAgent's `manage_instructions`): `read` returns the text plus a JSON dump of the bundled environment; `create` writes a full bundle — inheriting the current live `model`/`temperature`/`thinking_*`/`skill_modes`/`disabled_confirm_patterns` from **thread-safe plain attributes** (NOT `_capture_prompt_settings()`, which reads Tk widgets and is main-thread-only — `do_manage_prompts` runs on the streaming worker), with the tool toggles taken from params defaulting OFF and the terminal names bundled only if explicitly passed; `update` overlays any provided bundle field (text, model params, toggles, names) and **merges** `skill_modes` (only listed skills change), leaving the rest intact. Anthropic-only, so unlike `manage_instructions` there is no `provider`/`conversational` field, but there IS a `proton` toggle and `my_name`/`my_friend`. Prompts the tool creates load correctly through `_apply_prompt_settings` (same key set as `_capture_prompt_settings`), including the on-startup apply. The **`apply` action** lets the model switch the LIVE session to a saved prompt (text + full environment) on command — create/update/delete are disk-only, `apply` is the one action that mutates live state. Because `_apply_prompt_settings` touches main-screen Tk widgets (name entries, model/thinking vars, tool-toggle `BooleanVar`s, `_on_model_selected`), `do_manage_prompts` marshals it onto the Tk loop via `root.after(0, …)` + a `threading.Event` wait (same main-thread hand-off as `_request_confirmation`), also setting `self.system_prompt`/`self.system_prompt_name` + `_update_title` so the switch is complete; it catches UI errors into a message and has a 10 s timeout so a wedged main thread can never hang the worker.

**Prompt caching (`cache_control`)** — ported from MyAgent 2026-07-31 (see CLAUDE_MYAGENT.md for the cost audit that found it: Anthropic caching is strictly **opt-in**, and neither app had ever set a breakpoint, so every call re-sent the whole growing prefix at the full miss rate). SelfBot is the bigger beneficiary of the two: a duo self-chat grows without bound by construction — that is *why* `_trim_history_for_context` exists — and every turn re-sends all of it. Two staticmethods on `App` (SelfBot keeps its own copies, like `_trim_history_for_context`, rather than importing `AnthropicMixin` — the `myagent` import is the optional/stubbed kind): `_cache_system` wraps the system prompt in a cached text block, which covers the tool array too (the prefix is ordered tools → system → messages and a breakpoint caches everything before it), and `_cache_messages` places two rolling markers on the newest eligible turns — three total, under Anthropic's ceiling of four. `CACHE_CONTROL` (module constant, near `MAX_TOKENS`) pins the **default 5-minute TTL** deliberately: writes cost 1.25x and match `ANTHROPIC_PRICING`'s cache-write column, so `_get_pricing`'s four-bucket cost stays exact (`ttl: "1h"` would need the `extended-cache-ttl-2025-04-11` beta and 2x writes). Invariants: **history is never mutated** (only breakpointed messages are shallow-copied — `stream_worker` works on `messages` and writes it back to `self.messages` on success, and the overflow handler trims it in place; mutating it here would accumulate stale breakpoints past the ceiling); the **wire copy is rebuilt inside the retry loop**, because the overflow trim's `del messages[:cut_at]` previously reached the retry via `api_kwargs["messages"]` being the same object, which a copy breaks; and assistant turns are skipped (line ~5493 appends `final_message.content` verbatim — SDK Pydantic blocks, not dicts), landing the markers on the user turns. `_payload_for_display` applies both helpers too, for the same no-drift reason `_apply_thinking_params` is shared. A trim invalidates the cache by changing the prefix — one re-write, then the discount resumes. Live-verified 2026-07-31 through SelfBot's own staticmethods (`cache_write=4429` then `cache_read=4429`, `input=2`); watch it in the cost line's `cache_read:` field with Activity on.

**API cost tracking** — `stream_worker` computes the Anthropic cost of each API call from `final_message.usage` via `_get_pricing(model)` — a longest-prefix lookup into MyAgent's `ANTHROPIC_PRICING` table (imported from `myagent.constants` to stay in sync), which prices the four **disjoint** token buckets separately: `input_tokens` × input rate, `output_tokens` × output rate, `cache_creation_input_tokens` × cache-write rate, `cache_read_input_tokens` × cache-read rate. Costs accumulate into `self._session_cost` **across the whole process** (all messages and chats), and each call emits a `cost_update` queue message that `check_queue` renders in the blue-monospace `cost_info` tag as `$x this call | $y session (in:… out:…)`, **gated by the Activity toggle** (like MyAgent). On graceful close, `_finish_close` calls `_log_api_cost(self._session_cost)`, which appends one `{timestamp};Anthropic;{model};{cost:.4f};{params};;{prompt};{calls}` line — `params` (5th field, 2026-08-10) comes from SelfBot's own `_get_model_param_summary()` (the Anthropic-only mirror of MyAgent's ui_mixin helper: `mode=X` for adaptive models, `thinking=<budget label>` for manual ones, `temp=` only when actually sent), comma-joined; it reflects the settings at close, matching how the model field already works; the 6th field (MyAgent's TIME(sec) run duration) is deliberately EMPTY — a self-chat's duration is window-open time, not a comparable run metric — so the two 2026-08-16 fields land in MyAgent's positions: `prompt` (7th → the viewers' INSTRUCTION column) is `system_prompt_name`, the active saved system prompt — SelfBot's analogue of an Agent Instruction, blank when none is loaded — whitespace-collapsed with any `;` turned into `,`; `calls` (8th → CALLS) is `_session_calls`, incremented beside `call_num` in `stream_worker` so it totals the process's API round-trips across every message and chat, like `_session_cost` — to this machine's `APICostLog_<machine>.txt` in the OneDrive share — **the same file MyAgent writes** (`APICOST_LOG_FILE` resolves through `datapaths.resolve_costlog` in the optional-import block, with a repo-root `APICostLog.txt` stub fallback when the myagent package is absent), viewable via the API Cost Log launcher, which aggregates every machine's file. Skipped when the cost is zero (unmatched model prefix / no usage); best-effort, never raises. Before appending, `_log_api_cost` calls the shared `rotate_log_if_needed(APICOST_LOG_FILE, APICOST_LOG_MAX_BYTES)` (imported from `myagent.helpers` in the optional-import block, with a no-op stub when the package is absent) — the same one-slot 100 KB rotation MyAgent and Heartbeat.py use, archiving an over-cap log to `APICostLog.txt.old` and restarting it with a marker line. The key difference from MyAgent: MyAgent logs once **per agentic-loop run**; SelfBot logs once **per process, on close**, because a chat session spans many messages.

**DPI handling (SelfBot)** — `SetProcessDpiAwareness(2)` is called before any window creation. On macOS, Quartz captures at physical pixel resolution; `_capture_single_display()` resizes to the display's logical dimensions (from `_get_display_rects()`) so coordinates align with pyautogui's logical coordinate space. On Windows with DPI awareness, all coordinates are physical — no DPI alignment needed. The subsequent resize to provider API limits is tracked by `_screenshot_scale`; all coordinate-using tools compute `round(img_coord * scale) + offset` with `int()` type conversion for Gemini proto compatibility. `_screenshot_dims` tracks the last image dimensions for bounds checking. `pyautogui.PAUSE` is set to 0.1s.

**Note on MyAgent DPI** — MyAgent uses the newer `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` (i.e. `-4`), falling back to v1 then to legacy `SetProcessDPIAware()`. V2 fixes broken multi-monitor behavior under v1 when monitors have different DPI scaling (e.g. 100% primary + 225% secondary): v1 reports the secondary's rect as a logically-scaled smaller size, causing `ImageGrab.grab` to return a low-res image and `pyautogui` clicks to land in the wrong place. V2 returns true physical pixels per monitor regardless of per-monitor DPI.

**Auto-save on close** — When closing (via [X] button or `taskkill`), all instances auto-save their chat as `.json` + `.txt` to `saved_chats/`. Uses the name from the Save Chat entry if provided, otherwise auto-generates from the first user message. Instance 2's files are suffixed with `_` via `_save_name()` to avoid collisions. A periodic auto-save every 5 seconds on all instances also protects against force-kill data loss. Names pass through `_sanitize_filename`, which maps Windows-invalid characters AND control chars (`\x00`–`\x1f`) to `_` — a multi-line first user message otherwise put literal newlines into the auto-generated filename and Windows `open()` failed with `OSError 22`. The two saves in `_finish_close` are wrapped best-effort for the same incident: the close chain runs with `_closing` already latched, so an unhandled save exception aborted the close before `root.destroy()` and every later [X] click was silently eaten by the re-entrancy guard — a dead close button on a healthy window (observed live 2026-07-13; the periodic saver already swallowed the identical exception every 5 s, which is why no chat file ever appeared). A failure past the latch must never abort the close.

**Peer detection (cross-platform)** — `_poll_for_peer` (2 s cadence) arms auto-chat and shows instance 1's Auto button + Delay spinner when another SelfBot is running. Windows enumerates visible "Claude SelfBot" windows via pygetwindow; that library is Win32-only and reading another app's window title on macOS needs a Screen Recording consent, so `_macos_peer_pids` detects by **process** instead — a python executable with a `SelfBot.py` argument in `ps -axo pid=,command=` output (a SelfBot process IS a live window: a Tk failure kills the process, and a zombie's parenthesised ps command never matches). Fixed 2026-07-13; before this, the non-Windows branch hardcoded `peers = []`, so macOS never paired — no Auto button, no delay spinner, and no cross-instance injection (the `complete` handler only writes `selfbot_auto_msg.json` when `_auto_chat` is on). The Auto button itself is a `tk.Button` on Windows but a click-bound raised `tk.Label` on macOS: Aqua tk.Buttons ignore `bg`, which rendered the green/red state as invisible white-on-white.

**Graceful duo shutdown** — Pressing [X] on either instance stops auto-chat, waits for any active streaming to finish, saves both instances' chats, then closes the peer: `WM_CLOSE` messages on Windows, `SIGTERM` on macOS. `_handle_sigterm` (installed in `__init__`, macOS only — Windows gets this via WM_CLOSE) schedules `_on_close` onto the Tk loop, so a plain `kill`/`pkill` also gets the graceful close-and-save (the macOS analog of `taskkill` without `/F`); the `_closing` guard stops the peers from bouncing the shutdown back and forth. A peer SIGTERMed mid-stream finishes its reply first (the `_on_close` streaming wait), then saves and exits — verified live 2026-07-13. **Ungraceful peer death is covered by a watchdog in `_poll_for_peer`**: once an instance has been paired (`_ever_had_peer`, hoisted to set on any peer sighting), three consecutive peer-less polls (~6 s; enumeration-failure polls don't count, so a pygetwindow hiccup can't false-fire) mean the peer died without reaching `_finish_close`'s broadcast — crash, `taskkill /F`, or a model-driven self-kill via `run_command` (`taskkill`/`Stop-Process` are only CONFIRM-tier, so a confirm click or Safety bypass allows them). The survivor posts a ⚠ warning and runs the same graceful `_on_close` (finish streaming, save chat, exit), making "close one → both close" hold for every death mode, not just [X]. Added 2026-07-13 after a live duo session where instance 1's model force-killed its own process on request and instance 2 lingered solo. Note the dying instance's own final in-flight reply is unavoidably lost on a force-kill (no close-save runs; the 5 s periodic auto-save bounds the loss) — a model wanting a clean exit should use `taskkill` *without* `/F` (WM_CLOSE → full graceful duo shutdown, both chats saved).

**API retry logic** — `stream_worker` retries up to 10 times on transient API errors. Rate-limit errors (429) use exponential backoff capped at 60s (~6.5 min total). Overload errors (529) use exponential backoff capped at 90s (~10 min total). This makes the app resilient to prolonged Anthropic API outages without absurdly long individual waits.

**Context-overflow recovery (self-chat sliding window)** — A self-chatting duo accumulates history without bound, so a long enough run eventually exceeds the model's context window and the API returns a **400 `prompt is too long: <T> tokens > <M> maximum`**. Unlike 429/529 this is **not** retryable as-is, and before the fix it fell through `stream_worker`'s `APIStatusError` handler to the bare `else: raise`, ending the run (observed live: a duo crossed 1M and died with `1597842 tokens > 1000000 maximum`). The handler now has a **first branch** for `status_code == 400 and "too long" in emsg`: it regex-parses the reported `<T>`/`<M>`, calls `_trim_history_for_context(messages, T, M)` to drop the oldest rounds, posts a red ⚠ `warning`, resets `full_text`, and `continue`s the retry loop with the trimmed list (`api_kwargs["messages"]` is the *same* list object, mutated in place by `del messages[:cut_at]`, so the retry sends the shorter prompt). `_trim_history_for_context` cuts **only at genuine user-turn boundaries** — a `is_turn_start` helper treats a `role=="user"` message as a turn start unless its content is a `tool_result` carrier — so a `tool_use`↔`tool_result` pair is never orphaned (which would itself be a 400) and the first kept message is always a real user turn. It sizes the cut proportionally when `T`/`M` parse (`target = 0.75·M`, walk rounds summing `_estimate_content_tokens` ≈ chars/4, images counted 1600 flat, until `T−target` removed), else drops the oldest half; it **always keeps the last two rounds** and returns 0 (→ `raise`, surfacing the original error) when only those remain. Because `stream_worker` runs on `list(self.messages)` and only writes `self.messages = messages` on success, the trim persists into the ongoing conversation (the next injected peer turn continues from the shortened history, preventing immediate re-overflow) without corrupting a mid-run copy. Happy-path calls never touch any of this — the branch fires only on the overflow 400. Structurally unit-tested (turn-boundary cuts, no orphaned tool_results, ≥2-round floor, error-string regex, flat image estimate). MyAgent's Anthropic path had the same latent gap; closed 2026-07-22 by porting the trim into `myagent/helpers.py` (`trim_history_for_context`/`parse_overflow_counts`, same semantics) wired into `anthropic_mixin`'s BadRequestError handler — SelfBot keeps its own in-class copy. On Claude Fable 5.1 this trim is a history edit under the preserved-thinking check (keep-tail compaction) — the `drop_block` binding in the next paragraph is what lets the retry succeed there.

**Claude Fable 5.1 harness surface (2026-09-02)** — the same treatment MyAgent got the same day (the full rationale, the API facts and the SDK 0.84.0 constraints are in CLAUDE_MYAGENT.md's paragraph of the same name; this is the SelfBot delta). `claude-fable-5-1` rides the prefix-matched always-on class for thinking / temperature / effort and the shared `ANTHROPIC_PRICING` table (its own row: cache reads $0.25/MTok, 0.025×), so the picker and `_get_pricing` needed nothing beyond the `FALLBACK_MODELS` / `ADAPTIVE_THINKING_MODELS` entries. In-file copies (SelfBot's convention — the `myagent` import is the optional kind): `_fable_features()` (the two betas + `block_binding` + `fallbacks` for the Fable/Mythos class, None otherwise, minus the surfaces in `_anthropic_unsupported`), `_refusal_note()`, and the classmethods `_strip_thinking_blocks` / `_strip_pre_fallback_blocks` (with `_block_type` / `_block_field` for dict-or-SDK-object blocks), all grouped above `_trim_history_for_context`; the four beta constants are try-imported from `myagent.constants` with literal fallbacks in the stub block. `ANTHROPIC_BETAS` (module constant beside `MAX_TOKENS`) is the base header list `stream_worker` extends per call. **Why SelfBot needs the binding even more than MyAgent:** its history is user-editable mid-conversation — a system-prompt switch, a tool-toggle change (the `tools` array is part of the bound prefix), a reloaded chat continued under a different prompt, a mid-chat model switch (blocks from another model are dropped as `model_binding_mismatch`), and the overflow trim — every one invalidates Fable 5.1's later thinking blocks, a 400 on enforced accounts without `prefix_mismatch_behavior: "drop_block"`; with it the API drops them unbilled and `stream_worker` prints the `input_transformations` count as an Activity line. The no-beta floor is a 400 rung in the `APIStatusError` handler (checked before the beta-surface rungs, because the signature error text names `block_binding` as its remedy) that strips every thinking block from history via `_strip_thinking_blocks` — in place on the shared message dicts, so the strip persists into `self.messages` — and retries once. **Refusals:** SelfBot had NO refusal handling before this — a classifier decline (HTTP 200, `stop_reason="refusal"`) produced a silently blank reply, and a pre-output refusal left an EMPTY assistant message in history that 400ed the *next* request ("all messages must have non-empty content"); `stream_worker` now appends the trailing assistant text only when non-empty (consecutive user turns are legal — the API merges them) and posts `_refusal_note` (⚠, `stop_details` captured off the `message_delta` event). Fable/Mythos requests opt into server-side fallbacks (`fallbacks: "default"`), so a declined turn is re-run on an Opus-tier model inside the same call — for a duo self-chat that is the difference between the conversation continuing and stalling; the serving model (`final_message.model`, served-by = a `fallback_message` iteration) prices the call and a ⚠ names it, and `_strip_pre_fallback_blocks` applies the echo rule before the assistant turn is appended (`content_blocks` replaces `final_message.content` at both the history append and the `tool_blocks` scan).
