## Architecture (SelfBot.py)

**Single class design** — The `App` class contains all UI, API, tool execution, and persistence logic. No separate modules.

**Model picker & per-model parameters** — The Provider is fixed to Anthropic. `_fetch_available_models` pulls the live `models.list()` and hides deprecated / soon-to-be-retired ids via `DEPRECATED_MODEL_PREFIXES` (Opus 4.1, the dated 4.0 ids `claude-(opus|sonnet)-4-20…`, and every Claude 3.x / 2.x) so newer models appear automatically and only the retiring ones drop out; Opus 4.5 / Haiku 4.5 stay (still active) — Sonnet 4.5 (`claude-sonnet-4-5-20250929`, deprecated 2026-09-30, retires 2026-11-30 → Sonnet 5.5) left the picker and the pricing table on 2026-10-14 under the retirement policy, the Models API's new `lifecycle` field notwithstanding (it still said "active"); its manual-thinking and output-cap wiring stays for a pinned prompt. Capability detection is **version-parsed**, not a hardcoded set — `_parse_claude_major_minor(mid, families)` yields a `(major, minor)` tuple (Claude 5 ids dropped the minor, so `claude-sonnet-5` → `(5, 0)`; dated snapshots keep working because the date lands in the minor slot), and the helpers apply per-family thresholds: `_is_adaptive_model` (Opus/Sonnet 4.6+, Haiku 5+ since 2026-10-14 — `_is_haiku_5`, MyAgent's `_is_anthropic_haiku_5` twin — and always-on) picks the **Thinking-mode combobox** over the manual checkbox+budget; `_anthropic_mode_values` builds the combobox list per model — the always-on models drop **Off** (an explicit disable is HTTP 400): Fable/Mythos 5 and 5.1, prefix-matched via `ALWAYS_ON_THINKING_PREFIXES` (so `claude-fable-5-1` needed no entry), and, since 2026-09-28, Claude Opus 5.5 and any later Opus by version (`ALWAYS_ON_OPUS_MIN` = (5, 5) in `_is_always_on_thinking`, MyAgent's `_is_anthropic_always_on_thinking` twin — a dated snapshot's date in the minor slot does not count), which also gives Opus 5.5 the temperature rejection, the Xhigh / Max ladder and the Fable request surface (`_fable_features`); until then SelfBot offered it an Off the API refuses and none of that surface, **Xhigh** needs Opus 4.7+ / Sonnet 5+ / Haiku 5+, **Max** needs Opus 4.6+ / Sonnet 4.6+ / Haiku 5+; `_rejects_temperature` (Opus 4.7+ / Sonnet 5+ / Haiku 5+ / Fable-Mythos) hides the temperature spinbox and never sends the param (HTTP 400 otherwise), through `_sends_temperature` (below); `_thinking_on_by_default` (Opus 5+ / Sonnet 5+ / Haiku 5+ / always-on) makes "Off" send an explicit `thinking={"type":"disabled"}` so the model doesn't silently think, billed, with the Show Thinking pane dark. `MANUAL_THINKING_PREFIXES` (Opus/Sonnet 4.5, Haiku 4.5) keep the checkbox + `budget_tokens` UI; `claude-3-5-sonnet` is deliberately absent (extended thinking arrived with 3.7/4 — a thinking block to a 3.5 model is HTTP 400). Both request builders — the live `stream_worker` `api_kwargs` and the debug `_payload_for_display` — funnel through the shared `_apply_thinking_params(kwargs)` so they never drift; adaptive thinking is sent as `{"type":"adaptive","display":"summarized"}` so the Show Thinking pane isn't blank on Fable / Opus 4.7+ (their default became `"omitted"`). For the Fable/Mythos class the same builder adds Fable 5.1's `thinking.block_binding` and a `fallbacks` value (see **Claude Fable 5.1 harness surface** below); `fallbacks` sits in the kwargs under its wire name so the debug dump shows it, and `stream_worker` moves it into `extra_body` because anthropic 0.84.0 has no typed kwarg for it. A reactive `self._no_temperature` set (populated by the `stream_worker` BadRequest handler on a 400 naming temperature) backstops any future rejecting model the version parser doesn't know yet; `self._anthropic_unsupported` does the same for the two Fable beta surfaces. Model + all thinking params persist via `app_state.json` (last-live-state) and the system-prompt bundle; `_on_model_selected` re-coerces a stale saved mode (e.g. an unsupported `Max`/`Xhigh` → `High`, `Off` on an always-on model → `Adaptive`). **Claude Sonnet 5.5 (`claude-sonnet-5-5`, live 2026-09-28; the 2026-10-14 model audit)** — the Sonnet >= 5 rules had given it an Off the API refuses: the Models API tree says `thinking.types.disabled` is unsupported and a 15-request probe (US$0.03) confirmed the contract — the explicit disable is HTTP 400 ('To turn thinking off on this model, send "thinking": {"type": "between_tools"}'), `between_tools` (no extended thinking; the short notes between tool calls come back as thinking blocks) is accepted at effort high or below only and with NO other field inside `thinking` (display / budget / block_binding each a 400; the binding's beta header alone tolerated), adaptive thinking takes the binding and the summarized display, `fallbacks: "default"` is accepted beside either shape (a model list is refused), the budget form and any temperature but 1 are 400, the 20260209 triple is accepted. So `_is_sonnet_55` (Sonnet (5, 5)+ by version, a dated snapshot's date not counting) makes "Off" a bare `between_tools` in `_apply_thinking_params` (no effort — "Off" never sends one), gives the model the Fable surface through `_fable_features` (binding + fallbacks, the binding only in the adaptive branch), and `stream_worker` keeps the binding's beta header off a between_tools call as it does off a disable; the Off rung stays in the picker. Its pricing row is its own — Sonnet 5's $2 / $10 / $2.50 but cache reads at 0.05x ($0.10/MTok, the pricing page's footnote 2, with Opus 5.5) — where the `claude-sonnet-5` prefix had billed its cache reads 2x over. MyAgent still sends Sonnet 5.5 the explicit disable (its two pinned instructions run with thinking on) — open. Pinned in `tests/test_selfbot_sonnet55.py`. **Shown = usable = sent (2026-10-14, the user's report: some models still showed the Temp box, dimmed and unusable — "not the case in MyAgent")**: SelfBot disabled a control that could not apply where MyAgent hides it. The parameter controls are now created by `_build_model_param_widgets` (thinking controls first, Temp last — creation order is Tab order; the four Tk variables carry `master=toolbar`) and packed by `_layout_model_params` ALONE, MyAgent's `_forget_all_model_widgets` rule: every control forgotten, then what the model and thinking setting use re-packed in one order — `Thinking [mode]` for an adaptive model, `[x] Thinking [budget]` / `[ ] Thinking  Temp` for a budget model, Temp alone for a model with no thinking control — so the control just changed stays put and Temp comes and goes to its right; nothing is ever configured `state="disabled"` (a scan pins it). Temp is shown exactly when `_sends_temperature()` — thinking off, not the always-on class, not `_rejects_temperature`, not learned off in `_no_temperature` — the ONE predicate `_apply_thinking_params` and `_get_model_param_summary` read too, so the box, the wire and the cost log's params string cannot disagree. `_on_model_selected` is the display-name mapping + `_apply_model_params` (coerce the thinking state to the model, then lay out; no save) + `_save_last_state`, and `setup_ui` calls `_apply_model_params` once the right-hand buttons are packed: a first launch with no state file never reaches `_on_model_selected`, and the default (adaptive) model wore the budget models' controls, an editable Temp it never received among them. Three shown-vs-sent defects went with it: the mode combobox keeps the budget models' Thinking box in step (`_sync_thinking_mode` — Opus 4.6 at Off, then Haiku 4.5, showed the box ticked while thinking-off and a temperature were sent; replayed on the pre-fix code); the budget box always shows `thinking_budget`'s preset, a budget no preset names (`manage_prompts` takes any integer) snapping to the nearest one, which is then what is sent (`_update_thinking_strength_options`, a tie to the smaller); and the temperature 400 rung hands `_layout_model_params` to the Tk thread (`root.after(0, …)`, guarded for a root-less host), so a learned-off Temp box goes as well. The Models API read the same day (zero tokens: every served id's `capabilities.effort` / `thinking.types`) agreed with every ladder `_anthropic_mode_values` builds and every `_model_supports_thinking` kind; the one parameter a served model takes that neither app exposes is Opus 4.5's effort (low / medium / high — its budget thinking is offered). Pinned in `tests/test_selfbot_model_params.py` (real widgets on a withdrawn root over the live picker's ids: the shown set per model and state, nothing dimmed, the handlers, shown = sent against `_apply_thinking_params` and the summary, the budget snap, the learned-off rung through the REAL `stream_worker`, creation order, a wiring scan).

**Tool system** — Global tool lists define API tool schemas:
- `TOOLS` — Core tools always sent to the API (`run_command`, `csv_search`); the Anthropic server-side declarations are appended in `stream_worker` from `_anthropic_server_tools()` (2026-09-25, a byte-identical in-file copy of AnthropicMixin's, pinned in `tests/test_server_tools.py`): the current `web_search_20260209` + `web_fetch_20260209` + `code_execution_20260521` triple — free code execution while the web tools are declared — with Haiku 4.5 on the older web pair + `web_fetch_20250910` under its beta, and a learn-off 400 rung for a future model the gate over-admits (see CLAUDE_MYAGENT.md's Server-side tools paragraph)
- `DESKTOP_TOOLS` — MyAgent's 15-tool list, try-imported from `myagent.constants` since 2026-10-14 (the Desktop tools are `DesktopMixin`'s, inherited — see **Tool parity with MyAgent** below): `_get_tools` offers 14 of them when the Desktop checkbox is enabled, `find_element` (Gemini's pointing API) stripped — `view_image` (an image file read into the conversation, MyAgent's tool of 2026-10-13), the `grid` overlay and the per-display `display` parameter included
- `BROWSER_TOOLS` — MyAgent's 12 Playwright/CDP tools (`BrowserMixin`'s, inherited; `browser_download` included), conditionally included when Browser checkbox is enabled
- `FILE_TOOLS` / `READ_DOCUMENT_TOOLS` — MyAgent's five native file tools (`read_file` / `edit_file` / `write_file` / `glob_files` / `grep_files`, `FileMixin`) and `read_document` (`DocumentMixin`; the schema picked out of MyAgent's `TOOLS`), always sent like `TOOLS` — no checkbox, as in MyAgent (since 2026-10-14)
- `EXCEL_TOOLS` / `PHYSICAL_TOOLS` — MyAgent's nine `excel_*` tools (`ExcelMixin`, xlwings) and `camera_capture` / `microphone_listen` (`PhysicalMixin`), included when the Excel / Physical checkboxes are enabled (since 2026-10-14; each Physical tool only with its own package)
- `SELFBOT_META_TOOLS` — 2 meta tools (`manage_skills`, `manage_prompts`), included when the Meta checkbox is enabled
- `GOOGLE_TOOLS`/`PROTON_TOOLS`/`OUTLOOK_TOOLS`/`MCP_TOOLS` — imported from `myagent.constants`, included when the Google/IMAP/Outlook/MCP checkboxes are enabled (see the tool-subsystems note below)
- `_get_tools()` assembles the final tool list dynamically based on UI toggle state

**Adding a new tool** requires three changes:
1. Add schema dict to the appropriate tool list (`TOOLS`, `SELFBOT_META_TOOLS` or `EXIT_TOOLS` — a Desktop / Browser / Excel / Physical / file tool is MyAgent's: add it to `myagent/constants.py` and its mixin, and SelfBot inherits it)
2. Add a `do_<tool_name>()` method to the `App` class
3. Wire it up in the `_execute_tool()` method's tool dispatch block (`elif block.name == "..."`)

**MyAgent tool subsystems (Meta / MCP / Google / IMAP / Outlook — and, since 2026-10-14, Desktop / Browser / Excel / Physical / file / document)** — SelfBot reuses MyAgent's native MCP + mail mixins **by inheritance** (not reimplementation): `class App(MCPMixin, GmailMixin, ProtonMailMixin, OutlookMixin, DocumentMixin, FileMixin, DesktopMixin, BrowserMixin, ExcelMixin, PhysicalMixin, VoiceMixin)` (the last seven since 2026-10-14 — see **Tool parity with MyAgent** below), imported optionally at the module top (`try: from myagent… except:` → empty-class stubs), gated by `_HAS_MYAGENT_TOOLS` plus per-provider `_HAS_MCP`/`_HAS_GOOGLE`/`_HAS_PROTONMAIL`/`_HAS_OUTLOOK`/`_HAS_EXCEL`/`_HAS_PHYSICAL` (from `myagent.constants`; `_HAS_CAMERA` / `_HAS_MICROPHONE` gate each Physical tool). The mixin order matches MyAgent's so Proton/Outlook's helper-prefix anti-shadowing (vs Gmail's unprefixed `_header`/`_extract_bodies`) holds. These tools are **Anthropic-only** (SelfBot has no other provider) and each subsystem's checkbox is `state=DISABLED` when its lib is absent (Meta needs none; Proton is labelled **IMAP**).
- **Host contract** (all the mixins need): `self.root`, `self.queue`, and `self._disabled_confirm_patterns` (a `set`, added in `__init__` — empty means every destructive mail action confirms). `__init__` also calls `_init_mcp_state()`/`_google_init_state()`/`_proton_init_state()`/`_outlook_init_state()` to seed connection caches. MCP is the only subsystem that eagerly connects — `root.after(100, self._connect_mcp_servers)` at startup **regardless of the checkbox** (like MyAgent; the checkbox only gates whether the tools are *offered*), and it is torn down in `_finish_close` via `_disconnect_mcp_servers()`. The connect returns at once (the inherited non-blocking startup, since 2026-09-28 — it used to freeze the window until every server was up) and `stream_worker` calls `_mcp_wait_ready` first, so a message sent while the servers are still connecting waits for them on the worker; a `_`-prefixed server name is disabled.
- **Toggles**: seven `BooleanVar`s (`meta_enabled`/`mcp_enabled`/`google_enabled`/`proton_enabled`/`outlook_enabled`, and since 2026-10-14 `excel_enabled`/`physical_enabled`) in a **second checkbox row** (grid row 8, directly under the Debug/display-toggle row 7 — the rows below the message box moved down one on 2026-10-14 for the voice row, row 5) that also holds the **Desktop** and **Browser** toggles (moved down from the Debug row) and the SelfBot-native **Exit** toggle (**Pause** until 2026-10-14 — see **Exit tool** below); the ten tool toggles thus share one row — Desktop, Browser, Meta, MCP, Google, IMAP, Outlook, Excel, Physical, Exit (they fit at the default width, checked on the laptop 2026-10-14) — and the Debug row carries MyAgent's **Diag** box (`diag_enabled`, the desktop tools' coordinate-trail lines) after Save Thinking — and, since 2026-10-14, the **Voice Setup** button at its left (see **Voice input** below). Both rows are left-aligned (`sticky="w"`) and `attach_label` sits at row 9. Persisted in `app_state.json` (keys `meta_enabled`…`outlook_enabled`, `excel_enabled`, `physical_enabled`, `exit_enabled` — the old `pause_enabled` read once more — `diag_enabled`) and restored only when the corresponding lib is present (a saved-on flag can't re-enable a disabled checkbox). **Convo is deliberately NOT wired** (irrelevant to SelfBot).
- **`_get_tools()`** appends `SELFBOT_META_TOOLS` (Meta), the runtime-populated `MCP_TOOLS`, and deep-copied `GOOGLE_TOOLS`/`PROTON_TOOLS`/`OUTLOOK_TOOLS` with each tool's `account` enum patched from `_get_google_account_names()`/`_get_proton_account_names()`/`_get_outlook_account_names()`; since 2026-10-14 also `READ_DOCUMENT_TOOLS` + `FILE_TOOLS` unconditionally, `DESKTOP_TOOLS` minus `find_element` (Desktop), `BROWSER_TOOLS` (Browser), `EXCEL_TOOLS` (Excel) and the installed `PHYSICAL_TOOLS` (Physical).
- **`_execute_tool()`** routes (before the native chain): MCP by `block.name in self._mcp_tools_by_name` → `do_mcp_call(name, input)`; mail by `startswith(("gmail_","proton_","outlook_"))` → dynamic `getattr(self, f"do_{name}")(input)`; Meta → `do_manage_skills`/`do_manage_prompts`; since 2026-10-14 `excel_` / `camera_` / `microphone_` by prefix (an install hint when the package is absent, a checkbox hint when the toggle is off, then the mixin's `do_<name>`), `read_document` and the five file tools by name — and the Desktop and Browser blocks of the native chain are MyAgent's dispatch (the `grid` and `display` parameters, `browser_download`, a stray `find_element` refused in words).
- **Meta is SelfBot-native**, not MyAgent's `META_TOOLS`: MyAgent's `manage_instructions`/`run_instruction` are tied to its agent-instruction system, which SelfBot lacks. `SELFBOT_META_TOOLS` = `manage_skills` (the shared `skills/` SKILL.md tree, identical to MyAgent — since 2026-09-25 including the four bundled-resource-file actions `list_files` / `read_file` / `write_file` / `delete_file` over the same datapaths helpers, with standalone stubs mirroring them and both apps' action enums pinned equal in `tests/test_skill_resource_tool.py`) + `manage_prompts` (CRUD `system_prompts.json`, SelfBot's analog of `manage_instructions`). `do_manage_skills`/`do_manage_prompts` live on the App; UI refreshes (`_update_skills_button`) are scheduled via `root.after(0, …)` for thread safety.
- **Queue types**: the mail mixins emit `{"type": "warning"}` on confirm-bypass — `check_queue` renders it in the red `error` tag, always shown (independent of Activity). MCP emits `{"type": "tool_info"}` (already handled).

**Exit tool (`exit_conversation`)** — a chatbot that can close itself (2026-10-14, the user's request: change the Pause box's wiring "to actually kill the process as opposed to just STOP — in that way a chatbot can kill itself"). It replaced the **Pause / rest tool** (`pause_conversation`, 2026-07-13 → 2026-10-14), which switched auto-chat off and left both windows open — added to test whether the duo's habit of ending every conversation in a model-driven `taskkill` (given `run_command`, the only exit in its action space) was just the one door out of the room; the rest machinery (`_model_paused`, `_resume_from_model_pause`, the `send_message` hook) went with it. `EXIT_TOOLS` (one tool, optional `reason` param) is gated by the **Exit** checkbox in the tool row (no lib needed; wired like MyAgent's Convo toggle — a per-environment behavioural affordance). `do_exit_conversation` is the model-callable [X]: on the streaming worker it hands `_on_close` — the window's own close handler — to the Tk loop (`root.after(0, …)`; the worker never touches widgets), posts a ⏻ `{"type": "warning"}` notice carrying the reason (always shown; the reason gets its full stop if it has none), and returns a result telling the model the close is coming and that whatever it writes next is a closing note kept in the saved chat but not delivered. `_on_close` latches `_closing` (the peer poll and the auto-message poll stop at once, so no new message can start a reply), switches auto-chat off, removes `AUTO_MSG_FILE`, and WAITS for `self.streaming` to clear — the tool runs mid-turn, so the model's final API round still streams into the window — before `_finish_close` saves the state file and the chat, writes the session's cost line, removes the in-progress record, closes the peer (WM_CLOSE on Windows, SIGTERM on macOS — its own graceful close), releases the lock files and destroys the window: a duo always ends as a pair, as it does from [X]. Auto-chat being off by then, the closing reply is held as `_pending_injection` and never reaches the peer (the chat is over for both). With no partner, the one window closes. The dispatch refuses a call whose box was unticked since the turn began. NOT in `PARALLEL_SAFE`. Persisted as `exit_enabled` in `app_state.json` (the old `pause_enabled` read once more at load), bundled as `exit` in the system-prompt environment (`_capture_prompt_settings` / `_apply_prompt_settings` — which still honours a saved `pause` key until the prompt is re-saved — / `_PROMPT_TOGGLE_KEYS` + a `manage_prompts` param). The tool description states what the tool does, never when to use it, so a duo's end stays the model's own choice. Pinned in `tests/test_selfbot_exit_tool.py` (the schema under the toggle, the dispatch and its guard, the tool on a bare host, the REAL `stream_worker` over the parity fake client finishing the reply after the call, `_on_close`'s wait and the close's order, the persistence keys with the legacy reads, a scan for the old names).

**Threading model** — API calls run in a background `stream_worker` thread. A `queue.Queue` passes events (text, thinking, tool info, errors) to the main thread, polled every 50ms via `root.after()`. `_ensure_newline()` guarantees each new output block starts on a fresh line; an `ensure_newline` queue event between loop iterations prevents text merging when Activity is off.

**Thinking accumulator lifecycle** — `_current_thinking_text` is reset at `thinking_start` (not at `label`), so the accumulated thinking text survives past the label event and is available when `complete` fires to inject into the peer instance.

**Show Thinking checkbox** — The `show_thinking` BooleanVar (defaults False) gates display of thinking blocks in `check_queue` and `_poll_auto_msg`. This is separate from `thinking_enabled` which controls whether the API generates thinking blocks. Both must be on for thinking to appear in the output.

**Save Thinking checkbox** — The `save_thinking` BooleanVar (defaults False) controls whether thinking and redacted_thinking blocks are preserved in saved chat JSON files. When enabled, Anthropic thinking blocks (including cryptographic signatures) are kept during `_serialize_messages()`, allowing loaded chats to continue with full reasoning context. When disabled, thinking blocks are stripped to reduce file size. Has no effect for OpenAI models, whose reasoning summaries are display-only and never stored in messages. Persisted in the app's state file.

**Dual geometry persistence** — State files store `geometry` (solo mode) and `duo_geometry` (duo mode via `--no-geometry` flag) independently. `_duo_mode` is set in `__init__` from `sys.argv` before any save can occur. On save, the app reads the existing state file to preserve the other mode's geometry key. **Since 2026-09-16 the main window is ALSO filed per monitor layout**: `main_geometries[layout_key][mode]` (`mode` = `solo` / `duo`, `layout_key` from `_monitor_layout_key()` — see the dialog paragraph below), captured only once the root is mapped and ≥ `MAIN_MIN_W`×`MAIN_MIN_H` (an unmapped root reports `1x1`, so the save in `__init__` can't overwrite a good entry), and `_load_last_state` restores from THAT via `_main_geometry_from_state` (this layout's entry, else the flat `geometry` / `duo_geometry` key as the LAST USED position — since 2026-10-13; until then a file with per-layout data read it for no layout, so a layout seen for the first time, the laptop undocked, lost the window's size and spot) gated by `_usable_main_geometry` — real size plus the any-monitor title-bar test — and, with nothing usable, the solo window opens at its saved size (or the default) centred on the primary monitor through `_default_main_geometry` (since the same day; it was left to the WM at the default size — the rule MyAgent, MyBackup, CSVEditor and TodoList share), instance 2 cascaded off that spot. Before that day the restore used the primary-only test (`x < screen_width and x + w > 0`) behind a `screen_width` / `screen_height` equality guard, which rejected every position on a monitor LEFT of the primary (negative x), so a main window parked there came back on the primary — the user's "it does not save the monitor" report. The flat `geometry` / `duo_geometry` / `screen_*` keys are still written as last-seen values; instance 2's cascade check reads instance 1's entry through the same helper. The duo default (side-by-side from the primary work area) and the instance-2 cascade are unchanged. Pinned in `tests/test_selfbot_dialog_geometry.py` (`MainGeometryFromStateTests`, `UsableMainGeometryTests`, `DefaultMainGeometryTests`, `SaveMainGeometryTests`, `MainRestoreWiringTests`). **Second-instance cascade (solo mode)** — a manually-opened instance 2 restores the *same* saved solo `geometry` as instance 1 (a fresh instance 2 even bootstraps its geometry from instance 1's `app_state.json` in `_load_last_state`), so it would land pixel-perfectly on top of instance 1 and look like nothing opened / a crash. `_load_last_state`'s solo branch detects this by comparing instance 2's restored position against instance 1's saved position (read from `APP_STATE_FILE`) and, only when they nearly coincide (<30 px), cascades instance 2 down-right by `CASCADE_OFFSET` (60 px), clamped on-screen. Cascade-only-on-collision preserves deliberate manual placement and prevents drift across launches (once offset, it no longer collides). The duo path is unaffected — it already tiles side-by-side. This is only reachable because the launcher (`SelfBot_Win.ps1` / `SelfBot.app`) is always-launch-fresh, not launch-or-focus, so double-clicking the shortcut twice genuinely opens the self-chat pair.

**Dialog geometry persistence — per instance, per monitor layout (2026-09-16)** — the three auxiliary windows — System Prompt Editor, Skills Manager, Safety — Confirm Patterns — remember their size AND position across launches, each instance separately and each monitor arrangement separately, through the same `_save_last_state` / `_load_last_state` pair the main window uses. The state file (`self._state_file`: `app_state.json` for instance 1, `app_state_2.json` for instance 2, so a duo pair keeps two independent sets; instance 2 seeds from instance 1's file only when its own does not exist yet) carries one `dialog_geometries` dict, **keyed by `_monitor_layout_key()`** — every monitor's rect from `_get_display_rects()`, sorted (the primary screen alone when the enumeration fails) — holding `{prompt_editor, skills_dialog, ps_safety}` → geometry for that arrangement (`DIALOG_WINDOWS` in the module constants maps each kind to its window attribute; `DIALOG_LEGACY_KEYS` to the flat pre-2026-09-16 state keys, adopted once on load by the pure `_dialog_geometries_from_state` and never written again). A monitor added, removed, moved or re-scaled changes the key, so geometries saved on one arrangement are never applied to another (MyAgent's rule): a laptop docked to two monitors and undocked to its panel keeps BOTH sets, and a save under the current key preserves every other layout's entry in the file. Each dialog is saved LIVE while open (`_current_dialog_geometries`, so the 5-second periodic save and a close-with-dialogs-open both capture it), else from its `_last_<kind>_geometry` attribute, which every close path sets — the `WM_DELETE_WINDOW` handler of each dialog, and the prompt editor's **Apply to Chat**, which destroys the editor too (before 2026-09-16 the editor had no persistence at all: a fixed `650x500` wherever the WM put it). Open follows one pattern — `withdraw()` → build → `update_idletasks()` → **`_place_dialog(win, kind, default_size)`** → `deiconify()` — and `_place_dialog` is the one placement routine with the **safe fallback**: the saved position when `_sanitize_geometry` finds a monitor that still shows it; else the saved SIZE at the default position; with nothing saved for this layout, the default size at the default position — the default (`_default_dialog_geometry`) being centred on the main window, shrunk to fit and clamped onto the monitor holding the main window's centre (`_monitor_rect_containing`, primary when the main window is off every monitor), so a dialog with no usable saved spot lands where the user is looking whatever the monitor count or resolution. `transient(root)` on Windows only, since the macOS WM confines a transient to its parent's screen. **`_sanitize_geometry` validates against every monitor**, via `_dialog_geometry_visible` — MyAgent's rule, at least 50 px of the 30-px title strip and 10 px of its height on SOME rect from `_monitor_rects()`. The `manage_prompts` meta-tool is **bundle-aware** (brought to parity with SelfBot's environment-bundle prompts, mirroring MyAgent's `manage_instructions`): `read` returns the text plus a JSON dump of the bundled environment; `create` writes a full bundle — inheriting the current live `model`/`temperature`/`thinking_*`/`skill_modes`/`disabled_confirm_patterns` from **thread-safe plain attributes** (NOT `_capture_prompt_settings()`, which reads Tk widgets and is main-thread-only — `do_manage_prompts` runs on the streaming worker), with the tool toggles taken from params defaulting OFF and the terminal names bundled only if explicitly passed; `update` overlays any provided bundle field (text, model params, toggles, names) and **merges** `skill_modes` (only listed skills change), leaving the rest intact. The **`apply` action** lets the model switch the LIVE session to a saved prompt (text + full environment) on command — create/update/delete are disk-only, `apply` is the one action that mutates live state. Because `_apply_prompt_settings` touches main-screen Tk widgets (name entries, model/thinking vars, tool-toggle `BooleanVar`s, `_on_model_selected`), `do_manage_prompts` marshals it onto the Tk loop via `root.after(0, …)` + a `threading.Event` wait (same main-thread hand-off as `_request_confirmation`), also setting `self.system_prompt`/`self.system_prompt_name` + `_update_title` so the switch is complete; it catches UI errors into a message and has a 10 s timeout so a wedged main thread can never hang the worker.

**Prompt caching (`cache_control`)** — ported from MyAgent 2026-07-31 (see CLAUDE_MYAGENT.md for the cost audit that found it: Anthropic caching is strictly **opt-in**, and neither app had ever set a breakpoint, so every call re-sent the whole growing prefix at the full miss rate). SelfBot is the bigger beneficiary of the two: a duo self-chat grows without bound by construction — that is *why* `_trim_history_for_context` exists — and every turn re-sends all of it. Two staticmethods on `App` (SelfBot keeps its own copies, like `_trim_history_for_context`, rather than importing `AnthropicMixin` — the `myagent` import is the optional/stubbed kind): `_cache_system` wraps the system prompt in a cached text block, which covers the tool array too (the prefix is ordered tools → system → messages and a breakpoint caches everything before it), and `_cache_messages` places two rolling markers on the newest eligible turns — three total, under Anthropic's ceiling of four. `CACHE_CONTROL` (module constant, beside `ANTHROPIC_BETAS`) pins the **default 5-minute TTL** deliberately: writes cost 1.25x and match `ANTHROPIC_PRICING`'s cache-write column, so `_get_pricing`'s four-bucket cost stays exact (`ttl: "1h"` would need the `extended-cache-ttl-2025-04-11` beta and 2x writes). Invariants: **history is never mutated** (only breakpointed messages are shallow-copied — `stream_worker` works on `messages` and writes it back to `self.messages` on success, and the overflow handler trims it in place; mutating it here would accumulate stale breakpoints past the ceiling); the **wire copy is rebuilt inside the retry loop**, because the overflow trim's `del messages[:cut_at]` previously reached the retry via `api_kwargs["messages"]` being the same object, which a copy breaks; and assistant turns are skipped (line ~5493 appends `final_message.content` verbatim — SDK Pydantic blocks, not dicts), landing the markers on the user turns. `_payload_for_display` applies both helpers too, for the same no-drift reason `_apply_thinking_params` is shared. A trim invalidates the cache by changing the prefix — one re-write, then the discount resumes. Live-verified 2026-07-31 through SelfBot's own staticmethods (`cache_write=4429` then `cache_read=4429`, `input=2`); watch it in the cost line's `cache_read:` field with Activity on.

**System prompt fixed per reply (2026-09-29)** — MyAgent's fix of the same day (CLAUDE_MYAGENT.md's **System prompt fixed per run** has the why and the incident: a mid-run skill edit re-wrote the whole prompt cache and, on Fable 5.1 / Mythos 5.1 / Opus 5.5, dropped every earlier thinking block). `_build_system_prompt` / `_compose_system_prompt` / `_freeze_system_prompt` / `_thaw_system_prompt` are byte-identical in-file copies of SkillsMixin's, and `stream_worker` freezes after `_mcp_wait_ready`, before its loop, and thaws in a `finally`. **API cost tracking** — `stream_worker` computes the Anthropic cost of each API call from `final_message.usage` via `_get_pricing(model, prompt_tokens)` — a longest-prefix lookup into MyAgent's `ANTHROPIC_PRICING` table (imported from `myagent.constants` to stay in sync), on the second rate card where a model has one (`ANTHROPIC_LONG_CONTEXT_PRICING`: Haiku 5.5 above 100K prompt tokens) — which prices the four **disjoint** token buckets separately: `input_tokens` × input rate, `output_tokens` × output rate, `cache_creation_input_tokens` × cache-write rate, `cache_read_input_tokens` × cache-read rate — plus, since 2026-09-25, `usage.server_tool_use.web_search_requests` × `ANTHROPIC_WEB_SEARCH_FEE` ($10/1,000 per executed search; an errored search is neither billed nor counted). Costs accumulate into `self._session_cost` **across the whole process** (all messages and chats), and each call emits a `cost_update` queue message that `check_queue` renders in the blue-monospace `cost_info` tag as `$x this call | $y session (in:… out:…)`, **gated by the Activity toggle** (like MyAgent). **Since 2026-10-14 the collection is MyAgent's, per session** (the user's request — the cost log's TIME column was empty on every SelfBot line): `_log_api_cost` is a byte-identical copy of StreamingMixin's writer (`self.provider = "Anthropic"` in `__init__` is what lets it be one), as are `_cost_split_field`, `_run_progress_write` and `_run_progress_clear`, with `_run_progress_fold_in` the same in SelfBot's wording — pinned in `tests/test_selfbot_costlog.py` — and its arguments come from ONE place, `_session_log_args` (the analogue of MyAgent's `_log_run` argument list), built for the close and the in-progress record alike so the two cannot drift: the session's cost; `_session_had_usage` (a call answered with usage, priced or not — the zero-cost gate's flag); **the working seconds** (`_session_secs`: every finished reply's wall-clock minus the seconds it sat on a confirmation dialog, summed in `stream_worker`'s `finally` from `_reply_started`, plus the reply in flight so far — the per-reply form of MyAgent's run clock, `_request_confirmation`'s wait sitting inside `helpers.input_wait_timer` as the inherited mail confirms' already did; NOT the window-open time, which the earlier writer declined to record, and not the human's typing between messages); the active saved system prompt's name as the INSTRUCTION field (SelfBot's analogue of an Agent Instruction, blank when none is loaded, sanitised like MyAgent's); `_session_calls`, incremented beside `call_num` so it totals the process's API round-trips across every message and chat; the four token buckets `_session_tokens_in` / `_out` / `_cache_write` / `_cache_read`, accumulated for EVERY call that reported usage, priced or not (MyAgent's rule); **the per-model split** `_session_per_model` (served model → `[cost, in, out, cache_write, cache_read]`, keyed by `final_message.model` with a dated snapshot of the configured model folded into it — the 13th field whenever more than one model served the session, a mid-chat model switch or a refusal fallback served by an Opus tier, or when its one serving model is not the model the line is logged under, the model at close); and the stem of the chat file the close auto-saved (`_last_saved_chat_name`, set by `_auto_save_on_close` before the line is written — the 14th field, which forces a 13th out, blank or not). So the line is `{timestamp};Anthropic;{model};{cost:.4f};{params};{secs};{prompt};{calls};{in};{out};{cache_write};{cache_read}[;{split}[;{chat}]]`, every field in MyAgent's position and meaning; `params` (5th) is SelfBot's own `_get_model_param_summary()` (the Anthropic-only mirror of MyAgent's ui_mixin helper), comma-joined, the settings at close like the model field. **The in-progress record** — `selfbot_run_<1|2>.json` beside the state file (`SELFBOT_RUN_PREFIX`; per machine, gitignored; `_run_progress_path` is None on a host without `_state_file`, so the bare test hosts never write one) — is rewritten after every call's accounting with exactly what the close would write, and `_finish_close` logs the line (through `_session_log_args`) and THEN removes it, so a record found at launch means that instance died with calls unlogged — the duo's `taskkill`, a crash, a reboot, the `os.kill(pid, 9)` fallback of a peer's close — and `__init__` calls `_run_progress_fold_in` once the queue and the slot exist, before `check_queue` is scheduled: the line is written from the record under its own model and settings, stamped with the time of its last call, `unfinished@call<N>` appended to PARAMETERS, and a ⚠ names the chat; the record goes whatever happens. Until then a SelfBot killed from outside lost its whole session's line. **Unpriced is never silent** either: a call whose model has no pricing row posts one ⚠ per model, shows its tokens behind *unpriced this call | no pricing row* (`check_queue` renders a `cost_update` whose costs are None), and the close skips the line with a second ⚠ (the copied writer's; a `$0.0000` row would claim the session was free), while a session with no usage at all is skipped in silence as before. The log is this machine's `APICostLog_<machine>.txt` in the OneDrive share — **the same file MyAgent writes** (`APICOST_LOG_FILE` resolves through `datapaths.resolve_costlog` in the optional-import block, with a repo-root `APICostLog.txt` stub fallback when the myagent package is absent), viewable via the API Cost Log launcher, which aggregates every machine's file; the copied writer never rotates the log (since 2026-10-25, with MyAgent's: the one-slot 100 KB rotation both ran before each append had moved the laptop's whole history into a `.old` file the viewers ignore; `rotate_log_if_needed` and `APICOST_LOG_MAX_BYTES` left SelfBot's optional-import block with it). The key difference from MyAgent stays: MyAgent logs once **per agentic-loop run**; SelfBot logs once **per process, on close**, because a chat session spans many messages — so one SelfBot line may carry several chats and several models.

**DPI handling (SelfBot)** — since 2026-10-14 the same bootstrap as MyAgent's, ahead of every import that could touch Tk: `SetProcessDpiAwarenessContext(-4)` (PER_MONITOR_AWARE_V2), falling back to `SetProcessDpiAwareness(2)`, then to the legacy `SetProcessDPIAware()`. **Why V2** — MyAgent (and SelfBot since 2026-10-14) uses the newer `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` (i.e. `-4`), falling back to v1 then to legacy `SetProcessDPIAware()`. V2 fixes broken multi-monitor behavior under v1 when monitors have different DPI scaling (e.g. 100% primary + 225% secondary): v1 reports the secondary's rect as a logically-scaled smaller size, causing `ImageGrab.grab` to return a low-res image and `pyautogui` clicks to land in the wrong place. V2 returns true physical pixels per monitor regardless of per-monitor DPI.

**Auto-save on close** — When closing (via [X] button or `taskkill`), all instances auto-save their chat as `.json` + `.txt` to `saved_chats/`. The toolbar's DELETE (`_delete_chat`) removes both files of the selected saved chat and, since 2026-09-02, asks first (`askyesno`, default **No**, parented to the main window); no tool path reaches it. Uses the name from the Save Chat entry if provided, otherwise auto-generates from the first user message. Instance 2's files are suffixed with `_` via `_save_name()` to avoid collisions. A periodic auto-save every 5 seconds on all instances also protects against force-kill data loss. **API retry logic** — `stream_worker` retries up to 10 times on transient API errors. Rate-limit errors (429) use exponential backoff capped at 60s (~6.5 min total). Overload errors (529) use exponential backoff capped at 90s (~10 min total). This makes the app resilient to prolonged Anthropic API outages without absurdly long individual waits.

**Context-overflow recovery (self-chat sliding window)** — A self-chatting duo accumulates history without bound, so a long enough run eventually exceeds the model's context window and the API returns a **400 `prompt is too long: <T> tokens > <M> maximum`**. Unlike 429/529 this is **not** retryable as-is, and before the fix it fell through `stream_worker`'s `APIStatusError` handler to the bare `else: raise`, ending the run (observed live: a duo crossed 1M and died with `1597842 tokens > 1000000 maximum`). The handler now has a **first branch** for `status_code == 400 and "too long" in emsg`: it regex-parses the reported `<T>`/`<M>`, calls `_trim_history_for_context(messages, T, M)` to drop the oldest rounds, posts a red ⚠ `warning`, resets `full_text`, and `continue`s the retry loop with the trimmed list (`api_kwargs["messages"]` is the *same* list object, mutated in place by `del messages[:cut_at]`, so the retry sends the shorter prompt). `_trim_history_for_context` cuts **only at genuine user-turn boundaries** — a `is_turn_start` helper treats a `role=="user"` message as a turn start unless its content is a `tool_result` carrier — so a `tool_use`↔`tool_result` pair is never orphaned (which would itself be a 400) and the first kept message is always a real user turn. It sizes the cut proportionally when `T`/`M` parse (`target = 0.75·M`, walk rounds summing `_estimate_content_tokens` ≈ chars/4, images counted 1600 flat, until `T−target` removed), else drops the oldest half; it **always keeps the last two rounds** and returns 0 (→ `raise`, surfacing the original error) when only those remain. Because `stream_worker` runs on `list(self.messages)` and only writes `self.messages = messages` on success, the trim persists into the ongoing conversation (the next injected peer turn continues from the shortened history, preventing immediate re-overflow) without corrupting a mid-run copy. Happy-path calls never touch any of this — the branch fires only on the overflow 400. Structurally unit-tested (turn-boundary cuts, no orphaned tool_results, ≥2-round floor, error-string regex, flat image estimate). MyAgent's Anthropic path had the same latent gap; closed 2026-07-22 by porting the trim into `myagent/helpers.py` (`trim_history_for_context`/`parse_overflow_counts`, same semantics) wired into `anthropic_mixin`'s BadRequestError handler — SelfBot keeps its own in-class copy. On Claude Fable 5.1 this trim is a history edit under the preserved-thinking check (keep-tail compaction) — the `drop_block` binding in the next paragraph is what lets the retry succeed there.
