# MyAgent — API cost tracking

**API cost tracking** — `stream_worker()` tracks real-time cost across all three providers. Each streaming method returns a usage dict (6th tuple element): Anthropic from `final_message.usage` (incl. `cache_creation_input_tokens`/`cache_read_input_tokens`), OpenAI from `stream.get_final_response().usage`, Gemini from the last chunk's `usage_metadata`. Static `_get_pricing(provider, model)` does a longest-prefix match against the hardcoded tables in `constants.py` (`ANTHROPIC_PRICING`/`OPENAI_PRICING`/`GEMINI_PRICING`) — and, since 2026-10-08, takes the call's `prompt_tokens` to pick a model's second rate card where it has one (`ANTHROPIC_LONG_CONTEXT_PRICING`: Haiku 5.5 above 100K prompt tokens — see its bullet under Temperature/thinking UI visibility). Costs accumulate per run and emit as `cost_update` messages (blue monospace `cost_info` tag, gated by Activity); unmatched prefixes skip silently. `MyAgent_Pricing.txt` documents the entries. STOP/incomplete streams return `None` usage and skip cost for that call. When the agentic loop ends (GUI **and** headless, on success **and** on the exception path — which also schedules `_on_close` in headless so a failed unattended run exits instead of lingering as a zombie process), `_log_api_cost(total_cost, had_usage, duration_secs, instruction=, calls=, tokens=, split=, chat=)` appends one `{timestamp};{provider};{model};{cost};{params};{secs};{instruction};{calls};{in};{out};{cache_write};{cache_read}[;{split}[;{chat}]]` line (the 14th field, 2026-10-07: the stem of the chat files the run's transcript is saved under — `<chat>.json` + `.txt` in `CHATS_DIR`, the share's `saved_chats/` since 2026-10-08 (see **Chats in the OneDrive share**), the "Save Chat as" name every MyAgent run has since that day, see **Every run saves its chat** — sanitised like the instruction, and forcing the 13th out, blank when there is nothing to split, so a chat can never be read as a split; absent for a caller without one — a bare host; SelfBot writes its own since 2026-10-14 — whose lines keep their 12 / 13 fields; both viewers render it as the rightmost CHAT column after INSTRUCTION, which is padded to its widest name on Windows and dashed when empty on macOS so the chat cannot slide left, the Windows console widened to 280 for it — and since 2026-10-25 both rule the FULL LOG with a row of dashes after every five runs, the table's full width, never one after the last (`tests/test_costlog_viewer_days.py`'s GroupRuleTests); pinned in `tests/test_chat_autoname.py` and `tests/test_costlog_viewer_days.py`'s ChatColumnTests on the real viewer; the 13th field, 2026-09-27, `_cost_split_field`: ONLY for a run more than one model served — a Model upgrade, or an Anthropic refusal fallback — or, since 2026-09-28, one whose single serving model is not the model the line is logged under (`logged_model`) — `model,cost,in,out,cache_write,cache_read` per model, first-used first, joined by `|`, cost at six places; stream_worker keys every call by the model that served it — `usage["model"]` where the provider reports one, else `self.model` at pricing time, which is the calling model because a switch only ever happens between calls — a dated snapshot of the configured model (`<model>-YYYYMMDD`) folded into it; a one-model run keeps its 12 fields exactly, 13 with a blank split once a chat follows; both viewers' By-model blocks, cost and tokens, split such a row between its models, pinned by `tests/test_costlog_split.py` and `tests/test_costlog_viewer_days.py`'s ModelSplitTests on the real viewer) — `params` (5th field, 2026-08-10) is the comma-joined `_get_model_param_summary()` title-bar string (e.g. `mode=Adaptive`, `reasoning=Medium, temp=1`), recording the thinking/temperature settings the run used; `secs` (6th field, 2026-08-12) is the run's wall-clock duration in whole seconds (`time.monotonic()` from stream_worker entry, hoisted beside `total_cost` so the exception path logs it too) minus `_input_wait_secs` — the seconds the run sat parked on user input (`user_prompt`, command and mail confirmation dialogs), accumulated by `helpers.input_wait_timer` around each blocking wait and zeroed at run start, so TIME(sec) measures the agent working, not the user's response latency (2026-08-13) — rendered as a TIME(sec) column right of COST(USD) in both viewers; `instruction` (7th field, 2026-08-16) is `agent_instruction_name` **snapshotted at run start** (an instruction applied mid-run can't relabel the entry; blank for an ad-hoc run), whitespace-collapsed with any `;` turned into `,` so a user-typed name can never split the line — the viewers' rightmost INSTRUCTION column (after PARAMETERS, per the user), plus a "By instruction" spend rollup in the SUMMARY (rows with a name only; since 2026-09-02 all four rollups — machine / provider / model / instruction — are repeated over the current month only under a THIS MONTH heading, one shared rollup function per viewer; since 2026-09-22 the SUMMARY's `today` row is followed by one row per day for the last seven days — every calendar day back from yesterday, `$0.0000` for a day without a run, weekday in `today`'s slot, the amounts of those rows and `this month` in one decimal-aligned column ending at column 34 — the two viewers byte-identical, each reading every date from ONE clock reading and the sums from one per-day map built in a single pass; details in `desktop_launchers/README.md`); `calls` (8th field, 2026-08-16) is the final `call_num` — the "Call #N" counter, one per API round-trip of the agentic loop, so every call after the first is a tool-use round-trip — hoisted above the `try` beside `total_cost` for the same reason (a run that dies on Call #3 logs `3`), the viewers' CALLS column right of TIME(sec) — where the macOS viewer substitutes `-` for an empty secs / calls / params because BSD `column -t` collapses consecutive delimiters, which would shift every column after a mid-row empty field; `tokens` (9th-12th fields, 2026-09-14) is the run's cumulative `(input, output, cache_write, cache_read)` token counts — the same four buckets `_get_pricing` rates, summed over every call; they were ALREADY accumulated for the output window's running totals and merely discarded at log time, which left the log unable to answer *what is my blended $/MTok for this model* (cost alone cannot separate a 5x per-token rate from a 40x cache-read discount — e.g. Fable 5.1 reads cache at $0.25/MTok against Sonnet 5's $0.20, a 1.25x gap, while their input rates differ 5x). All four are hoisted above the `try` beside `total_cost`, and that is load-bearing rather than tidy: the except path READS them to build the fields, so leaving them beside the loop (where they used to live, unread from outside) makes an EARLY failure — anything raising before the loop — abort the handler with `UnboundLocalError`; the error message still reaches the queue, since it is queued first, but `_write_result_file` and the headless auto-close after it never run, so a waited parent sits out its whole timeout and an unattended run is left a zombie (pinned by `test_early_failure_completes_the_exception_handler`, which fails if they move back inside). They are written as plain integers and go blank ALL FOUR TOGETHER when `tokens` is None (a partially-filled group would read as *zero tokens billed* rather than *not recorded*, which is also how the viewers distinguish `-` from `0`); `input_tokens` is the NON-cached count and the cache buckets are disjoint, so `in+cache_write+cache_read` is the run's true billed input volume — never add input to a cache total expecting a subtotal. Both viewers render them as fixed-width TOK-IN / TOK-OUT / CACHE-W / CACHE-R columns joining the numeric cluster right of CALLS (still LEFT of the open-ended MODEL/PARAMETERS/INSTRUCTION, so the never-drop-the-cost invariant is unchanged), compacted to k/M, and feed a new SUMMARY block — **By model (tokens and effective blended rate)** — dividing real cost by real tokens, lifetime only (a blended rate over a handful of runs is noise) and skipping rows whose token group is blank — plus, since 2026-09-15, a **CACHE%** column: cache reads as a share of the input side (`cache_read / (in + cache_write + cache_read)`), the cache effect on its own. The blended rate's denominator also carries output tokens, which bill 5–6× input, so a blended figure under the input sticker can mean cheap cache reads OR little output (gpt-5.6-luna: 1.4% of the tokens were output yet 33% of the cost); only CACHE% separates the two, needs no pricing, and compares across providers. One known bias remains in COST itself, so in the rate: OpenAI's `web_search_preview` fee never reaches `usage`, whereas xAI folds its $0.005/tool fee into `cost_in_usd_ticks` — **Anthropic's web-search fee is COUNTED since 2026-09-25**: the usage dict carries `usage.server_tool_use.web_search_requests` (an errored search is not billed and not counted) and stream_worker adds `count × ANTHROPIC_WEB_SEARCH_FEE` ($10/1,000) to the call's cost, SelfBot's per-call block likewise; and Anthropic code execution is free while the 20260209 web tools are declared (see Server-side tools) — so of the search fees only OpenAI's is still invisible; older 4-/5-/6-/8-field lines stay valid and render blank PARAMETERS/TIME/INSTRUCTION/CALLS/TOKENS columns, and SelfBot's lines (prompt name + session call total in fields 7/8, its own session token totals in 9-12 — and since 2026-10-14 its working seconds in 6, its per-model split in 13 and its chat in 14, written by a byte-identical copy of this writer) line up in the same positions — to `APICOST_LOG_FILE` (`datapaths.resolve_costlog()`: `APICostLog_<machine>.txt` in the OneDrive share since 2026-08-03 — one file PER MACHINE because an append-only log can't be key-level-unioned, so machines must never share a synced file; every machine's log syncs side by side and the Cost Log viewers aggregate them all, with a legacy repo-root log folded in at first resolve, the claim made atomic by the local-file rename so concurrently-launching apps migrate exactly once; repo-root `APICostLog.txt` fallback without OneDrive, gitignored either way) — semicolon-delimited so a comma in a model name can't split a field, plain 4-decimal cost for spreadsheet summing. Zero-cost gate (since 2026-08-12): Ollama runs are free but LOG anyway as `0.0000` lines when at least one call returned usage (`had_usage`, hoisted beside `total_cost` so the exception path sees it) — local activity shows in the viewers without inflating spend — and, since 2026-09-15, WITH its token counts: the four accumulators run for every call that reported usage, priced or not (inside the pricing gate, where they sat until then, an unpriced Ollama call's counts were dropped and its line read `0;0;0;0`, which the viewers render as *no tokens billed*; `tests/test_costlog_run_fields.py`'s `_OllamaHost` pins the fix, and its paired unpriced-paid-model test pins that the gate below is unchanged); other zero-cost runs (a paid provider's unmatched pricing prefix, or a STOP before the first result) stay skipped, because a fabricated `$0.0000` for a paid provider would claim "free" when the truth is "price unknown" — no longer silently, since 2026-09-23: the unmatched-prefix case posts a ⚠ at run start (`_unpriced_model_warning`) and another from `_log_api_cost` when it skips the line, and its calls still show their tokens (see the GPT-6 Sol / Luna paragraph above) (line format characterized in `tests/test_costlog_params.py` — incl. the absent-vs-zero token group and the int coercion; the stream_worker → `_log_api_cost` wiring of instruction/calls/tokens on both loop-end paths in `tests/test_costlog_run_fields.py`, which drives the real loop against a stubbed `_stream_anthropic_call` — note its `_Host` usage stays input/output only because `tests/test_fable51_harness.py` subclasses it and asserts exact per-call costs, so the cache buckets are exercised by a separate `_CacheHost`). Best-effort, so a write failure warns via the queue but never interrupts the run. The log is NEVER rotated (since 2026-10-25): until then each append first ran the shared one-slot rotation `rotate_log_if_needed` at a 100 KB cap, and at 11:04 that day the laptop's log crossed it — its 963 lines, June to that morning's four runs, moved to `APICostLog_LenovoAug23.txt.old`, which the viewers exclude by name, so the viewer showed one run and a $0.02 lifetime total, and a second rotation would have overwritten the archive for good; the archive was folded back by hand that day and the call removed from both writers (`tests/test_log_rotation.py`'s CostLogNeverRotatesTests). The viewers still skip a semicolon-free marker line (`NF>=4` / `$f.Count -lt 4`) in case a log carries one from before. `Heartbeat.py` (`heartbeat.log`) and `UnreadSummary.py` (`unread_summary.log`) keep rotating through the helper — chatter, not a ledger. **The in-progress record (2026-10-08)** — the line exists only in stream_worker's locals until `_end_run`, so a run killed from OUTSIDE left nothing: `Process_Dockets_PROGRAM_2026-10-08_092704` (gpt-6-astra Max, 53 calls, US$7.77) finished its task, parked at the Convo-mode Agent Request prompt, and a Windows Update restart (MoUsoCoreWorker, 10:22:51) killed MyAgent with the worker blocked in `do_user_prompt` — a complete transcript (`_periodic_save` — every `PERIODIC_SAVE_MS`, 10 s since 2026-10-08, 5 s then — autosaves the chat on every message-count change) and no line (that one was reconstructed by hand from the pane's per-call figures and appended with secs blank). Now `_run_progress_write` (streaming_mixin, beside `_log_api_cost`) rewrites `agent_run_<N>.json` (`AGENT_RUN_PREFIX` + the instance number, beside the state file, per machine, gitignored) after EVERY call's cost accounting — inside the usage block, after both `cost_update` branches — with exactly the arguments `_log_run` would hand `_log_api_cost` (cost, had_usage, the working seconds so far, instruction, calls, the four token buckets, the per-model split, the chat stem) plus the live provider / model / raw parameter summary and the time; atomic (mkstemp + `os.replace`), on the worker (file IO only), best-effort with one warning per run. Its TIME is the working time up to that call, which is right for a death while parked: `input_wait_timer` adds a wait's seconds only once the wait ends. `_end_run` calls `_run_progress_clear` right after `_log_run` on BOTH tails, so the record exists only while a run is in flight and a record found at launch means its instance died with one — `_run_progress_fold_in`, called from `MyAgent.py` `__init__` once the queue exists (after the slot claim, before `check_queue` and the `-l` auto-launch), writes the line from it through `_log_api_cost`'s overrides (`provider` / `model` / `params` / `timestamp`, 2026-10-08 — None = the live value, so every existing caller writes what it wrote; the gate reads the overridden provider / model too, and the method now returns True when a line was written): the record's own provider and model, its summary joined like the live one with `unfinished@call<N>` appended (the viewers show it in PARAMETERS; the cost counts, it was spent), the record's `written` time as the timestamp, the zero-cost gate as at a run end; then the record is removed whatever happened (an unreadable one is reported, not retried every launch) and a ⚠ names the chat. Only a host WITH `_instance_num` keeps a record (`_run_progress_path` is None on the bare test hosts), so the other modules' loop harnesses — and a test run beside a live MyAgent — never touch one; headless runs keep one too (it is cost accounting, not window state). Not covered: a death within one call of the last write loses that call, and the fold-in needs a later launch on the same machine (a Heartbeat child counts). SelfBot carries the same record since 2026-10-14 (`selfbot_run_<N>.json` — byte-identical copies of the write and the clear, the fold-in in its own words, its line per session; CLAUDE_SELFBOT.md's **API cost tracking**).
