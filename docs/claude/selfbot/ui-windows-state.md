# SelfBot — Threading, thinking display, geometry, DPI, close, keyboard / focus fixes, voice input

<!-- Moved verbatim from .claude/rules/CLAUDE_SELFBOT.md on 2026-11-10; that file, which loads with every SelfBot task, is now an index pointing here. Edit the contract here. -->

**Threading model** — API calls run in a background `stream_worker` thread. A `queue.Queue` passes events (text, thinking, tool info, errors) to the main thread, polled every 50ms via `root.after()`. `_ensure_newline()` guarantees each new output block starts on a fresh line; an `ensure_newline` queue event between loop iterations prevents text merging when Activity is off.

**Thinking accumulator lifecycle** — `_current_thinking_text` is reset at `thinking_start` (not at `label`), so the accumulated thinking text survives past the label event and is available when `complete` fires to inject into the peer instance.

**Show Thinking checkbox** — The `show_thinking` BooleanVar (defaults False) gates display of thinking blocks in `check_queue` and `_poll_auto_msg`. This is separate from `thinking_enabled` which controls whether the API generates thinking blocks. Both must be on for thinking to appear in the output.

**Save Thinking checkbox** — The `save_thinking` BooleanVar (defaults False) controls whether thinking and redacted_thinking blocks are preserved in saved chat JSON files. When enabled, Anthropic thinking blocks (including cryptographic signatures) are kept during `_serialize_messages()`, allowing loaded chats to continue with full reasoning context. When disabled, thinking blocks are stripped to reduce file size. Has no effect for OpenAI models, whose reasoning summaries are display-only and never stored in messages. Persisted in the app's state file.

**Dual geometry persistence** — State files store `geometry` (solo mode) and `duo_geometry` (duo mode via `--no-geometry` flag) independently. `_duo_mode` is set in `__init__` from `sys.argv` before any save can occur. On save, the app reads the existing state file to preserve the other mode's geometry key. **Since 2026-09-16 the main window is ALSO filed per monitor layout**: `main_geometries[layout_key][mode]` (`mode` = `solo` / `duo`, `layout_key` from `_monitor_layout_key()` — see the dialog paragraph below), captured only once the root is mapped and ≥ `MAIN_MIN_W`×`MAIN_MIN_H` (an unmapped root reports `1x1`, so the save in `__init__` can't overwrite a good entry), and `_load_last_state` restores from THAT via `_main_geometry_from_state` (this layout's entry, else the flat `geometry` / `duo_geometry` key as the LAST USED position — since 2026-10-13; until then a file with per-layout data read it for no layout, so a layout seen for the first time, the laptop undocked, lost the window's size and spot) gated by `_usable_main_geometry` — real size plus the any-monitor title-bar test — and, with nothing usable, the solo window opens at its saved size (or the default) centred on the primary monitor through `_default_main_geometry` (since the same day; it was left to the WM at the default size — the rule MyAgent, MyBackup, CSVEditor and TodoList share), instance 2 cascaded off that spot. Before that day the restore used the primary-only test (`x < screen_width and x + w > 0`) behind a `screen_width` / `screen_height` equality guard, which rejected every position on a monitor LEFT of the primary (negative x), so a main window parked there came back on the primary — the user's "it does not save the monitor" report. The flat `geometry` / `duo_geometry` / `screen_*` keys are still written as last-seen values; instance 2's cascade check reads instance 1's entry through the same helper. The duo default (side-by-side from the primary work area) and the instance-2 cascade are unchanged. Pinned in `tests/test_selfbot_dialog_geometry.py` (`MainGeometryFromStateTests`, `UsableMainGeometryTests`, `DefaultMainGeometryTests`, `SaveMainGeometryTests`, `MainRestoreWiringTests`). **Second-instance cascade (solo mode)** — a manually-opened instance 2 restores the *same* saved solo `geometry` as instance 1 (a fresh instance 2 even bootstraps its geometry from instance 1's `app_state.json` in `_load_last_state`), so it would land pixel-perfectly on top of instance 1 and look like nothing opened / a crash. `_load_last_state`'s solo branch detects this by comparing instance 2's restored position against instance 1's saved position (read from `APP_STATE_FILE`) and, only when they nearly coincide (<30 px), cascades instance 2 down-right by `CASCADE_OFFSET` (60 px), clamped on-screen. Cascade-only-on-collision preserves deliberate manual placement and prevents drift across launches (once offset, it no longer collides). The duo path is unaffected — it already tiles side-by-side. This is only reachable because the launcher (`SelfBot_Win.ps1` / `SelfBot.app`) is always-launch-fresh, not launch-or-focus, so double-clicking the shortcut twice genuinely opens the self-chat pair.

**Dialog geometry persistence — per instance, per monitor layout (2026-09-16)** — the three auxiliary windows — System Prompt Editor, Skills Manager, Safety — Confirm Patterns — remember their size AND position across launches, each instance separately and each monitor arrangement separately, through the same `_save_last_state` / `_load_last_state` pair the main window uses. The state file (`self._state_file`: `app_state.json` for instance 1, `app_state_2.json` for instance 2, so a duo pair keeps two independent sets; instance 2 seeds from instance 1's file only when its own does not exist yet) carries one `dialog_geometries` dict, **keyed by `_monitor_layout_key()`** — every monitor's rect from `_get_display_rects()`, sorted (the primary screen alone when the enumeration fails) — holding `{prompt_editor, skills_dialog, ps_safety}` → geometry for that arrangement (`DIALOG_WINDOWS` in the module constants maps each kind to its window attribute; `DIALOG_LEGACY_KEYS` to the flat pre-2026-09-16 state keys, adopted once on load by the pure `_dialog_geometries_from_state` and never written again). A monitor added, removed, moved or re-scaled changes the key, so geometries saved on one arrangement are never applied to another (MyAgent's rule): a laptop docked to two monitors and undocked to its panel keeps BOTH sets, and a save under the current key preserves every other layout's entry in the file. Each dialog is saved LIVE while open (`_current_dialog_geometries`, so the 5-second periodic save and a close-with-dialogs-open both capture it), else from its `_last_<kind>_geometry` attribute, which every close path sets — the `WM_DELETE_WINDOW` handler of each dialog, and the prompt editor's **Apply to Chat**, which destroys the editor too (before 2026-09-16 the editor had no persistence at all: a fixed `650x500` wherever the WM put it). Open follows one pattern — `withdraw()` → build → `update_idletasks()` → **`_place_dialog(win, kind, default_size)`** → `deiconify()` — and `_place_dialog` is the one placement routine with the **safe fallback**: the saved position when `_sanitize_geometry` finds a monitor that still shows it; else the saved SIZE at the default position; with nothing saved for this layout, the default size at the default position — the default (`_default_dialog_geometry`) being centred on the main window, shrunk to fit and clamped onto the monitor holding the main window's centre (`_monitor_rect_containing`, primary when the main window is off every monitor), so a dialog with no usable saved spot lands where the user is looking whatever the monitor count or resolution. `transient(root)` on Windows only, since the macOS WM confines a transient to its parent's screen. **`_sanitize_geometry` validates against every monitor**, via `_dialog_geometry_visible` — MyAgent's rule, at least 50 px of the 30-px title strip and 10 px of its height on SOME rect from `_monitor_rects()`. The earlier test (`x < screen_width and x + w > 0`, the primary screen only) rejected every position on a monitor LEFT of the primary, where x is negative, so a dialog parked there was re-placed by the WM on every open — the reason the Skills Manager and Safety dialogs *looked* non-persistent on the dual-monitor desktop while their geometry was in the state file all along. The main window got the same per-layout / any-monitor treatment the same day (see **Dual geometry persistence** above). Pinned in `tests/test_selfbot_dialog_geometry.py` (layout key, sanitize on a two-monitor layout incl. the negative-x case and the no-rects fallback, default placement centred / shrunk / clamped / primary fallback, `_place_dialog`'s three branches, `_save_last_state` live-vs-last-known capture under the layout key with other layouts preserved, `_dialog_geometries_from_state` incl. the legacy adoption, and a source scan of the three dialogs' wiring); live-verified 2026-09-16 on the dual-2560×1440 desktop (editor moved to the left monitor, closed, reloaded from disk, reopened at the identical geometry; then with the display rects patched to one 1920×1080 panel the same file yielded no entry and the editor opened centred on the main window inside that panel). **Since 2026-10-02 every geometry write** — `_place_dialog`, the main-window restore (solo, duo and the instance-2 cascade), PS Safety's 100 ms re-apply and the confirm dialog — goes through `_set_geometry`, an in-file byte-identical copy of `state_mixin.py`'s (with `_shown_normal` / `_settle_when_shown` / `_settle_geometry` and the two `GEOMETRY_SETTLE_*` constants) that makes a window come out at the size it was asked for on a Windows monitor whose scale differs from the primary's, where Tk 8.6 alone grew it by one frame difference per launch — see the **Mixed-scale size settle** paragraph in `.claude/rules/CLAUDE_MYAGENT.md`; pinned by `SizeSettleCopyTests` in `tests/test_selfbot_dialog_geometry.py`.

**DPI handling (SelfBot)** — since 2026-10-14 the same bootstrap as MyAgent's, ahead of every import that could touch Tk: `SetProcessDpiAwarenessContext(-4)` (PER_MONITOR_AWARE_V2), falling back to `SetProcessDpiAwareness(2)`, then to the legacy `SetProcessDPIAware()`. The screenshot pipeline — the macOS Quartz capture resized to the display's logical dimensions, `_screenshot_scale` / `_screenshot_offset` / `_screenshot_dims`, the per-display states, `_api_image_caps`, `pyautogui.PAUSE` — is `DesktopMixin`'s (CLAUDE_MYAGENT.md); SelfBot's own copy of it went with the tool parity change below.

**Why V2** — MyAgent (and SelfBot since 2026-10-14) uses the newer `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` (i.e. `-4`), falling back to v1 then to legacy `SetProcessDPIAware()`. V2 fixes broken multi-monitor behavior under v1 when monitors have different DPI scaling (e.g. 100% primary + 225% secondary): v1 reports the secondary's rect as a logically-scaled smaller size, causing `ImageGrab.grab` to return a low-res image and `pyautogui` clicks to land in the wrong place. V2 returns true physical pixels per monitor regardless of per-monitor DPI.

**Auto-save on close** — When closing (via [X] button or `taskkill`), all instances auto-save their chat as `.json` + `.txt` to `saved_chats/`. The toolbar's DELETE (`_delete_chat`) removes both files of the selected saved chat and, since 2026-09-02, asks first (`askyesno`, default **No**, parented to the main window); no tool path reaches it. Uses the name from the Save Chat entry if provided, otherwise auto-generates from the first user message. Instance 2's files are suffixed with `_` via `_save_name()` to avoid collisions. A periodic auto-save every 5 seconds on all instances also protects against force-kill data loss. Names pass through `_sanitize_filename`, which maps Windows-invalid characters AND control chars (`\x00`–`\x1f`) to `_` — a multi-line first user message otherwise put literal newlines into the auto-generated filename and Windows `open()` failed with `OSError 22`. The two saves in `_finish_close` are wrapped best-effort for the same incident: the close chain runs with `_closing` already latched, so an unhandled save exception aborted the close before `root.destroy()` and every later [X] click was silently eaten by the re-entrancy guard — a dead close button on a healthy window (observed live 2026-07-13; the periodic saver already swallowed the identical exception every 5 s, which is why no chat file ever appeared). A failure past the latch must never abort the close.

**Toolbar "last pressed" highlight (2026-09-08)** — the main window's seven plain buttons — DELETE / NEW CHAT (row 1), SAVE (row 2), Attach Images / System Prompt / Skills / Safety (the button bar; the three formerly anonymous ones are now `delete_chat_button` / `new_chat_button` / `save_chat_button`) — are one "last pressed" group with one shared `toolbar_font = ("Arial", 10)`, the treatment MyAgent's Instruction / START / STOP got the same day (mechanism and invariants in CLAUDE_MYAGENT.md's paragraph of the same name): `_track_toolbar_presses` / `_press_toolbar_button` are **in-file copies** of ui_mixin's (SelfBot's convention — the `myagent` import is the optional kind), pinned byte-identical to the originals by `tests/test_selfbot_toolbar_highlight.py`, and `TOOLBAR_ACTIVE_BG` is try-imported from `myagent.constants` with a literal fallback in the stub block. The seven commands are wired by the tracker call at the end of the button bar (not at creation), so a press repaints first — the pressed button light blue + bold, the other six back to their creation-time look at regular weight — then runs the real handler; the `<Return>` binding on the Save-Chat entry calls `_save_chat` directly and is not a press. Two SelfBot specifics: (1) the red/green **Auto toggle is deliberately NOT in the group** — its colour IS its state (and on macOS it is a click-bound Label, see the next paragraph); (2) none of the seven is ever disabled — only `config(text=…)` relabels on Skills / Safety, which leave the paint alone — so MyAgent's disabled-but-not-greyed STOP treatment has nothing to apply to here.

**Skills Manager list band (2026-09-12)** — the Skills Manager's list wears the fixed uppercase **SKILLS** band that MyAgent's Instruction Editor list (INSTRUCTIONS) and Skills Manager list wear (the why — a native ttk heading lights up on hover and click and cannot hold one look — and the layout are in CLAUDE_MYAGENT.md's *Instructions list* paragraph): a plain `tk.Label` from `list_title_band`, an **in-file copy** of ui_mixin's pinned byte-identical by `tests/test_selfbot_list_title_band.py`, on `LIST_TITLE_BG` (try-imported from `myagent.constants`, literal fallback in the stub block), gridded between the Cycle Mode button and the listbox at the list's width, the scrollbar rowspanning band and list; a Label has no bindings, so the band reacts to nothing.

**Button focus ring on macOS (2026-09-15)** — the same fix MyAgent got the same day (the mechanism, the probes and the invariants are Keyboard operation (8) in CLAUDE_MYAGENT.md; this is the SelfBot delta). Tk 9.0.3 on macOS 26 draws a focused `tk.Button`'s own 1-px focus ring shifted up-left by the parent frame's offset within the window, so SelfBot showed it two ways: the Skills Manager's SAVE / DELETE / NEW (their `top` frame sits at (10, 10)) wore the L-shaped black strike-through MyAgent's Instruction did, and the main window's seven buttons showed no focus cue at all (their frames sit further down, so the ring missed the widget entirely) — checked live in-process on the M4 Mac Mini, with a plain button placed on the root drawing correctly, which is what exposed the offset. From 3 px Tk hands the ring to Aqua, which draws the system's rounded blue one in the right place, so SelfBot carries `install_focus_ring_defaults(root)` as a module-level **in-file copy of `myagent/keyboard.py`'s** (SelfBot's convention: the myagent import is the optional kind) that sets `*Button.highlightThickness` to 3 in the option database when the windowing system is `aqua`, called FIRST in `setup_ui`, before any button exists (the option database only fills options at creation). An explicit `highlightthickness=` still wins — the red/green Auto toggle keeps its 0, its colour IS its state — Windows / X11 are left exactly as they were, and the seven-button "last pressed" frame is 3 px wide on the Mac (it is the same area). Pinned in `tests/test_selfbot_focus_ring.py`: the copy byte-identical to the original, the call first in `setup_ui` and before the first `tk.Button(`, and the Auto toggle's explicit zero.

**Scrollbars out of the Tab order (2026-09-26)** — the same fix MyAgent got the same day (Keyboard operation (4) in CLAUDE_MYAGENT.md has the mechanism; this is the SelfBot delta). Tk's fallback focus rule (`tk::FocusOK`, for a widget whose `takefocus` is unset) counts any viewable, enabled widget whose class carries a Key binding, and Tk 9.0.3's Scrollbar class binds Page Up / Page Down, so on the Mac each of SelfBot's six `tk.Scrollbar`s (chat display, System Prompt editor, Skills Manager list + text, Safety dialog, confirm-command dialog) was a Tab stop. SelfBot carries `install_scrollbar_defaults(root)` as a module-level **in-file copy of `myagent/keyboard.py`'s**, beside the focus-ring copy, that sets `*Scrollbar.takeFocus` to 0 in the option database on every platform, called right after `install_focus_ring_defaults` in `setup_ui`, before any scrollbar exists; an explicit `takefocus=` would still win, and none of the six carries one. Pinned in `tests/test_selfbot_focus_ring.py`: the copy byte-identical to the original, the call after the focus-ring one and before the first `tk.Scrollbar(`. CSVEditor and TodoList need nothing: their scrollbars are `ttk.Scrollbar`s, whose class (TScrollbar) has no Key bindings and so was never a Tab stop (probed 2026-09-26: `tk::FocusOK` answers 0, Tab goes from the Treeview to the next button).

**Cmd+Q is the same close as [X] on macOS (2026-10-31)** — the same fix MyAgent got the same day (Keyboard operation (3) in CLAUDE_MYAGENT.md has the measurements; this is the SelfBot delta). Tk's application-menu Quit calls `::tk::mac::Quit` when that command exists and plain `exit` when it does not — measured on the M4 Mac Mini with real keystrokes: Cmd+Q ended the process at once, `WM_DELETE_WINDOW` never ran, so `_on_close` / `_finish_close` were skipped — the state file, the chat auto-save, the session's cost line (the in-progress record folded it in at the next launch with `unfinished@call<N>`), the peer's close (a duo's partner lingered until its watchdog fired). SelfBot carries `install_quit_handler(root, handler)` and `is_aqua(widget)` as module-level **in-file copies of `myagent/keyboard.py`'s**, beside the scrollbar copy, and `__init__` calls `install_quit_handler(self.root, self._on_close)` right after the `WM_DELETE_WINDOW` protocol line — the same handler, so [X], Cmd+W (which Tk's File > Close already routed to the protocol) and Cmd+Q are one close; a no-op off the Mac. MyAgent's other change of that day — its Alt+letter mnemonics bound to Command on the Mac, Cmd+Shift for the letters macOS owns — has nothing to apply to here: SelfBot has no mnemonics anywhere. Pinned in `tests/test_selfbot_focus_ring.py`: both copies byte-identical, the call within reach of the protocol line and once, no `<Alt-` / `bind_mnemonics` in the file. Verified live on the Mac Mini: Cmd+Q on the real SelfBot exited 0 with `app_state.json` rewritten.

**Voice input (2026-10-14)** — MyAgent's Voice input, adjusted for a chatbot (the user's request, the day the tool parity made `VoiceMixin` one of SelfBot's bases). What is MyAgent's: the **Mike** button, the **Auto-send** box and the status line are the row `_voice_build_row` builds for MyAgent's Agent Request dialog — here gridded under the message box (row 5; the button bar, the Debug row, the tool row and `attach_label` moved down one, to rows 6-9), with `self.root` as the row's window (its `<Destroy>` releases the microphone at close), `self.input_field` as the box the transcript lands in and `_send_as_enter` as the row's `send`; the **Voice Setup** button at the left of the Debug row (created before Debug, so Tab reaches it first; disabled without the `myagent` package, like the row, which is then not built at all) opens the inherited dialog — provider / model / language / vocabulary hint / microphone + Test — over the SAME per-user settings file MyAgent's edits (`~/.config/myagent-voice/config.json`), so one Voice Setup serves both apps on a machine and `microphone_listen` (Physical) hears what Mike hears; the recorder, the dictation state machine, the three transcription paths and their audit-chosen pickers are the mixin's (CLAUDE_MYAGENT.md's **Voice input** paragraph has the contract), and the speech-to-text clients `openai_client` / `xai_client` / `gemini_client` are built in `__init__` whenever the package is present (the gate was the microphone package alone until then; `sounddevice` itself is imported at the first press, never at launch) — transcription only, the chat stays Anthropic-only. **The Enter rule** of the dialog applies to the message box: `on_enter_key` ends a recording in flight (Mike's own toggle) and swallows Enter while transcribing, because sending mid-dictation would lose the speech; `_send_as_enter`, split out of it, is what Enter does past the Shift and dictation checks — the duo's send delay, else `send_message` — and what Auto-send does the moment a transcript lands. **Adjusted, four points** (SelfBot's own methods, overriding the mixin's): (1) `_voice_end_word` returns `""` — SelfBot has no Convo-mode end words, so a dictated "Quit." or "Stop." lands as heard, a message like any other (MyAgent lands the bare word for its end-of-conversation check); (2) `_voice_auto_send_changed` keeps the Auto-send box like SelfBot's other toggles — `dictation_auto_send` in `app_state.json` (saved on the tick through `_save_last_state`, restored by `_load_last_state`) and in a saved system prompt's bundle at its SAVE (`_capture_prompt_settings`, restored by the apply; `_PROMPT_TOGGLE_KEYS` and the `manage_prompts` schema carry it) — where MyAgent writes the value into the applied instruction's store entry at once, because its editor has no widget for the setting; (3) `_voice_key_status` names SelfBot as the app to restart; (4) `_place_window` is a shim over SelfBot's `_place_dialog` for the dialog's placement call (the unpersisted kind `voice_setup`: centred on the main window, then handed a position-only geometry so Tk sizes it from its content, as in MyAgent). **The hands-free loop** (the user's request, later the same day): once a reply has ended — `check_queue`'s `complete` and `error` tails — `_focus_for_reply` puts the focus on Mike while the Auto-send box is ticked, so Enter or Space starts the next dictation at once, and rings the display bell (`root.bell()` — Windows' Default Beep, the Mac's alert sound, nothing where system sounds are muted) as the cue to press Space, the way MyAgent's dialog opens on Mike and rings when its box is ticked (the user's request, later still the same day: "this will let me know when to press space to reply"); the launch restore moves the focus without ringing — there is nothing to answer yet — unless something is already typed in the message box, where Enter must keep meaning send; otherwise the message box takes the focus as it always did, and a launch that restores the box ticked starts on Mike too. No mnemonics — SelfBot has none anywhere. Pinned in `tests/test_selfbot_voice.py` (the REAL row over the voice test fakes on a withdrawn root — the end word landing as heard, the tick saving the state and sending through SelfBot's path, the duo delay parking the send, nothing landed nothing sent — the Enter rule, the overrides, the REAL dialog opened on a transparent mapped root through `_place_dialog` and closed by Cancel, the persistence and wiring scans); `tests/test_selfbot_tool_parity.py`'s STT-client test follows the new gate.
