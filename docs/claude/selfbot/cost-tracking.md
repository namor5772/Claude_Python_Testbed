# SelfBot — API cost tracking

<!-- Moved verbatim from .claude/rules/CLAUDE_SELFBOT.md on 2026-11-10; that file, which loads with every SelfBot task, is now an index pointing here. Edit the contract here. -->

**API cost tracking** — `stream_worker` computes the Anthropic cost of each API call from `final_message.usage` via `_get_pricing(model, prompt_tokens)` — a longest-prefix lookup into MyAgent's `ANTHROPIC_PRICING` table (imported from `myagent.constants` to stay in sync), on the second rate card where a model has one (`ANTHROPIC_LONG_CONTEXT_PRICING`: Haiku 5.5 above 100K prompt tokens) — which prices the four **disjoint** token buckets separately: `input_tokens` × input rate, `output_tokens` × output rate, `cache_creation_input_tokens` × cache-write rate, `cache_read_input_tokens` × cache-read rate — plus, since 2026-09-25, `usage.server_tool_use.web_search_requests` × `ANTHROPIC_WEB_SEARCH_FEE` ($10/1,000 per executed search; an errored search is neither billed nor counted). Costs accumulate into `self._session_cost` **across the whole process** (all messages and chats), and each call emits a `cost_update` queue message that `check_queue` renders in the blue-monospace `cost_info` tag as `$x this call | $y session (in:… out:…)`, **gated by the Activity toggle** (like MyAgent). **Since 2026-10-14 the collection is MyAgent's, per session** (the user's request — the cost log's TIME column was empty on every SelfBot line): `_log_api_cost` is a byte-identical copy of StreamingMixin's writer (`self.provider = "Anthropic"` in `__init__` is what lets it be one), as are `_cost_split_field`, `_run_progress_write` and `_run_progress_clear`, with `_run_progress_fold_in` the same in SelfBot's wording — pinned in `tests/test_selfbot_costlog.py` — and its arguments come from ONE place, `_session_log_args` (the analogue of MyAgent's `_log_run` argument list), built for the close and the in-progress record alike so the two cannot drift: the session's cost; `_session_had_usage` (a call answered with usage, priced or not — the zero-cost gate's flag); **the working seconds** (`_session_secs`: every finished reply's wall-clock minus the seconds it sat on a confirmation dialog, summed in `stream_worker`'s `finally` from `_reply_started`, plus the reply in flight so far — the per-reply form of MyAgent's run clock, `_request_confirmation`'s wait sitting inside `helpers.input_wait_timer` as the inherited mail confirms' already did; NOT the window-open time, which the earlier writer declined to record, and not the human's typing between messages); the active saved system prompt's name as the INSTRUCTION field (SelfBot's analogue of an Agent Instruction, blank when none is loaded, sanitised like MyAgent's); `_session_calls`, incremented beside `call_num` so it totals the process's API round-trips across every message and chat; the four token buckets `_session_tokens_in` / `_out` / `_cache_write` / `_cache_read`, accumulated for EVERY call that reported usage, priced or not (MyAgent's rule); **the per-model split** `_session_per_model` (served model → `[cost, in, out, cache_write, cache_read]`, keyed by `final_message.model` with a dated snapshot of the configured model folded into it — the 13th field whenever more than one model served the session, a mid-chat model switch or a refusal fallback served by an Opus tier, or when its one serving model is not the model the line is logged under, the model at close); and the stem of the chat file the close auto-saved (`_last_saved_chat_name`, set by `_auto_save_on_close` before the line is written — the 14th field, which forces a 13th out, blank or not). So the line is `{timestamp};Anthropic;{model};{cost:.4f};{params};{secs};{prompt};{calls};{in};{out};{cache_write};{cache_read}[;{split}[;{chat}]]`, every field in MyAgent's position and meaning; `params` (5th) is SelfBot's own `_get_model_param_summary()` (the Anthropic-only mirror of MyAgent's ui_mixin helper), comma-joined, the settings at close like the model field. **The in-progress record** — `selfbot_run_<1|2>.json` beside the state file (`SELFBOT_RUN_PREFIX`; per machine, gitignored; `_run_progress_path` is None on a host without `_state_file`, so the bare test hosts never write one) — is rewritten after every call's accounting with exactly what the close would write, and `_finish_close` logs the line (through `_session_log_args`) and THEN removes it, so a record found at launch means that instance died with calls unlogged — the duo's `taskkill`, a crash, a reboot, the `os.kill(pid, 9)` fallback of a peer's close — and `__init__` calls `_run_progress_fold_in` once the queue and the slot exist, before `check_queue` is scheduled: the line is written from the record under its own model and settings, stamped with the time of its last call, `unfinished@call<N>` appended to PARAMETERS, and a ⚠ names the chat; the record goes whatever happens. Until then a SelfBot killed from outside lost its whole session's line. **Unpriced is never silent** either: a call whose model has no pricing row posts one ⚠ per model, shows its tokens behind *unpriced this call | no pricing row* (`check_queue` renders a `cost_update` whose costs are None), and the close skips the line with a second ⚠ (the copied writer's; a `$0.0000` row would claim the session was free), while a session with no usage at all is skipped in silence as before. The log is this machine's `APICostLog_<machine>.txt` in the OneDrive share — **the same file MyAgent writes** (`APICOST_LOG_FILE` resolves through `datapaths.resolve_costlog` in the optional-import block, with a repo-root `APICostLog.txt` stub fallback when the myagent package is absent), viewable via the API Cost Log launcher, which aggregates every machine's file; the copied writer never rotates the log (since 2026-10-25, with MyAgent's: the one-slot 100 KB rotation both ran before each append had moved the laptop's whole history into a `.old` file the viewers ignore; `rotate_log_if_needed` and `APICOST_LOG_MAX_BYTES` left SelfBot's optional-import block with it). The key difference from MyAgent stays: MyAgent logs once **per agentic-loop run**; SelfBot logs once **per process, on close**, because a chat session spans many messages — so one SelfBot line may carry several chats and several models.
