# SelfBot — Shared stores, skills, and system prompts as environment bundles

<!-- Moved verbatim from .claude/rules/CLAUDE_SELFBOT.md on 2026-11-10; that file, which loads with every SelfBot task, is now an index pointing here. Edit the contract here. -->

**Shared-store sync** — `PROMPTS_FILE` and `SKILLS_DIR` resolve through `myagent.datapaths` (try-imported with repo-root stubs when the package is absent) to **`<OneDrive>/MyAppShare/`**, shared with MyAgent — see CLAUDE_MYAGENT.md's datapaths + skills-tree blocks for the full semantics (one-shot repo→OneDrive migration, atomic saves, conflict-fork absorption, never-overwrite-unparseable). Since 2026-08-07 skills are the per-skill `skills/<Name>/SKILL.md` tree (`_load_skills` → `_load_skills_tree`, `_save_skills` → diff-aware write-only `_save_skills_tree`, deletes explicit via `_delete_skill_tree_entry` at both delete callsites); the no-myagent stub fallbacks (`_sb_skill_*`) mirror the exact same file format minus OneDrive fork healing, so a standalone SelfBot.py stays store-compatible. `_load_saved_prompts` is the prompts absorb point; a corrupt/half-synced prompts file now yields a session-only Default instead of the pre-2026-07-19 crash (`json.load` was unguarded) — and since 2026-09-28 that Default is an `_UnreadableStore` which `_save_prompts_to_disk` refuses to write (it returns False after a ⚠ warning and, on the Tk thread, an error dialog; the GUI SAVE / DELETE stop there, and `manage_prompts` returns an error string rather than raising, since it runs on the streaming worker, where an exception ends the turn): every caller modifies the dict it was handed and saves it, so saving the stand-in replaced the whole library with Default plus one change. MyAgent's `_save_instructions_to_disk` guard, ported (`store_unreadable` try-imported from datapaths, with an in-file stub); pinned in `tests/test_review_followups.py`. `STORES_SYNCED` appends "— synced" to the title — appended, not prepended, so Windows peer detection's "Claude SelfBot" substring match still holds.

**Skills system** — Three modes: disabled, enabled (injected into system prompt), on-demand (retrieved via `get_skill` tool). Each skill may carry an optional `description` (what it does + when to use it): `_format_on_demand_listing` (an in-file copy of SkillsMixin's staticmethod, like `_trim_history_for_context`) renders on_demand skills as a bulleted name — description index in the system prompt — the Agent-Skills-style routing signal; undescribed skills list by bare name. `do_manage_skills` accepts `description` on create/update ("" clears it; >1024 chars warns but saves), and both editors' SAVE paths **merge into the existing entry** rather than whole-entry replace, so fields one surface doesn't show survive a save from the other. Managed through `_build_system_prompt()` and `_get_tools()`. Contract unit-tested in `tests/test_skills_description.py` (against the mixin — written when SelfBot was assumed un-importable under test; since 2026-09-02 `tests/test_selfbot_delete_confirm.py` shows it IS importable in-process, because module import builds no Tk root). The **Skills Manager** dialog (`open_skills_editor`) is brought to parity with MyAgent's `skills_mixin`: an expanding Skill Name entry with SAVE / DELETE / NEW hugging the right edge (since 2026-09-02 DELETE asks first — `askyesno`, warning icon, default **No**, parented to the dialog — because it removes the skill's whole folder from the OneDrive-shared tree on every machine with no undo; the `manage_skills` tool's delete action stays unprompted, as in MyAgent; and since 2026-09-25 **SAVE under a NEW name while another skill is loaded is a save-as that copies the source's bundled resource files** — `references/`, `scripts/`, … — into the new folder via `_copy_skill_resources`, MyAgent's `datapaths.copy_skill_resources` through the try-import with a frontmatter-resolving in-file stub for standalone SelfBot, never overwriting existing destination files and never touching an EXISTING skill's folder, an info dialog naming the count; the dialog tracks the loaded skill in a `loaded` closure dict — set by the list selection, cleared by NEW and by deleting it — and the wiring lines are pinned byte-identical to MyAgent's by `tests/test_selfbot_skill_copy.py`, the closures verified live over a temp tree), a "Cycle Mode" button (and the `<space>` key) above a `width=40` listbox that shows each skill's mode via a `[ON]`/`[OD]`/blank prefix plus green/blue coloring, and a content editor on the right. **Geometry persistence** follows MyAgent's withdraw→build→restore→deiconify pattern: on open it applies the saved geometry through `_sanitize_geometry(min_w=400, min_h=300)` (or defaults to `900x500`); the `WM_DELETE_WINDOW` handler captures `win.geometry()` into `_last_skills_dialog_geometry` and calls `_save_last_state`, which persists it in `app_state.json` as `skills_dialog_geometry` (also captured live by the 5-second periodic save while the dialog is open). `_post_skill_ui_refresh()` marshals tool-driven edits (`do_manage_skills`, which runs on the streaming thread) onto the Tk main thread via `root.after(0, …)`, repainting both the Skills button label and an open dialog's listbox through the stored `_skills_refresh_list` closure. SelfBot has **no per-instruction `skill_modes`** (it has no instruction system — MyAgent's `_restore_skill_modes` is deliberately not ported); the `skills/` tree is the single sticky global store.

**System prompt = environment bundle** — Each saved system prompt in `system_prompts.json` bundles a full main-screen environment, analogous to MyAgent's per-instruction settings. Entries are `{name: {text, my_name, my_friend, model, temperature, thinking_enabled/effort/budget/mode, desktop, browser, meta, mcp, google, proton, outlook, excel, physical, exit (`pause` until 2026-10-14, still read), dictation_auto_send, skill_modes, disabled_confirm_patterns}}` — everything on the main screen EXCEPT the Debug/display-toggle row (Debug / Tool Calls / Activity / Show Thinking / Save Thinking), which stays global. `_load_saved_prompts` migrates the legacy flat `{name: "text"}` format to the dict form eagerly on launch (called unconditionally from `_load_last_state`, idempotent); `_prompt_entry_text(entry)` reads the text from either form (named to avoid colliding with the `_prompt_text` editor widget). **Save** (`_save_prompt` / the editor's SAVE button) snapshots the current live main screen via `_capture_prompt_settings()` and writes `{"text": …} + settings`. The editor's DELETE (`_delete_prompt`) confirms first since 2026-09-02 (`askyesno`, default **No**, after its existence checks) — a prompt is a whole saved environment in the shared store, gone from every machine with no undo — while the `manage_prompts` tool's delete action stays unprompted (it already refuses to delete `Default`); pinned in `tests/test_selfbot_delete_confirm.py`, which imports SelfBot in-process (it IS importable under test; the old note above predates that finding). **Load** (selecting a prompt in the editor combo → `_on_prompt_selected`) restores the whole environment via `_apply_prompt_settings(entry)`, which applies only keys present in the entry — so a legacy text-only prompt leaves the current environment untouched. Skill modes apply **session-only** via `_restore_skill_modes` (does NOT rewrite the skills store, the sticky global source of truth — matching MyAgent; skills absent from the snapshot fall back to disabled for that session). Nor does a later skill save, since 2026-09-28: `_skill_global_modes` / `_skills_for_tree` / `_set_skill_mode` are in-file copies of SkillsMixin's, so a save writes each skill's global mode and only Cycle Mode or a `manage_skills` mode change moves it (before, any Skills Manager SAVE / Cycle Mode / DELETE or `manage_skills` change wrote the prompt's session modes into the shared tree). The tool-row toggles (now including Desktop/Browser) and the Safety confirm-bypass set are also persisted independently in `app_state.json` as last-live-state, which serves as the startup baseline (and covers the no-prompt case plus non-bundled keys — Save Thinking, delay, geometry). **On startup the current system prompt is authoritative**: after the independent last-live-state restores, `_load_last_state` re-applies the remembered prompt's full bundle via `_apply_prompt_settings(prompts[last_system_prompt_name])`, so the **skills AND the rest of the layout reflect the current prompt** — not a session that drifted a toggle without re-saving. This is what closes the gap where `_restore_skill_modes` was never called at launch (skill modes previously came only from the skills store); it stays session-only (still does not rewrite the skills store), the 2nd-instance name swap survives (names are guarded inside `_apply_prompt_settings`), and a legacy text-only prompt is a safe no-op (no bundled keys). The `manage_prompts` meta-tool is **bundle-aware** (brought to parity with SelfBot's environment-bundle prompts, mirroring MyAgent's `manage_instructions`): `read` returns the text plus a JSON dump of the bundled environment; `create` writes a full bundle — inheriting the current live `model`/`temperature`/`thinking_*`/`skill_modes`/`disabled_confirm_patterns` from **thread-safe plain attributes** (NOT `_capture_prompt_settings()`, which reads Tk widgets and is main-thread-only — `do_manage_prompts` runs on the streaming worker), with the tool toggles taken from params defaulting OFF and the terminal names bundled only if explicitly passed; `update` overlays any provided bundle field (text, model params, toggles, names) and **merges** `skill_modes` (only listed skills change), leaving the rest intact. Anthropic-only, so unlike `manage_instructions` there is no `provider`/`conversational` field, but there IS a `proton` toggle and `my_name`/`my_friend`. Prompts the tool creates load correctly through `_apply_prompt_settings` (same key set as `_capture_prompt_settings`), including the on-startup apply. The **`apply` action** lets the model switch the LIVE session to a saved prompt (text + full environment) on command — create/update/delete are disk-only, `apply` is the one action that mutates live state. Because `_apply_prompt_settings` touches main-screen Tk widgets (name entries, model/thinking vars, tool-toggle `BooleanVar`s, `_on_model_selected`), `do_manage_prompts` marshals it onto the Tk loop via `root.after(0, …)` + a `threading.Event` wait (same main-thread hand-off as `_request_confirmation`), also setting `self.system_prompt`/`self.system_prompt_name` + `_update_title` so the switch is complete; it catches UI errors into a message and has a 10 s timeout so a wedged main thread can never hang the worker.
