**Model picker & per-model parameters** — The Provider is fixed to Anthropic. `_fetch_available_models` pulls the live `models.list()` and hides deprecated / soon-to-be-retired ids via `DEPRECATED_MODEL_PREFIXES` (Opus 4.1, the dated 4.0 ids `claude-(opus|sonnet)-4-20…`, and every Claude 3.x / 2.x) so newer models appear automatically and only the retiring ones drop out; Opus 4.5 / Haiku 4.5 stay (still active) — Sonnet 4.5 (`claude-sonnet-4-5-20250929`, deprecated 2026-09-30, retires 2026-11-30 → Sonnet 5.5) left the picker and the pricing table on 2026-10-14 under the retirement policy, the Models API's new `lifecycle` field notwithstanding (it still said "active"); its manual-thinking and output-cap wiring stays for a pinned prompt. `claude-3-5-sonnet` is deliberately absent (extended thinking arrived with 3.7/4 — a thinking block to a 3.5 model is HTTP 400). **Prompt caching (`cache_control`)** — ported from MyAgent 2026-07-31 (see CLAUDE_MYAGENT.md for the cost audit that found it: Anthropic caching is strictly **opt-in**, and neither app had ever set a breakpoint, so every call re-sent the whole growing prefix at the full miss rate). SelfBot is the bigger beneficiary of the two: a duo self-chat grows without bound by construction — that is *why* `_trim_history_for_context` exists — and every turn re-sends all of it. Two staticmethods on `App` (SelfBot keeps its own copies, like `_trim_history_for_context`, rather than importing `AnthropicMixin` — the `myagent` import is the optional/stubbed kind): `_cache_system` wraps the system prompt in a cached text block, which covers the tool array too (the prefix is ordered tools → system → messages and a breakpoint caches everything before it), and `_cache_messages` places two rolling markers on the newest eligible turns — three total, under Anthropic's ceiling of four. `CACHE_CONTROL` (module constant, beside `ANTHROPIC_BETAS`) pins the **default 5-minute TTL** deliberately: writes cost 1.25x and match `ANTHROPIC_PRICING`'s cache-write column, so `_get_pricing`'s four-bucket cost stays exact (`ttl: "1h"` would need the `extended-cache-ttl-2025-04-11` beta and 2x writes). Invariants: **history is never mutated** (only breakpointed messages are shallow-copied — `stream_worker` works on `messages` and writes it back to `self.messages` on success, and the overflow handler trims it in place; mutating it here would accumulate stale breakpoints past the ceiling); the **wire copy is rebuilt inside the retry loop**, because the overflow trim's `del messages[:cut_at]` previously reached the retry via `api_kwargs["messages"]` being the same object, which a copy breaks; and assistant turns are skipped (line ~5493 appends `final_message.content` verbatim — SDK Pydantic blocks, not dicts), landing the markers on the user turns. `_payload_for_display` applies both helpers too, for the same no-drift reason `_apply_thinking_params` is shared. A trim invalidates the cache by changing the prefix — one re-write, then the discount resumes. Live-verified 2026-07-31 through SelfBot's own staticmethods (`cache_write=4429` then `cache_read=4429`, `input=2`); watch it in the cost line's `cache_read:` field with Activity on.

**System prompt fixed per reply (2026-09-29)** — MyAgent's fix of the same day (CLAUDE_MYAGENT.md's **System prompt fixed per run** has the why and the incident: a mid-run skill edit re-wrote the whole prompt cache and, on Fable 5.1 / Mythos 5.1 / Opus 5.5, dropped every earlier thinking block). `_build_system_prompt` / `_compose_system_prompt` / `_freeze_system_prompt` / `_thaw_system_prompt` are byte-identical in-file copies of SkillsMixin's, and `stream_worker` freezes after `_mcp_wait_ready`, before its loop, and thaws in a `finally`. SelfBot's run is one REPLY — a `stream_worker` answers one message, typed or peer-injected — so every call of a reply's tool loop sends one prompt, and a `manage_skills` change or a `manage_prompts` `apply` (which sets `self.system_prompt`) made during a reply reaches the prompt at the next message; between messages the prompt follows the live state as before (a System Prompt switch, a Skills Manager edit). `_run_system_prompt` is None in `__init__`. Pinned in `tests/test_system_prompt_freeze.py` (the real `stream_worker` on a bare App over a fake client — success and failure tails — and the byte-identical copies).

**API retry logic** — `stream_worker` retries up to 10 times on transient API errors. Rate-limit errors (429) use exponential backoff capped at 60s (~6.5 min total). Overload errors (529) use exponential backoff capped at 90s (~10 min total). This makes the app resilient to prolonged Anthropic API outages without absurdly long individual waits.

**Context-overflow recovery (self-chat sliding window)** — A self-chatting duo accumulates history without bound, so a long enough run eventually exceeds the model's context window and the API returns a **400 `prompt is too long: <T> tokens > <M> maximum`**. Unlike 429/529 this is **not** retryable as-is, and before the fix it fell through `stream_worker`'s `APIStatusError` handler to the bare `else: raise`, ending the run (observed live: a duo crossed 1M and died with `1597842 tokens > 1000000 maximum`). The handler now has a **first branch** for `status_code == 400 and "too long" in emsg`: it regex-parses the reported `<T>`/`<M>`, calls `_trim_history_for_context(messages, T, M)` to drop the oldest rounds, posts a red ⚠ `warning`, resets `full_text`, and `continue`s the retry loop with the trimmed list (`api_kwargs["messages"]` is the *same* list object, mutated in place by `del messages[:cut_at]`, so the retry sends the shorter prompt). `_trim_history_for_context` cuts **only at genuine user-turn boundaries** — a `is_turn_start` helper treats a `role=="user"` message as a turn start unless its content is a `tool_result` carrier — so a `tool_use`↔`tool_result` pair is never orphaned (which would itself be a 400) and the first kept message is always a real user turn. It sizes the cut proportionally when `T`/`M` parse (`target = 0.75·M`, walk rounds summing `_estimate_content_tokens` ≈ chars/4, images counted 1600 flat, until `T−target` removed), else drops the oldest half; it **always keeps the last two rounds** and returns 0 (→ `raise`, surfacing the original error) when only those remain. Because `stream_worker` runs on `list(self.messages)` and only writes `self.messages = messages` on success, the trim persists into the ongoing conversation (the next injected peer turn continues from the shortened history, preventing immediate re-overflow) without corrupting a mid-run copy. Happy-path calls never touch any of this — the branch fires only on the overflow 400. Structurally unit-tested (turn-boundary cuts, no orphaned tool_results, ≥2-round floor, error-string regex, flat image estimate). MyAgent's Anthropic path had the same latent gap; closed 2026-07-22 by porting the trim into `myagent/helpers.py` (`trim_history_for_context`/`parse_overflow_counts`, same semantics) wired into `anthropic_mixin`'s BadRequestError handler — SelfBot keeps its own in-class copy. On Claude Fable 5.1 this trim is a history edit under the preserved-thinking check (keep-tail compaction) — the `drop_block` binding in the next paragraph is what lets the retry succeed there.

**Claude Fable 5.1 harness surface (2026-09-02)** — the same treatment MyAgent got the same day (the full rationale, the API facts and the SDK 0.84.0 constraints are in CLAUDE_MYAGENT.md's paragraph of the same name; this is the SelfBot delta). `claude-fable-5-1` rides the prefix-matched always-on class for thinking / temperature / effort and the shared `ANTHROPIC_PRICING` table (its own row: cache reads $0.25/MTok, 0.025×), so the picker and `_get_pricing` needed nothing beyond the `FALLBACK_MODELS` / `ADAPTIVE_THINKING_MODELS` entries. In-file copies (SelfBot's convention — the `myagent` import is the optional kind): `_fable_features()` (the two betas + `block_binding` + `fallbacks` for the Fable/Mythos class, None otherwise, minus the surfaces in `_anthropic_unsupported`), `_refusal_note()`, and the classmethods `_strip_thinking_blocks` / `_strip_pre_fallback_blocks` (with `_block_type` / `_block_field` for dict-or-SDK-object blocks), all grouped above `_trim_history_for_context`; the four beta constants are try-imported from `myagent.constants` with literal fallbacks in the stub block. `ANTHROPIC_BETAS` (module constant beside `CACHE_CONTROL`) is the base header list `stream_worker` extends per call. **Why SelfBot needs the binding even more than MyAgent:** its history is user-editable mid-conversation — a system-prompt switch, a tool-toggle change (the `tools` array is part of the bound prefix), a reloaded chat continued under a different prompt, a mid-chat model switch (blocks from another model are dropped as `model_binding_mismatch`), and the overflow trim — every one invalidates Fable 5.1's later thinking blocks, a 400 on enforced accounts without `prefix_mismatch_behavior: "drop_block"`; with it the API drops them unbilled and `stream_worker` prints the `input_transformations` count as an Activity line. The no-beta floor is a 400 rung in the `APIStatusError` handler (checked before the beta-surface rungs, because the signature error text names `block_binding` as its remedy) that strips every thinking block from history via `_strip_thinking_blocks` — in place on the shared message dicts, so the strip persists into `self.messages` — and retries once. **Refusals:** SelfBot had NO refusal handling before this — a classifier decline (HTTP 200, `stop_reason="refusal"`) produced a silently blank reply, and a pre-output refusal left an EMPTY assistant message in history that 400ed the *next* request ("all messages must have non-empty content"); `stream_worker` now appends the trailing assistant text only when non-empty (consecutive user turns are legal — the API merges them) and posts `_refusal_note` (⚠, `stop_details` captured off the `message_delta` event). Fable/Mythos requests opt into server-side fallbacks (`fallbacks: "default"`), so a declined turn is re-run on an Opus-tier model inside the same call — for a duo self-chat that is the difference between the conversation continuing and stalling; the serving model (`final_message.model`, served-by = a `fallback_message` iteration) prices the call and a ⚠ names it, and `_strip_pre_fallback_blocks` applies the echo rule before the assistant turn is appended (`content_blocks` replaces `final_message.content` at both the history append and the `tool_blocks` scan). Verified 2026-09-02 through the real `App` + `stream_worker` in-process (Tk root withdrawn, queue drained by hand): a `run_command` round-trip on `claude-fable-5-1` at effort low, no warnings, call 2's 6,221 cache-read tokens priced at $0.25/MTok ($0.0064). Not adopted, as in MyAgent: per-message effort, turn-scoped `clear_at` system messages, `display: "updates"`.

**MyAgent parity — the October 2026 Anthropic-path changes (2026-10-14)** — SelfBot is Anthropic-only, so every change MyAgent's Anthropic caller got this month applies to it, and the user asked for all of them. Ported in-file (SelfBot's convention; the helpers that are byte-identical copies are pinned so in `tests/test_selfbot_anthropic_parity.py`, which drives the REAL `stream_worker` over a scripted fake client for the rest): (1) **the output ceiling** — `_apply_thinking_params` sends `max_tokens` = `_anthropic_output_cap()` thinking on or off: the startup listing's `max_tokens` per served id (captured by `_fetch_available_models` into `_anthropic_output_caps`, the hidden ids too), else `ANTHROPIC_MAX_OUTPUT_TOKENS`' family row, else `ANTHROPIC_MAX_OUTPUT_DEFAULT` — all try-imported from `myagent.constants` with stubs (no table = the default for every model) — with a 400 rung that learns a refused ceiling (`parse_output_cap`, the exact wording MyAgent probed) and retries at it; `MAX_TOKENS` / `MAX_TOKENS_THINKING` / `MODEL_MAX_OUTPUT_TOKENS` are gone, since 32,768 was the only bound on adaptive reasoning (CLAUDE_MYAGENT.md's **Anthropic output ceiling** has the incident); a manual 32K budget now sits under Haiku 4.5's 64K. (2) **A connection error or timeout** (`anthropic.APIConnectionError`, a sibling of `APIStatusError` under `APIError`, so a rung of its own after it) is retried on the 429 schedule (`connection_error_backoff`) instead of ending the reply — in a duo chat, the conversation; a mid-stream break restarts the call. (3) **HTTP 413** — the body over the API's 32 MB limit, the screenshots a desktop-driving chat keeps — replaces the oldest half of the history's images with a note (`strip_old_images`, in place, the first user turn's images untouched) and retries on the same list, falling back to the overflow trim, then raising. (4) **The dropped-thinking notice** is worded by reason (`_thinking_drop_why`, SelfBot's wording: a mid-chat model switch or a refusal fallback's blocks, vs. a history edit) and said once per CONVERSATION per shape (`_thinking_drops_noted`, reset by `_new_chat`; MyAgent resets per run, but a reply is too short a scope here — after a model switch every reply's first call drops the same blocks). (5) **Claude Haiku 5.5** — `_is_haiku_5` (Haiku major >= 5, so a dated snapshot rides along) joins the adaptive / on-by-default / temperature / xhigh / max helpers, `_fable_features` gives it the thinking binding ALONE (no fallbacks: a list is 400, "default" a no-op), `stream_worker` keeps the binding's beta header off a call whose thinking is an explicit disable (the field is refused there), and it joins `FALLBACK_MODELS` / `ADAPTIVE_THINKING_MODELS`; the server-tools copy already gave it the current triple. (6) **Its second rate card** — `_get_pricing(model, prompt_tokens)` selects `ANTHROPIC_LONG_CONTEXT_PRICING`'s card when the call's whole prompt (input plus both cache buckets) passes the line, the dict carrying `long_context`, with one ⚠ per process (`_long_context_noted`). (7) **run_command** — `_run_command_env` (a byte-identical copy of SafetyMixin's) puts the venv's bin folder first on the child's PATH with `VIRTUAL_ENV` set, and PowerShell is told to write UTF-8 (`_PS_UTF8_OUTPUT`, on its own line ahead of the command) and decoded as UTF-8 with replacement — MyAgent's 2026-09-28 fix: non-ASCII output came back garbled, and one undecodable byte killed the reader thread so the whole output read `[No output]`. (8) **`view_image`** — the 14th Desktop tool, ported that morning as an in-file copy and superseded the same day by the tool parity change below, which made the whole Desktop set `DesktopMixin`'s: its text opens with `FILE_IMAGE_MARKER`, it is PARALLEL_SAFE and gated by the Desktop checkbox like the rest. (9) **The cost log's 14th field** — `_auto_save_on_close` records the saved chat's file stem (`_last_saved_chat_name`) before `_finish_close` logs, and `_log_api_cost` writes it after a blank 13th (the per-model split a self-chat never has), so the viewers' CHAT column names the transcript; a line without one keeps its 12 fields. Deliberately NOT ported: the chats-in-OneDrive move (SelfBot's chats stay per machine by design), the 10 s periodic-save tick (its reason — OneDrive re-uploads — does not apply, so SelfBot keeps 5 s), the in-progress cost record (ported later the same day with the rest of the cost collection — see **API cost tracking** above), and MyAgent's run-oriented UI features (Other Setup colours and the Model upgrade; the Physical tools and Voice input came later the same day — see **Tool parity with MyAgent** and **Voice input** below). Verified by the parity module (35 tests) and the existing SelfBot modules; relaunched on the laptop the same day.
