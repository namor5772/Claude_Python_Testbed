# SelfBot — Tools, MyAgent tool parity, the Exit tool and command safety

<!-- Moved verbatim from .claude/rules/CLAUDE_SELFBOT.md on 2026-11-10; that file, which loads with every SelfBot task, is now an index pointing here. Edit the contract here. -->

**Tool system** — Global tool lists define API tool schemas:
- `TOOLS` — Core tools always sent to the API (`run_command`, `csv_search`); the Anthropic server-side declarations are appended in `stream_worker` from `_anthropic_server_tools()` (2026-09-25, a byte-identical in-file copy of AnthropicMixin's, pinned in `tests/test_server_tools.py`): the current `web_search_20260209` + `web_fetch_20260209` + `code_execution_20260521` triple — free code execution while the web tools are declared — with Haiku 4.5 on the older web pair + `web_fetch_20250910` under its beta, and a learn-off 400 rung for a future model the gate over-admits (see CLAUDE_MYAGENT.md's Server-side tools paragraph)
- `DESKTOP_TOOLS` — MyAgent's 15-tool list, try-imported from `myagent.constants` since 2026-10-14 (the Desktop tools are `DesktopMixin`'s, inherited — see **Tool parity with MyAgent** below): `_get_tools` offers 14 of them when the Desktop checkbox is enabled, `find_element` (Gemini's pointing API) stripped — `view_image` (an image file read into the conversation, MyAgent's tool of 2026-10-13), the `grid` overlay and the per-display `display` parameter included
- `BROWSER_TOOLS` — MyAgent's 12 Playwright/CDP tools (`BrowserMixin`'s, inherited; `browser_download` included), conditionally included when Browser checkbox is enabled
- `FILE_TOOLS` / `READ_DOCUMENT_TOOLS` — MyAgent's five native file tools (`read_file` / `edit_file` / `write_file` / `glob_files` / `grep_files`, `FileMixin`) and `read_document` (`DocumentMixin`; the schema picked out of MyAgent's `TOOLS`), always sent like `TOOLS` — no checkbox, as in MyAgent (since 2026-10-14)
- `EXCEL_TOOLS` / `PHYSICAL_TOOLS` — MyAgent's nine `excel_*` tools (`ExcelMixin`, xlwings) and `camera_capture` / `microphone_listen` (`PhysicalMixin`), included when the Excel / Physical checkboxes are enabled (since 2026-10-14; each Physical tool only with its own package)
- `SELFBOT_META_TOOLS` — 2 meta tools (`manage_skills`, `manage_prompts`), included when the Meta checkbox is enabled
- `GOOGLE_TOOLS`/`PROTON_TOOLS`/`OUTLOOK_TOOLS`/`MCP_TOOLS` — imported from `myagent.constants`, included when the Google/IMAP/Outlook/MCP checkboxes are enabled (see the tool-subsystems note below)
- `_get_tools()` assembles the final tool list dynamically based on UI toggle state

**Adding a new tool** requires three changes:
1. Add schema dict to the appropriate tool list (`TOOLS`, `SELFBOT_META_TOOLS` or `EXIT_TOOLS` — a Desktop / Browser / Excel / Physical / file tool is MyAgent's: add it to `myagent/constants.py` and its mixin, and SelfBot inherits it)
2. Add a `do_<tool_name>()` method to the `App` class
3. Wire it up in the `_execute_tool()` method's tool dispatch block (`elif block.name == "..."`)

**MyAgent tool subsystems (Meta / MCP / Google / IMAP / Outlook — and, since 2026-10-14, Desktop / Browser / Excel / Physical / file / document)** — SelfBot reuses MyAgent's native MCP + mail mixins **by inheritance** (not reimplementation): `class App(MCPMixin, GmailMixin, ProtonMailMixin, OutlookMixin, DocumentMixin, FileMixin, DesktopMixin, BrowserMixin, ExcelMixin, PhysicalMixin, VoiceMixin)` (the last seven since 2026-10-14 — see **Tool parity with MyAgent** below), imported optionally at the module top (`try: from myagent… except:` → empty-class stubs), gated by `_HAS_MYAGENT_TOOLS` plus per-provider `_HAS_MCP`/`_HAS_GOOGLE`/`_HAS_PROTONMAIL`/`_HAS_OUTLOOK`/`_HAS_EXCEL`/`_HAS_PHYSICAL` (from `myagent.constants`; `_HAS_CAMERA` / `_HAS_MICROPHONE` gate each Physical tool). The mixin order matches MyAgent's so Proton/Outlook's helper-prefix anti-shadowing (vs Gmail's unprefixed `_header`/`_extract_bodies`) holds. These tools are **Anthropic-only** (SelfBot has no other provider) and each subsystem's checkbox is `state=DISABLED` when its lib is absent (Meta needs none; Proton is labelled **IMAP**).
- **Host contract** (all the mixins need): `self.root`, `self.queue`, and `self._disabled_confirm_patterns` (a `set`, added in `__init__` — empty means every destructive mail action confirms). `__init__` also calls `_init_mcp_state()`/`_google_init_state()`/`_proton_init_state()`/`_outlook_init_state()` to seed connection caches. MCP is the only subsystem that eagerly connects — `root.after(100, self._connect_mcp_servers)` at startup **regardless of the checkbox** (like MyAgent; the checkbox only gates whether the tools are *offered*), and it is torn down in `_finish_close` via `_disconnect_mcp_servers()`. The connect returns at once (the inherited non-blocking startup, since 2026-09-28 — it used to freeze the window until every server was up) and `stream_worker` calls `_mcp_wait_ready` first, so a message sent while the servers are still connecting waits for them on the worker; a `_`-prefixed server name is disabled.
- **Toggles**: seven `BooleanVar`s (`meta_enabled`/`mcp_enabled`/`google_enabled`/`proton_enabled`/`outlook_enabled`, and since 2026-10-14 `excel_enabled`/`physical_enabled`) in a **second checkbox row** (grid row 8, directly under the Debug/display-toggle row 7 — the rows below the message box moved down one on 2026-10-14 for the voice row, row 5) that also holds the **Desktop** and **Browser** toggles (moved down from the Debug row) and the SelfBot-native **Exit** toggle (**Pause** until 2026-10-14 — see **Exit tool** below); the ten tool toggles thus share one row — Desktop, Browser, Meta, MCP, Google, IMAP, Outlook, Excel, Physical, Exit (they fit at the default width, checked on the laptop 2026-10-14) — and the Debug row carries MyAgent's **Diag** box (`diag_enabled`, the desktop tools' coordinate-trail lines) after Save Thinking — and, since 2026-10-14, the **Voice Setup** button at its left (see **Voice input** below). Both rows are left-aligned (`sticky="w"`) and `attach_label` sits at row 9. Persisted in `app_state.json` (keys `meta_enabled`…`outlook_enabled`, `excel_enabled`, `physical_enabled`, `exit_enabled` — the old `pause_enabled` read once more — `diag_enabled`) and restored only when the corresponding lib is present (a saved-on flag can't re-enable a disabled checkbox). **Convo is deliberately NOT wired** (irrelevant to SelfBot).
- **`_get_tools()`** appends `SELFBOT_META_TOOLS` (Meta), the runtime-populated `MCP_TOOLS`, and deep-copied `GOOGLE_TOOLS`/`PROTON_TOOLS`/`OUTLOOK_TOOLS` with each tool's `account` enum patched from `_get_google_account_names()`/`_get_proton_account_names()`/`_get_outlook_account_names()`; since 2026-10-14 also `READ_DOCUMENT_TOOLS` + `FILE_TOOLS` unconditionally, `DESKTOP_TOOLS` minus `find_element` (Desktop), `BROWSER_TOOLS` (Browser), `EXCEL_TOOLS` (Excel) and the installed `PHYSICAL_TOOLS` (Physical).
- **`_execute_tool()`** routes (before the native chain): MCP by `block.name in self._mcp_tools_by_name` → `do_mcp_call(name, input)`; mail by `startswith(("gmail_","proton_","outlook_"))` → dynamic `getattr(self, f"do_{name}")(input)`; Meta → `do_manage_skills`/`do_manage_prompts`; since 2026-10-14 `excel_` / `camera_` / `microphone_` by prefix (an install hint when the package is absent, a checkbox hint when the toggle is off, then the mixin's `do_<name>`), `read_document` and the five file tools by name — and the Desktop and Browser blocks of the native chain are MyAgent's dispatch (the `grid` and `display` parameters, `browser_download`, a stray `find_element` refused in words).
- **Meta is SelfBot-native**, not MyAgent's `META_TOOLS`: MyAgent's `manage_instructions`/`run_instruction` are tied to its agent-instruction system, which SelfBot lacks. `SELFBOT_META_TOOLS` = `manage_skills` (the shared `skills/` SKILL.md tree, identical to MyAgent — since 2026-09-25 including the four bundled-resource-file actions `list_files` / `read_file` / `write_file` / `delete_file` over the same datapaths helpers, with standalone stubs mirroring them and both apps' action enums pinned equal in `tests/test_skill_resource_tool.py`) + `manage_prompts` (CRUD `system_prompts.json`, SelfBot's analog of `manage_instructions`). `do_manage_skills`/`do_manage_prompts` live on the App; UI refreshes (`_update_skills_button`) are scheduled via `root.after(0, …)` for thread safety.
- **Queue types**: the mail mixins emit `{"type": "warning"}` on confirm-bypass — `check_queue` renders it in the red `error` tag, always shown (independent of Activity). MCP emits `{"type": "tool_info"}` (already handled).

**Exit tool (`exit_conversation`)** — a chatbot that can close itself (2026-10-14, the user's request: change the Pause box's wiring "to actually kill the process as opposed to just STOP — in that way a chatbot can kill itself"). It replaced the **Pause / rest tool** (`pause_conversation`, 2026-07-13 → 2026-10-14), which switched auto-chat off and left both windows open — added to test whether the duo's habit of ending every conversation in a model-driven `taskkill` (given `run_command`, the only exit in its action space) was just the one door out of the room; the rest machinery (`_model_paused`, `_resume_from_model_pause`, the `send_message` hook) went with it. `EXIT_TOOLS` (one tool, optional `reason` param) is gated by the **Exit** checkbox in the tool row (no lib needed; wired like MyAgent's Convo toggle — a per-environment behavioural affordance). `do_exit_conversation` is the model-callable [X]: on the streaming worker it hands `_on_close` — the window's own close handler — to the Tk loop (`root.after(0, …)`; the worker never touches widgets), posts a ⏻ `{"type": "warning"}` notice carrying the reason (always shown; the reason gets its full stop if it has none), and returns a result telling the model the close is coming and that whatever it writes next is a closing note kept in the saved chat but not delivered. `_on_close` latches `_closing` (the peer poll and the auto-message poll stop at once, so no new message can start a reply), switches auto-chat off, removes `AUTO_MSG_FILE`, and WAITS for `self.streaming` to clear — the tool runs mid-turn, so the model's final API round still streams into the window — before `_finish_close` saves the state file and the chat, writes the session's cost line, removes the in-progress record, closes the peer (WM_CLOSE on Windows, SIGTERM on macOS — its own graceful close), releases the lock files and destroys the window: a duo always ends as a pair, as it does from [X]. Auto-chat being off by then, the closing reply is held as `_pending_injection` and never reaches the peer (the chat is over for both). With no partner, the one window closes. The dispatch refuses a call whose box was unticked since the turn began. NOT in `PARALLEL_SAFE`. Persisted as `exit_enabled` in `app_state.json` (the old `pause_enabled` read once more at load), bundled as `exit` in the system-prompt environment (`_capture_prompt_settings` / `_apply_prompt_settings` — which still honours a saved `pause` key until the prompt is re-saved — / `_PROMPT_TOGGLE_KEYS` + a `manage_prompts` param). The tool description states what the tool does, never when to use it, so a duo's end stays the model's own choice. Pinned in `tests/test_selfbot_exit_tool.py` (the schema under the toggle, the dispatch and its guard, the tool on a bare host, the REAL `stream_worker` over the parity fake client finishing the reply after the call, `_on_close`'s wait and the close's order, the persistence keys with the legacy reads, a scan for the old names).

**Command safety / confirm patterns** — `run_command` accepts an optional `timeout` (clamped 5–600 s at dispatch, default 30); `run_powershell(command, timeout)` is Popen-based and on expiry `_kill_process_tree` kills the whole process tree (`taskkill /T /F` on Windows, `killpg` + `start_new_session` on POSIX) before a bounded final pipe read — the MyAgent fix of 2026-07-23 ported verbatim (a timed-out nested shell used to hold the inherited stdout/stderr pipes and block the post-kill `communicate()` forever; see CLAUDE_MYAGENT.md). `run_powershell` gates every `run_command` through `_check_command_safety`, a two-tier check against platform-specific regex lists (`COMMAND_BLOCKED` → rejected outright; `COMMAND_CONFIRM` → needs approval). Brought to parity with MyAgent's safety mixin: a **"Safety" button** (in the main toolbar, next to Skills) opens the **Safety — Confirm Patterns** dialog (`_open_ps_safety_dialog`) — a scrollable list of checkboxes (one `tk.Checkbutton` per pattern embedded in a `tk.Text` for reliable scrolling), where **checked = confirm required, unchecked = bypass**. Sections: the shell `COMMAND_CONFIRM` regex patterns, plus Gmail / IMAP(Proton) / Outlook destructive-tool names (each gated by `_HAS_GOOGLE`/`_HAS_PROTONMAIL`/`_HAS_OUTLOOK`) — the *same* `self._disabled_confirm_patterns` set is consulted by both `_check_command_safety` and the mail mixins' `mail_common.confirm_action`. Toggling a box calls `_toggle_confirm_pattern` (discard/add to the set, refresh the button label, `_save_last_state`). When a matched pattern is bypassed, `_check_command_safety` returns `"skipped"` and `run_powershell` posts a `{"type": "warning"}` ⚠ notice (rendered in red by `check_queue`, always shown regardless of Activity) instead of popping the confirm dialog; the confirm dialog itself (`_request_confirmation`) shows a red "Triggered by: <pattern>" line naming the matched pattern. The Safety button label shows a bypass count (`Safety (N bypassed)`) via `_update_ps_safety_button`. **Persistence**: `_disabled_confirm_patterns` is stored in `app_state.json` as `disabled_confirm_patterns` (a sorted list ↔ set) and the dialog geometry as `ps_safety_dialog_geometry` — both **top-level**, not per-instruction (SelfBot has no instruction system; MyAgent stores them per-instruction). Both warning sources (`run_powershell` and `mail_common`) put the ⚠ sign in the message content, so `check_queue` renders it verbatim. Note: the bare-switch `COMMAND_CONFIRM` entries for `-Force` / `-Recurse` are anchored with a `(?<!\S)` negative-lookbehind (`(?<!\S)-Force\b` / `(?<!\S)-Recurse\b`), so they match when the flag sits at a line start or after whitespace. The earlier `\b-Force\b` / `\b-Recurse\b` form (inherited verbatim from MyAgent) was a latent no-op — a leading `\b` can't assert a word boundary before `-` when it's preceded by a space (both are non-word chars) — and was corrected in commit `758e20b`. Since 2026-09-28 the pattern lists are MyAgent's exactly — `tests/test_review_followups.py` pins `SelfBot.COMMAND_BLOCKED` / `COMMAND_CONFIRM` equal to `myagent.constants`' — so the four Windows registry-delete patterns, whose doubled backslash matched nothing, became MyAgent's working `HKLM|HKCU|HKEY_…` one, a `shutdown` other than `/a` is blocked, and the PowerShell command-position aliases (`ri` / `erase`, `mi` / `move` / `mv`, `rni` / `ren`, `sc` / `clc`, `spps`, `saps`, `iwr … -OutFile`, `iex(`, `Remove-ItemProperty`) are APPENDED to the confirm list (a saved bypass names patterns by their text); and every matching confirm pattern counts — a command runs unasked only when ALL the patterns it matches are unticked (it used to consult the first match alone). **The PowerShell child gets no console window** (2026-10-14): `run_powershell`'s Popen passes `_SUBPROCESS_NOWND` (`CREATE_NO_WINDOW` on Windows; the module twin of `myagent/constants.py`'s) as MyAgent's has since 2026-09-03 — SelfBot's copy had lost it, so under pythonw every `run_command` flashed a Windows Terminal window over the chat; the user saw it while dictating, the bot reading the clock through the physical-interface recipe at the time. Proved under pythonw with an EnumWindows poll: with the flag no window appears during a command, without it a `CASCADIA_HOSTING_WINDOW_CLASS` Terminal window and a `PseudoConsoleWindow` do, the output captured either way. `tests/test_no_console_flash.py` pins the flag on both apps' command runners and inventories every `subprocess` launch in both apps — each flagged, or a POSIX-only program (`ps`, `pgrep`, `osascript`), or a GUI executable, or `run_instruction`'s child interpreter.

**Tool parity with MyAgent (2026-10-14)** — the user asked for the same tools as MyAgent — the Desktop extras, Excel and Physical in particular — and they came the way SelfBot already takes MCP and mail: **by inheritance**, never a second implementation. `DocumentMixin`, `FileMixin`, `DesktopMixin`, `BrowserMixin`, `ExcelMixin`, `PhysicalMixin` and `VoiceMixin` joined the `App` bases (MyAgent's order), and SelfBot's own desktop implementation (`KNOWN_APPS` … `do_mouse_drag`, `_capture_single_display`, that morning's in-file `view_image`), its Playwright helpers and `do_browser_*` tools and its module-level `DESKTOP_TOOLS` / `BROWSER_TOOLS` schema lists — some 1,300 lines — were deleted; the lists are try-imported from `myagent.constants` now (`TOOLS as _MYAGENT_TOOLS`, `FILE_TOOLS`, `DESKTOP_TOOLS`, `BROWSER_TOOLS`, `EXCEL_TOOLS`, `PHYSICAL_TOOLS`, `PARALLEL_SAFE_TOOLS` and the `_HAS_EXCEL` / `_HAS_CAMERA` / `_HAS_MICROPHONE` / `_HAS_PHYSICAL` probes — empty lists and False in the stub block), `READ_DOCUMENT_TOOLS` picked out of MyAgent's `TOOLS`. What SelfBot gained: on Desktop, MyAgent's `view_image`, the `grid` overlay and the `display` parameter of the mouse and OCR tools (MyAgent's per-display coordinate states — `_display_states` / `_display_images` / `_display_full_states` / `_display_full_images` / `_last_screenshot_bytes` — seeded in `__init__`) and the Diag box; on Browser, `browser_download`; the five file tools and `read_document` unconditionally, like `TOOLS` (`_file_read_paths`, FileMixin's read-before-edit memory, is reset by `_new_chat` — a conversation, not a run, is SelfBot's scope); the nine Excel tools behind an **Excel** box and `camera_capture` / `microphone_listen` behind a **Physical** box, each box `DISABLED` without its package (the Desktop and Browser boxes without the `myagent` package), persisted in `app_state.json` and bundled into a system prompt's environment (`excel` / `physical` in `_PROMPT_TOGGLE_KEYS` and the `manage_prompts` schema). `_execute_tool` routes the new families before the native chain (by prefix for `excel_` / `camera_` / `microphone_`, by name for the file and document tools) and its Desktop / Browser blocks are MyAgent's dispatch; `_get_tools` strips `find_element` (Gemini's pointing API — MyAgent offers it to the Google provider alone) and a stray call is refused in words; `PARALLEL_SAFE` = SelfBot's `csv_search` / `get_skill` plus MyAgent's whole set. Not applicable, so not taken: `web_search` / `fetch_webpage` (SelfBot declares Anthropic's server-side tools instead), `user_prompt` (a run's Agent Request dialog), `manage_instructions` / `run_instruction` (MyAgent's instruction store), `find_element`. Three consequences to know: (a) **`microphone_listen` transcribes through MyAgent's Voice Setup provider** — OpenAI by default, xAI or Google, the settings in `~/.config/myagent-voice/config.json` — so `__init__` builds `openai_client` / `xai_client` / `gemini_client` from the environment's keys when the microphone package is present; they transcribe audio and nothing else — the CHAT stays Anthropic-only (the one non-Anthropic client in the file; drop that block to be rid of it and the tool reports the missing client); (b) the DPI bootstrap is MyAgent's V2 one (above), and the Desktop and Browser tools exist only with the `myagent` package (`_HAS_DESKTOP` is anded with `_HAS_MYAGENT_TOOLS`) — a standalone `SelfBot.py` has none; (c) the mixins read STOP through `getattr(self, "stop_requested", False)`, which SelfBot never sets, so a camera self-timer or a 60 s glob runs to its own ceiling (SelfBot has no STOP button). Pinned in `tests/test_selfbot_tool_parity.py` (18 tests: the catalogue per toggle and package flag against MyAgent's lists, the bases and the gone copies, the V2 bootstrap; the dispatch of every family through the real `_execute_tool` with the mixin methods stubbed, the REAL `DocumentMixin` / `FileMixin` tools and `view_image` on temp files, `browser_download`'s arguments, the `find_element` refusal, the parallel-safe set; the state / prompt-bundle persistence, the checkboxes, the `_new_chat` reset, the STT clients; and a REAL screenshot through `DesktopMixin` on Windows); `tests/test_selfbot_anthropic_parity.py`'s ViewImage tests read the inherited `_api_image_caps` now. Relaunched on the laptop the same day: ten boxes on the tool row, Excel and Physical live (xlwings, OpenCV and sounddevice are installed there).
