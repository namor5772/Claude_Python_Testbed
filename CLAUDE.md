# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Environment
- OS: Windows 11 or macOS (cross-platform)
- Python: Activate the `.venv` before running Python commands
  - Windows: `source .venv/Scripts/activate`
  - macOS: `source .venv/bin/activate`
- After activation, use `python` to run scripts (the venv maps it correctly)
- Shell: bash (Git Bash on Windows, zsh/bash on macOS)

## Commands
```bash
# Activate venv (use Scripts on Windows, bin on macOS)
source .venv/bin/activate   # macOS
source .venv/Scripts/activate  # Windows

# Run MyAgent with auto-launch instruction
python MyAgent.py -l "Instruction Name"

# Run MyAgent headless (no main window, auto-closes on completion)
python MyAgent.py -l "Instruction Name" --headless

# Zero-token jobs (normally fired by launchd / Task Scheduler)
python UnreadSummary.py --dry-run   # print the would-be digest: zero mutations, no send
python Heartbeat.py --listen        # the resident Telegram listener (how it is deployed: Task Scheduler MyAgent_Heartbeat_Listener / launchd KeepAlive)
python Heartbeat.py                 # one pass: post finished runs' results, drain one Telegram message, exit
python Heartbeat.py --telegram-pair <bot token>   # once per machine: save the token, pair the first chat that messages the bot
python Heartbeat.py --telegram-test               # message the paired chat from this machine

# MyBackup: the FROM / TO directory mirror (GUI), and its scheduled form
python MyBackup.py
python MyBackup.py --headless       # mirror the saved setup with no window; exit 0 clean / 1 errors / 2 no setup
python MyBackup.py --dry-run        # print the plan, change nothing

# Kill any running instances before relaunching
# Windows:
taskkill //F //IM pythonw.exe 2>/dev/null; taskkill //F //IM python.exe 2>/dev/null
# macOS:
pkill -f "python.*MyAgent.py" 2>/dev/null; pkill -f "python.*SelfBot.py" 2>/dev/null

# Run the MyAgent characterization test suite (stdlib unittest, no extra deps)
python -m unittest discover -s tests -t .

# Lint with ruff (no mypy or build step). Baseline is 41 findings, all E402 — 38 of them MyAgent.py's imports, which

# (the 7 E401 and 5 E741 the baseline carried until the 2026-10-19 refactor are gone) — so judge a change by NEW findings against that baseline, don't chase it to zero
ruff check MyAgent.py myagent/
```

## Portability
- No hardcoded paths — the project works when cloned to any directory on any Windows PC or Mac
- `LaunchSelfBot.bat` uses `%~dp0` (resolves to its own directory at runtime)
- Python files use relative paths for all runtime file I/O
- The `.venv` is gitignored and must be recreated on each machine (`python -m venv .venv` + `pip install` dependencies)

## Workflow
- After editing or changing a .py file, always re-run it automatically — close any currently running instance first if necessary

## Conventions
- Keep code simple and focused — this is a testbed for experimentation
- Use tkinter for GUI work
- SelfBot uses single-file architecture: all changes go in `SelfBot.py`
- MyBackup is single-file too (`MyBackup.py`): keep its mirror engine free of Tk so `tests/test_mybackup.py` can drive it on temp trees, and keep the GUI's worker thread off Tk (events go through the queue; `_poll_queue` is the one place they become widgets)
- MyAgent uses a mixin-based modular architecture: the `App` class in `MyAgent.py` inherits from 27 mixin classes in the `myagent/` package. Add new methods to the appropriate mixin module by concern. `MyAgent.py` itself contains only `__init__` and the entry point.
