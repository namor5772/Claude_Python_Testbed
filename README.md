# Claude Python Testbed

A cross-platform (Windows 11 / macOS) collection of Python GUI applications and automation scripts, written almost entirely with [Claude Code](https://claude.com/claude-code). Everything is tkinter, everything runs from one cloned folder with no hardcoded paths, and the repo doubles as a living testbed for agentic-AI patterns: tool use, multi-provider streaming, desktop/browser automation, native mail integrations, MCP, and zero-token replacements for jobs that once burned API dollars.

The main residents:

| App | One-liner |
|---|---|
| **SelfBot.py** | Full-featured Claude chatbot (Anthropic-only) that can also run as *two instances talking to each other* |
| **MyAgent.py** + **myagent/** | Fire-and-forget autonomous task agent — Anthropic, OpenAI, Google (Gemini), xAI (Grok), Moonshot (Kimi), and Ollama (local) providers, ~97 built-in tools, MCP, native Gmail/IMAP/Outlook mail, live Excel automation |
| **Account_Activity_WBC.py** | Browser-automation utility that extracts Westpac bank transactions to HTML + CSV |
| **CSVEditor.py** | Spreadsheet-style CSV editor with filtering, date sort, and dialect preservation |
| **TodoList.py** | Todo manager with priorities, categories, due dates, and overdue highlighting — one OneDrive-synced list across all machines. `TodoList.mm` (macOS/Cocoa) and `TodoList.cpp` (Windows/Win32) are functionality-identical native C++ ports (`./build_todolist_native.sh` / `.\build_todolist_native.ps1` → `TodoList.exe`); all three round-trip the same synced file |
| **UnreadSummary.py** | Zero-token daily unread-email digest across Gmail / IMAP / Outlook accounts (production launchd job) |
| **Heartbeat.py** | Zero-token email-triggered agent dispatcher — email yourself `APD` / `APL` / `APM` and that machine launches MyAgent (production launchd + Task Scheduler jobs) |

## Quick Start (new machine)

The project is fully portable — clone anywhere, no path edits.

**Windows:**
```bash
git clone https://github.com/namor5772/Claude_Python_Testbed.git
cd Claude_Python_Testbed

python -m venv .venv
source .venv/Scripts/activate   # Git Bash   (CMD/PowerShell: .venv\Scripts\activate)

pip install -r requirements.txt

# Set the API key(s) you plan to use (or set them permanently via System Properties / setx)
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-proj-..."       # optional — MyAgent OpenAI provider
export GEMINI_API_KEY="..."               # optional — MyAgent Google (Gemini) provider
export XAI_API_KEY="xai-..."              # optional — MyAgent xAI (Grok) provider
export MOONSHOT_API_KEY="sk-..."          # optional — MyAgent Moonshot (Kimi) provider
```

**macOS:**
```bash
brew install python-tk@3.13     # system Python's Tk is too old

git clone https://github.com/namor5772/Claude_Python_Testbed.git
cd Claude_Python_Testbed

python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Keys go in ~/.zshrc or ~/.zshenv — zsh terminals read both, and the Desktop
# .app launchers source both explicitly (AppleScript's `do shell script` runs
# /bin/sh, NOT zsh, so neither file is read automatically — see
# desktop_launchers/README.md). Append them with echo rather than a
# terminal-embedded editor — bracketed-paste escape sequences pasted into an
# editor can corrupt the key (it ends up as \x1b[200~sk-...~ and every API
# call 400s).
echo 'export ANTHROPIC_API_KEY="sk-ant-..."' >> ~/.zshrc
source ~/.zshrc
```

**Requirements** (`requirements.txt`): `anthropic`, `openai`, `google-genai`, `google-api-python-client`, `google-auth-oauthlib`, `google-auth-httplib2`, `msal`, `requests`, `ollama`, `ddgs`, `httpx`, `pyautogui`, `pygetwindow`, `Pillow`, `pypdf`, `python-docx`.

**Optional extras**, installed only when you want the feature:

| Package | Enables |
|---|---|
| `playwright` | Browser tools (CDP connection to Edge/Chrome/Brave — **no** `playwright install` needed, the system browser is used) |
| `mcp` (+ `pywin32` on Windows) | External MCP servers via `mcp_servers.json` |
| `pyperclip` | Unicode text input via clipboard paste (desktop tools) |
| `winocr` | `read_screen_text` OCR on Windows (macOS uses the built-in Vision framework) |
| `opencv-python` | `find_image_on_screen` template matching |

At least one of `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`/`GOOGLE_API_KEY`, `XAI_API_KEY`, or `MOONSHOT_API_KEY`/`KIMI_API_KEY` must be set for MyAgent — **or** a local [Ollama](https://ollama.com) server, which is auto-detected at `localhost:11434` with no key at all. SelfBot requires `ANTHROPIC_API_KEY` specifically. The `.venv` is gitignored and recreated per machine; all runtime state files appear on first run.

Run anything with the venv active:

```bash
python SelfBot.py
python MyAgent.py
python CSVEditor.py
python TodoList.py
python Account_Activity_WBC.py
```

## SelfBot.py — Claude Chatbot & Dual-Instance Self-Chat

A single-file (~5,300-line) tkinter chatbot for the Anthropic API that works in two modes: a normal solo chatbot, or **two instances chatting with each other** via file-based message passing.

**Core features**

- **Model / temperature / thinking** toolbar — model list fetched live from the API (deprecated ids filtered out, so new models appear on their own); per-model parameters are version-parsed rather than hardcoded: adaptive models (Opus/Sonnet ≥ 4.6, Fable/Mythos 5 and 5.1) get MyAgent's Thinking-mode combobox — always-on models drop *Off*, temperature-rejecting models never see the param — while the 4.5 family keeps the manual checkbox + token budget. The Fable/Mythos class also carries the Claude Fable 5.1 harness surface (in-file copies of MyAgent's, see the 2026-09-02 note in the MyAgent section): `block_binding: drop_block` so a mid-chat prompt / tool / model switch, a reloaded chat or the overflow trim can't 400 on 5.1's bound thinking blocks, and server-side refusal `fallbacks` so a classifier decline is re-run on an Opus-tier model inside the same call instead of blanking the reply (priced at the serving model's rates); a whole-chain refusal is surfaced as a ⚠ line rather than an empty turn that would break the next request. *Show Thinking* (display) and *Save Thinking* (persist signed thinking blocks into saved chats so reloaded conversations keep their reasoning context) are independent toggles.
- **Tool use** — always-on core tools (`run_command`, `csv_search`) plus Anthropic's server-side `web_search` and `code_execution`; a toggle row gates the rest: **13 desktop-automation tools** (pyautogui: screenshot, click, type, OCR, clipboard, window management…), **11 browser tools** (Playwright over CDP), MyAgent's **MCP / Gmail / IMAP / Outlook** subsystems (reused *by inheritance* from the `myagent` mixins: stdio MCP servers plus the three 16-tool mail families), a SelfBot-native **Meta** pair (`manage_skills` + `manage_prompts`), and the **Pause** rest tool (below). `_get_tools()` assembles the list dynamically from the toggles.
- **Skills system** — reusable prompt fragments, one `SKILL.md` file per skill in the OneDrive-synced `skills/` tree (Agent-Skills-shaped; see *Cross-machine store sync* in the MyAgent section), with three modes per skill: *disabled*, *enabled* (injected into the system prompt), *on-demand* (fetched by the model via a `get_skill` tool). Each skill may carry an optional **description** — one or two sentences saying *what it does and when to use it*, listed per-skill in the system prompt's On-Demand Skills index (the Agent-Skills-spec routing signal, so the model triggers skills from more than a bare name; undescribed skills still list by name). Editable in the Skills Manager's three-row word-wrapped Description box or via `manage_skills`. New skill names are **kebab-case-enforced** (the dialog offers a one-click auto-converted name; `manage_skills` rejects non-conforming creates with the suggestion in the error; legacy names stay editable). Shared with MyAgent — one OneDrive-synced copy serves both apps on every machine (see *Cross-machine store sync* in the MyAgent section).
- **System prompt library** — named prompts in `system_prompts.json` (also OneDrive-synced; the title bar shows "— synced") with an editor dialog. Each prompt bundles a full main-screen *environment* — terminal names, model + thinking params, tool toggles, session-only skill modes, safety bypasses (MyAgent-instruction parity) — restored whole when the prompt loads, and the remembered prompt is authoritative at startup. The model can CRUD the library itself via `manage_prompts`, whose `apply` action switches the live session.
- **Chat management** — save/load named chats (`saved_chats/*.json` + a `.txt` transcript always written alongside), image attachments, DELETE/NEW CHAT, auto-naming from the first user message. Since 2026-09-02 every SelfBot DELETE button — saved chat, system prompt, skill — asks first (a warning dialog with **No** as the default), matching MyAgent; the `manage_prompts` / `manage_skills` tool delete actions stay unprompted so a model acting on an explicit instruction is never blocked by a dialog.
- **Command safety** — two-tier regex guardrails (`COMMAND_BLOCKED` / `COMMAND_CONFIRM`) with a confirmation dialog marshalled onto the Tk main thread; a Safety dialog lists every confirm pattern and destructive mail tool with per-item bypass checkboxes (a bypassed action logs a red ⚠ audit line instead of popping the dialog).
- **Cost tracking** — each call is priced from `usage` across all four token buckets (input / output / cache write / cache read) into a running session total, logged on close to the same per-machine cost log MyAgent writes (`APICostLog_<machine>.txt` in the OneDrive share — see *API Cost Tracking* in the MyAgent section); since 2026-08-10 the close line also records the **parameters in effect** — thinking mode / budget label / temperature actually sent, via SelfBot's own `_get_model_param_summary()` — as the line's 5th field, matching MyAgent's per-run lines (but not MyAgent's 6th TIME(sec) duration field, added 2026-08-12: a self-chat's "duration" is how long the window stayed open, not a comparable run metric, so SelfBot leaves that field EMPTY and renders a blank TIME column); since 2026-08-16 the close line also carries MyAgent's two newest fields in the same positions — the 7th is the **active saved system prompt's name** (SelfBot's analogue of an Agent Instruction → the viewers' INSTRUCTION column, blank when none is loaded) and the 8th is the **session's API-call total** (`_session_calls`, counted beside the per-message `Call #N` counter → the CALLS column), so a self-chat's spend can be read against how many round-trips it took. Since 2026-07-31 SelfBot also sets Anthropic **prompt-cache breakpoints** (ported from MyAgent — see *API Cost Tracking* below): a duo self-chat grows without bound by construction, which is exactly why the sliding-window trim exists, and every turn re-sends all of it — so the cached-prefix discount compounds for as long as the pair keeps talking.
- **Resilience** — exponential-backoff retry (HTTP 429 capped at 60 s, 529 at 90 s, up to 10 attempts); **context-overflow recovery** — an endless self-chat eventually exceeds the model's context window, and the resulting `prompt is too long` 400 now trims the oldest rounds (cutting only at true user-turn boundaries so `tool_use`/`tool_result` pairs are never orphaned, always keeping the last two rounds) and retries, so the duo keeps talking on a sliding window instead of dying at the 1M-token wall; periodic 5-second auto-save, auto-save on close, graceful paired shutdown. The close sequence is exception-total: auto-save filenames are sanitized down to control characters (a multi-line first message once put literal newlines into the derived filename, Windows rejected it, and the aborted close left the [X] button permanently dead behind its re-entrancy guard), and a failed save can no longer abort the close — [X] always wins.

**Dual-instance mode** — double-click `LaunchSelfBot.bat` (Windows) and two instances open side by side, or press the SelfBot Desktop launcher twice (Windows **or macOS** — the second window cascades off the first so they don't stack). Instance 1's reply is injected into instance 2's input and vice versa, with a configurable send delay, an Auto-chat toggle, pause/resume via pending-injection, name swapping (each instance shows the other's name as the "friend"), independent geometry/state files (`app_state.json` / `app_state_2.json`), and a paired shutdown that saves both chats and closes both windows from either [X]. The duo is fully cross-platform (since 2026-07-13): macOS pairs by *process* rather than window title (pygetwindow is Win32-only, and reading other apps' titles on macOS needs a Screen Recording consent) and closes the peer with a graceful `SIGTERM` handler instead of `WM_CLOSE`. **"Close one → both close" now holds for every death mode:** the graceful [X]/`taskkill` path broadcasts the close to its peer, and a watchdog in the peer-poll covers *ungraceful* peer death (crash, `taskkill /F`, or a model self-terminating via `run_command`) — once paired, a peer that vanishes without the broadcast triggers the survivor to run the same graceful close (finish streaming, save chat, exit) instead of lingering solo. The one message that can't be recovered is the *dying* instance's own in-flight reply on a force-kill, so a model wanting a clean exit should use `taskkill` **without** `/F` (which runs the full graceful duo shutdown and saves both chats). Killing a process is also no longer the only exit: the **Pause** toggle offers the model a `pause_conversation` tool — the hang-up that isn't a shutdown. Calling it flips auto-chat off, so the chat simply goes quiet with both windows open for the human to read. The pause is a rest, not a latch: the next fresh message (human-typed or peer-injected, or Auto: ON) resumes the conversation automatically, while a human's manual Auto: OFF is never auto-resumed. The tool's description is deliberately neutral about pausing vs closing, because it doubles as an experiment — every duo chat given `run_command` has ended in a model-driven graceful `taskkill`, and the pause tool tests whether that pattern was preference or just the only door out of the room. Watching two Claudes interview each other is the original reason this repo exists.

Architecture notes live in [.claude/rules/CLAUDE_SELFBOT.md](.claude/rules/CLAUDE_SELFBOT.md). By convention SelfBot stays a single file — all changes go in `SelfBot.py`.

## MyAgent.py — Autonomous AI Task Agent

A fire-and-forget task runner: you write an **Instruction** (the task), pick a **Provider + Model**, press **START**, and the agent loops — calling tools, reading results, calling more tools — until the task is done. You are a passive observer unless the agent explicitly asks for input via its `user_prompt` dialog.

### How the agentic loop works

1. **Configure** — write or load an Agent Instruction (optionally with attached reference images).
2. **START** (or `-l` from the command line) — the instruction becomes the first user message; a background thread starts the loop.
3. **Loop** — `stream_worker()` streams the response; on `stop_reason: "tool_use"` it executes the requested tools (parallel-safe network tools concurrently, everything else sequentially in order), appends results, and calls the API again; on `"end_turn"` the task is complete.
4. **STOP** — cancels mid-stream, not just between calls.

There is no fixed iteration limit; a **Call #N** badge counts API round-trips.

### Command-line launch

```bash
python MyAgent.py                              # normal GUI launch
python MyAgent.py -l "Weather_Agent3"          # auto-load instruction + START
python MyAgent.py -l "Weather_Agent3" --headless   # no main window, auto-closes when done
```

`-l` restores the instruction's full profile (text, images, tool toggles, provider, model, thinking params, skill modes, safety bypasses) and auto-fills "Save Chat as" with `{Name}_{timestamp}` so output is always captured. `--headless` withdraws the main window; dialogs still float standalone when needed. Headless is the backbone of every scheduled job below. Multiple instances can run at once — each claims an instance number via PID-verified lock files (`O_CREAT|O_EXCL` atomic claims; a judged-stale lock is reclaimed under a per-slot mutex *directory* with the content re-validated inside it, because a bare check-then-remove is a TOCTOU that let racing siblings double-claim a slot — caught by the reclaim-storm test on macOS) and gets its own `agent_state_N.json`.

### Providers & model controls

A **Provider** combobox switches between **Anthropic**, **OpenAI**, **Google**, **xAI**, **Moonshot**, and **Ollama**; only providers with a key (or a reachable Ollama server) appear. Labels are company names — Google serves the Gemini models, Moonshot the Kimi models — and instructions saved under the older "Gemini"/"Kimi" labels normalize on load. Model lists are fetched live per provider and filtered to what actually works — and, since the 2026-07 audit, models with an **announced retirement are removed ahead of their shutdown date**: hidden from the picker and unpriced, while the parameter wiring stays so a saved instruction pinning one keeps working until the provider actually pulls it. Per provider: Anthropic drops deprecated ids (Opus 4.1/4.0, Claude 3.x/2.x — `claude-opus-5` is the new default, a drop-in for Opus 4.8 at the same $5/$25); OpenAI keeps only the Responses-API `gpt-4.1`/`gpt-5` families minus the scheduled-out gpt-5.0 base tiers, `-chat`/`-codex` ids, and the whole o-series (all replaced by the GPT-5.6 sol/terra/luna tiers, terra default); Google keeps generative Gemini 3.x (2.5 is sunsetting ≥ 2026-10-16 and picker-hidden; since the 2026-08-25 audit `gemini-3.7-flash` — the stable Flash tier that `gemini-flash-latest` now resolves to — is the default); xAI keeps the grok chat/code tiers, image/video-gen dropped; Moonshot keeps the live `kimi-k*` catalog, with the discontinued dash-family `kimi-k2-*` dropped. The internal message format stays Anthropic-style — translation to each API happens only at the boundary. xAI rides on the OpenAI SDK pointed at `https://api.x.ai/v1` (its Responses API is OpenAI-compatible), so it reuses the same message/tool translators with its own streaming caller.

**Moonshot (Kimi)** also rides the OpenAI SDK — at `https://api.moonshot.ai/v1` with `MOONSHOT_API_KEY` (or `KIMI_API_KEY`) — but its surface is **Chat Completions only**, so it carries its own message/tool translators instead of reusing the Responses ones. The load-bearing detail is **`reasoning_content` round-tripping**: Kimi's thinking models return their reasoning in a non-standard field and are *trained* to have it sent back unmodified on assistant messages across tool-call loops — a naive OpenAI-compatible harness "works" but silently underperforms without this. MyAgent stores the streamed reasoning as thinking blocks in its internal history and replays it per model: required for `kimi-k3` / `kimi-k2.7-code` (Preserved Thinking always on) and `kimi-k2.6` (requested with `thinking.keep: "all"`), never for `kimi-k2.5` (unsupported there), with a learn-once 400 fallback for future models. Temperature is never sent (every Kimi model fixes sampling server-side), and re-sent reasoning bills as input at Kimi's cheap cache-hit rate, which the exact cost tracking accounts for (below). A `Kimi_Feature_Test` instruction in the shared store smoke-tests the whole surface — parallel tool fan-out, web search/fetch, file round-trip, `run_command`, browser + vision, and a memory-across-tools check that proves the reasoning round-trip (7/7 on its first live run, $0.058).

The parameter widgets are **model-aware**: controls that a model rejects are *hidden, not just disabled*.

### Ollama (local inference)

No key, no cost, no egress — at the price of speed (a 32B Q4 model on Apple Silicon streams ~10–30 tok/s).

```bash
ollama serve
ollama pull muse-glimmer:30b-mlx    # tools + vision + thinking (21 GB) — first pick
ollama pull qwen3:32b-q4_K_M        # text + tools + thinking (20 GB)
ollama pull qwen2.5vl:32b           # vision (21 GB)
ollama pull gemma3:27b              # strong vision (17 GB)
```

The model dropdown auto-populates from the local server, and **per-model capabilities are auto-detected** via `/api/show` (tools / vision / thinking / context length) — no hand-coded model lists. Context is passed as `num_ctx`, capped by `OLLAMA_NUM_CTX_CAP` (default 32768) to avoid KV-cache swap pressure on 32 GB machines. Tuning env vars: `OLLAMA_BASE_URL`, `OLLAMA_NUM_CTX_CAP`, `OLLAMA_KEEP_ALIVE` (set `24h` to avoid repeated cold loads — passed per-request since 2026-08-12; it was documented here but unwired before that. A warm model also reuses the server's KV prefix cache, so repeat runs skip most of the system-prompt/tool-catalog prefill — the dominant cost of 30B-class local agent runs, measured at ~58 tok/s prefill on the base M4. Reclaim the RAM anytime with `ollama stop <model>`).

**Muse Glimmer** (ADOPTED 2026-08-12 on the M4 Mac Mini — pulled, capability-verified via `/api/show`, and smoke-tested live: `think: true` reasoning + correct generation at ~10 tok/s on Ollama 0.32.9): Meta's 30B open-weights agentic model (Apache 2.0, released 2026-08-10, the first release from Meta Superintelligence Labs) is a confirmed **zero-code drop-in** for this provider — its Ollama build advertises exactly the three capabilities the auto-detection reads (tools / vision / thinking), so `ollama pull muse-glimmer:30b-mlx` (21 GB Apple-Silicon MLX build; plain `:30b` is 18 GB) is the entire "wiring". Same memory envelope as `qwen3:32b-q4_K_M`, with its 128K context capped to 32K by `OLLAMA_NUM_CTX_CAP` as usual; being local its runs log as `$0.0000` lines (see *API Cost Tracking*). Benchmarked the **fastest 30B-class model on the machine**: 58 vs 38 tok/s prefill and 9 vs 5 tok/s generation against `qwen3:32b-q4_K_M` on an identical 8.8K-token prompt at 32K ctx — so the minutes-long first-call prefill of a big tool catalog is the base M4's 30B reality, not a Muse Glimmer defect, and Muse Glimmer suffers it least. Update Ollama itself before pulling — the model manifest declares `requires 0.32.7` (the Mac Mini's 0.20.6 had to upgrade; the new perception-encoder architecture and MLX image input need it). The two optional cosmetic tweaks are applied: `"muse-glimmer"` is in `OLLAMA_VISION_PREFIXES` (silences the false weak-desktop-combo warning — screenshots are sent and understood regardless) and `OLLAMA_THINKING_PREFIXES` (surfaces the boolean Thinking checkbox; the `/api/show` capability gate makes that safe). ### Tool catalog

Roughly **97 built-in tools in nine families** (core 6 · file 5 · desktop 14 · browser 12 · meta 3 · mail 3 × 16 · Excel 9), plus dynamic MCP tools and the on-demand `get_skill` (whose skills are indexed in the system prompt by name **and optional description** — the what+when trigger signal, Agent-Skills style):

- **Core (always on):** `run_powershell`/`run_shell`, `csv_search`, `read_document` (PDF via pypdf, DOCX via python-docx, HTML, plain text — with page ranges, encrypted-PDF detection, per-page error isolation), `user_prompt` (the *only* way the agent can ask you something mid-task; empty reply = stop the agent — and the Agent Request dialog has the same Attach Images / Remove Selected controls as the instruction editor (identical layout in both: buttons stacked left of the filename listbox) — plus **Ctrl+V paste**: an image on the clipboard (a PrintScreen bitmap, files copied in Explorer/Finder, or — Windows — a web app's CF_HTML copy carrying an `<img>` reference, e.g. OneDrive Photos: a `data:` URI decodes locally, an https URL is downloaded best-effort) becomes an attachment, while text pastes normally; both the dialog and the instruction editor's text area support it — so a reply can carry images back to the model: they ride the tool result as standard image blocks, the same shape screenshots use, so every provider handles them; an image-only reply is auto-labelled "[See attached image(s)]" instead of counting as an empty stop. Convo-mode replies carry attachments the same way, as image blocks on the user message), and `web_search` + `fetch_webpage` for providers without server-side search. `run_command` takes an optional model-settable `timeout` (default 30 s, clamped 5–600) and a timed-out command now has its **whole process tree** killed — previously only the direct shell died, and a nested grandchild (e.g. `powershell -File` → `cmd` → `cl.exe` in a C++ build) kept the inherited output pipes open, wedging the agent thread indefinitely (diagnosed 2026-07-23 from a hung `Coding_Agent_CodingAgent_WIN_Laptop` build step; SelfBot carries the same fix).
- **File tools (always on):** `read_file` / `edit_file` / `write_file` / `glob_files` / `grep_files` — Claude-Code-style contracts for reliable code editing instead of shell round-trips: `edit_file` needs an exact, *unique* `old_string` match and fails loudly otherwise; edits and overwrites require the file to have been `read_file`'d first; CRLF line endings and a UTF-8 BOM round-trip byte-exactly; glob/grep prune `.git`/`.venv`/`node_modules` and skip binaries. Paired with the shared-store `Coding_Agent` instruction (explore → read → surgical edit → verify by running tests) — which also carries the Meta tools, so it can author child instructions and spawn them as waited subagents (`run_instruction` + `extra_text`): a self-contained Claude-Code-style coding orchestrator. Its instruction text now ends with a **DELEGATION roster** (mirroring how Claude Code injects its agent catalog: when to delegate, when not to, and that a child starts cold so the `extra_text` brief must be self-contained) naming eight least-privilege child instructions shipped in the same store: `Code_Scout` (read-only codebase research — `run_command`/`edit_file`/`write_file` hard-blocked via `blocked_tools`), `Test_Verifier` (runs tests/linters and reports verdicts — edit tools blocked), `Code_Reviewer` (reviews a diff, findings only — edit tools blocked), `Code_Planner` (read-only implementation planning — stepwise plan + risks + verification commands; same full blocklist as Code_Scout; the roster suggests spawning 2-3 in one turn with different angles and merging the best ideas, the judge-panel pattern), `Finding_Verifier` (adversarial check of ONE claimed defect — tries to *refute* it and returns CONFIRMED/REFUTED with evidence; `run_command` allowed for reproduction, edit tools blocked; fan out one per Code_Reviewer finding), `Security_Reviewer` (security-lens review — injection, secrets, path traversal, unsafe deserialization; findings only, edit tools blocked; runs in parallel with Code_Reviewer as a second lens), `Git_Historian` (read-only git archaeology — log/blame/show for "when/why did X change", never mutates repo state; fills the history gap Code_Scout's `run_command` block leaves), and `Code_Simplifier` (quality lens — duplication of existing helpers, dead code, wrong altitude; behaviour-preserving suggestions only, run after tests pass). All eight are Meta-off (no grandchildren), Convo-off, take their entire task from the ADDITIONAL TASK CONTEXT block (children can't ask questions — a headless `user_prompt` just stalls into the timeout), and end with a structured FINAL REPORT the parent receives as its tool result. First live orchestration verified 2026-07-22: told "review the last commit", Coding_Agent composed a complete brief (including redirecting from the clean working tree to `git show` on the commit), spawned `Code_Reviewer` with `wait=true`, and relayed its report — child cost logged to `APICostLog.txt` on its graceful close. The whole family now shares Claude Code's **CLAUDE.md project-memory convention** (2026-07-23): a PROJECT MEMORY block has the parent read the target repo's `CLAUDE.md` (plus any task-relevant `.claude/rules/*.md`) as soon as it knows the repo and treat it as authoritative conventions, offer via `user_prompt` to append durable non-obvious learnings back with `edit_file`, and offer to bootstrap a missing `CLAUDE.md` after exploring; DELEGATION briefs must carry the repo root and the load-bearing rules, with each child's shorter PROJECT MEMORY paragraph re-reading the file as a fallback — so MyAgent and Claude Code converge on the same per-repo memory file, synced by git like any other tracked file. The children's saved models are **value-tiered by workload** — readers/runners (`Code_Scout`/`Test_Verifier`/`Git_Historian`) on Haiku 4.5 (thinking off, temp 0; Scout carries a small 4096-token thinking budget for where-to-look-next judgment), judges (`Code_Reviewer`/`Security_Reviewer`/`Finding_Verifier`/`Code_Simplifier`) on grok-4.5 at reasoning low, `Code_Planner` at medium/temp 0.2 — pay for judgment, economize on reading; the fan-out children are exactly where the cheap-output discount compounds, and xAI's exact billing makes the per-child cost auditable in `APICostLog.txt`. And since MyAgent has no working-directory notion (the target repo is *data in the conversation*, not process state), the `cd repo && claude` equivalent is a **pinned-repo variant**: a copy of `Coding_Agent` with a TARGET REPO block naming the absolute repo root ("don't ask where, only what; absolute paths under this root; read its CLAUDE.md before asking for the task") — first instance `Coding_Agent_CodingAgent`, launched as `python MyAgent.py -l "Coding_Agent_CodingAgent"`. A **here-string guardrail** (2026-07-23) closes a footgun surfaced when a grok-4.5 parent verified a change with a multi-line `python -c @"…"@` PowerShell here-string: the command ran fine, but here-string quoting is fragile — a stdin-fed variant silently produces *no* output rather than erroring — so `Coding_Agent`/`Coding_Agent_CodingAgent` now steer any multi-line check to the `write_file` a throwaway `_verify_tmp.py` → run → delete pattern, while `Test_Verifier` (which has `write_file` blocked) is told to run existing files/commands only and never synthesize inline programs.
- **Server-side (replaces local search):** OpenAI gets `web_search_preview` + `code_interpreter`; Anthropic gets `web_search` + `code_execution` betas with Files-API downloads; xAI gets `web_search` + `x_search` + `code_interpreter` (mixing with custom function tools verified live; flat $0.005 per invocation, folded into the exact API-reported cost). Generated charts render inline (max 600 px) and save to `saved_chats/`. Google/Moonshot/Ollama keep local DuckDuckGo (Gemini's API can't mix built-in tools with custom function declarations; Moonshot offers no server-side tools).
  Server-side tools are **always on** for the providers that support them — there is no checkbox. They are *declared* on every call but **billed only when the model actually invokes one** (a run that never searches pays nothing extra), so the effective switch is the instruction text itself. The local `web_search`/`fetch_webpage` pair is stripped whenever a server-side search exists, so the model is never offered two search implementations at once — which search runs is decided by provider, not model whim. The one deliberate overlap is `run_command` (acts on *your* machine) vs the server code sandbox (compute-only, can't touch your machine); ticking **Desktop** removes the sandbox on OpenAI and xAI to protect click accuracy.
- **Desktop (checkbox):** 13 pyautogui tools + the **Gemini-only `find_element`**, which uses Gemini's trained pointing API (with Google's exact documented prompt phrasing — the capability only fires on that wording) to turn "the blue Save button" into pixel coordinates.
- **Browser (checkbox):** 12 Playwright/CDP tools. On macOS the auto-launch search order is Brave → Chrome → Edge, with a persistent debug profile so logins survive runs. `browser_download` is the one to use for in-page file downloads (CSV/statement exports): Playwright's CDP attach makes the browser rename every download to a random GUID in a temp dir (so a plain click shows a "failed" download with a strange name) — the tool arms `expect_download()` around the click and `save_as()`es the file to a real path.
- **Meta (checkbox):** `manage_instructions`, `manage_skills`, `run_instruction` — the agent can manage its own instruction/skill libraries — `manage_skills` covers each skill's what+when **description** too (the on-demand trigger signal: an update may carry only a description, an empty string clears it, >1024 chars warns but saves — so the agent can audit and backfill its own skill metadata; the shared library's 12 skills were fully described 2026-08-06). `manage_instructions` doubles as the agent's **self-inspection channel** (mapped out 2026-08-10): `read` returns any saved instruction's full environment — exact model id, thinking/temperature params, tool toggles, blocked tools — *including the instruction currently running* (there is no name channel, so the agent identifies itself by matching `list`'s text preview against its own task prompt), and `create` snapshots the LIVE session's model params, so a create→read→delete probe reveals even an ad-hoc run's live settings; writes are deliberately disk-only (they take effect on next load — no mid-run self-modification), and the shared library's `weather-report-generator` skill now uses exactly this for its report's AGENT INSTANCE INFORMATION section (*read* your parameters, never guess them — a Kimi run had confabulated "parameters not exposed to the agent" while holding the very tool that reads them). The third tool, `run_instruction`, **spawns other instructions** as headless processes (orchestrator pattern): fire-and-forget by default, or `wait=true` to block until the child finishes and receive its final report back as the tool result (true subagents), with optional `extra_text` appended to the child's instruction as per-run task context — one generic saved instruction, parameterized per spawn. Several `run_instruction` calls issued in the **same assistant turn run concurrently — waited ones included** (each blocks only its own executor thread; spawn prologue serialized by a module lock, instance-slot claiming O_EXCL-atomic so simultaneous children can't collide on state files), so a parent fans out independent subtasks and pays only the slowest child's wall clock, not the sum.
- **Mail (three checkboxes):** 16 Gmail + 16 IMAP/Proton + 16 Outlook tools — see the integration sections below.
- **Excel (checkbox):** 9 xlwings tools that drive the **running Excel application** (COM on Windows, AppleScript on macOS) — see the Excel section below.

**Desktop click accuracy** is a first-class concern: all providers receive plain pixel coordinates ("click what you see"), resolution caps match each API's real limit (Anthropic 1568 px / OpenAI 2048 px / Gemini 2048 px long edge), coordinates round rather than truncate, out-of-bounds clicks clamp (≤2 px) or refuse (>2 % of the dimension), per-display state is tracked separately for full vs region captures so chained region screenshots don't drift, an optional `grid=true` overlay draws a labelled 100-px coordinate grid for dense UIs, and a **Diag** checkbox logs the entire capture/click coordinate-mapping trail. OpenAI's `code_interpreter` is stripped whenever desktop tools are on — gpt-5.x otherwise inspects the image with PIL and "helpfully" pre-scales coordinates, producing double-scaled misclicks. A weak-combo warning flags provider/model choices with known-poor click precision at agent start.

### Agent Instructions

Saved task profiles in `agent_instructions.json` (in `<OneDrive>/MyAppShare/` — OneDrive, not git, syncs the library across machines; see the cross-machine sync note below). Each instruction stores: text, base64-embedded images, all tool toggles (Desktop/Browser/Excel/Meta/MCP/Gmail/IMAP/Outlook/Convo), provider + model + thinking/verbosity params, per-skill modes, and Safety bypass patterns — a complete self-contained environment per task. The editor uses a **draft/commit model** (SAVE writes to disk, Apply makes it live for the session only, [X] discards), and Apply survives restarts via a snapshot in `agent_state.json`. DELETE is the one editor button that mutates the shared store directly, so since 2026-09-02 it asks first (a warning dialog with **No** as the default) — the `manage_instructions` tool's delete action is deliberately unprompted, because an unattended run has nobody to answer a dialog. The Load Instruction dropdown sizes itself on every open — as many rows as fit between the combobox and the bottom edge of the instruction text area (recomputed live from window geometry and the popdown's actual font, so it tracks resizes and per-monitor DPI), so a tall editor shows more instructions while the list never covers the model/tool rows below. Skill-mode restores are deliberately session-only: the skills store (the `skills/` SKILL.md tree) remains the sticky global source of truth and is never silently overwritten by loading an instruction. That override is also *visible* now: applying an instruction whose snapshot omits a skill that's globally ON posts a ⚠ naming the forced-off skill (re-save the instruction with the skill set to include it) — re-posted at run start so even `-l` auto-launches, which clear the output window, show it.

**Cross-machine store sync** — the authored-content stores (`agent_instructions.json`, `system_prompts.json`, and the `skills/` tree) live in **`<OneDrive>/MyAppShare/`** — the suite-wide shared dir that also holds TodoList's `todos.json` — auto-located per platform (Windows env vars / macOS `~/Library/CloudStorage/OneDrive-*`), overridable with a `MYAGENT_DATA_DIR` env var, falling back to the repo root on machines without OneDrive (MyAgent's and SelfBot's title bars show "— synced" when the shared dir is in use). The dir was named `MyAgent` until 2026-07-19; a legacy-named dir is auto-adopted by an in-place rename (or, if the new dir already exists, its files are folded across individually). `myagent/datapaths.py` implements the plumbing (the stores and the per-machine cost log resolve through one shared use-the-share-else-repo-root fallback helper, so they can never land in different places): the first launch to find the shared slot empty seeds it from the repo-root copy; a machine joining later gets its leftover repo copy **key-level-unioned** into the shared store (shared entries keep their names; a genuinely different local entry survives as `name__<hostname>`), after which the local copy is renamed `*.migrated.bak` so later deletions can't resurrect. Writes are atomic (unique temp + `os.replace`), a shared file that exists but doesn't parse is never overwritten (half-synced cloud write — served as empty for the session, retried next launch), and OneDrive **conflict forks** (`<stem>-<Computer>.json`) are absorbed at each load by the same union and deleted. `Heartbeat.py` resolves the same path for its marker rewrites. This replaces git as the sync channel for these files — dropping a store file at the repo root is now simply an *import* (unioned in on next launch).

**The skills library is a per-skill file tree** (since 2026-08-07) — `<OneDrive>/MyAppShare/skills/<Name>/SKILL.md`, Anthropic-Agent-Skills-shaped: a small frontmatter block (`name` / `description` / `mode`) over the markdown content, so skills are editable in any editor and diff cleanly, and per-file storage aligns the data unit with OneDrive's sync unit (two machines editing *different* skills can no longer conflict at all). A legacy `skills.json` migrates into the tree on first load (existing tree entries win their names; a genuinely different JSON entry survives as `<name>__json`), then parks as `.migrated.bak`. Saves are per-file, atomic, **diff-aware** (unchanged skills are never rewritten — no OneDrive churn) and **write-only** — a stale in-memory dict can't delete a skill another machine just synced in; deletion is an explicit UI/tool action that removes the skill's folder (bundled resource files ride along with it). Per-file conflict forks (`SKILL-<Computer>.md`) are healed on load: an identical fork is deleted, a different one is preserved as a `<name>__<label>` sibling skill, an orphaned fork is promoted to the main file.

**Skill names are Agent-Skills kebab-case** (`westpac-login`, `process-payment-emails` — folder = name exactly, H1 body titles stay human-readable), **enforced on create**: the Skills Manager offers a one-click auto-conversion for a non-conforming new name (`Test_skill` → *"Create as 'test-skill' instead?"*), `manage_skills` rejects with the kebabized suggestion in the error, and existing legacy-named skills stay editable (grandfathered). The Skills Manager's DELETE button asks first (since 2026-09-02 — warning dialog, default **No**; it removes the whole folder from every synced machine with no undo), while the `manage_skills` tool's delete action stays unprompted for unattended runs. The tree layer is also battle-hardened against its OneDrive home (every defect below was found live on 2026-08-07): deletion clears the **ReadOnly attribute OneDrive stamps on stuck directories** (a read-only *directory* defeats `rmtree` — that, not the transient sync handle, is what made husk folders survive retries), retries briefly inline so the UI never freezes, then hands a still-blocked folder to a **background sweeper** (~2 min of retries), with a load-time sweep of aged *empty* SKILL.md-less folders as the cross-launch backstop; and the layer is **case-folding-aware** — on Windows/macOS `test-skill` resolves into an existing `Test-skill`, so writes never land in a differently-cased folder, and the scan heals case-mismatched or stranded `_N` folders and deletes identical-duplicate folders on load.

**Conversational mode** (Convo checkbox): for small open-weights models that won't follow "always call `user_prompt`" meta-rules, MyAgent enforces the chatbot loop itself — when the model ends a turn without asking, the app pops the prompt dialog directly and feeds the reply back in. Empty/`quit`/`exit`/`stop` ends cleanly.

### MCP Integration

A generic Model Context Protocol client (`myagent/mcp_mixin.py`) connects to stdio MCP servers (filesystem, GitHub, Slack, …) and pipes their tools through the same loop as native tools, on **all six providers**.

```bash
pip install mcp            # + pywin32 on Windows
cp mcp_servers.example.json mcp_servers.json   # then edit the placeholder path
```

`mcp_servers.json` (gitignored; same shape as Claude Desktop / Cursor):

```json
{
  "servers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/you/projects"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```

Highlights: `${NAME}` placeholders in `env` values resolve from your shell environment at spawn time (secrets never enter the JSON; substitution deliberately does **not** apply to `command`/`args`, so `ps` can't leak them); the reserved `${RANDOM_PORT}` yields a fresh OS-assigned port per occurrence so multiple MyAgent instances don't collide; tool names are namespaced `<server>__<tool>`; servers connect on a dedicated asyncio thread inside one long-lived `AsyncExitStack` (the architecture that survives anyio's cancel-scope rules — see [.claude/rules/CLAUDE_MYAGENT.md](.claude/rules/CLAUDE_MYAGENT.md) for the full war story, including the Windows `pythonw.exe` stderr/IOCP fix); cold-cache `npx -y` first runs get a generous 5-minute startup ceiling, warm launches connect in 1–3 s. Debug the stream with `python MyAgent.py 2> mcp.log`.

Mind the token budget: every connected server's catalog rides along on each API call (5–10K tokens for a fat server) — leave the MCP checkbox off for tasks that don't need it, especially on Ollama's capped context.

   ```json
   { "accounts": {
       "namor5772":      { "email": "namor5772@gmail.com" },
       "romangroblicki": { "email": "romangroblicki@gmail.com" } } }
   ```
5. First tool call per account opens the browser consent flow once; thereafter the token (`{account}_token.json`, chmod 600) refreshes silently.

Every tool takes an `account` parameter whose enum is patched at runtime from `accounts.json` — multi-account workflows are one parameter, not multiple processes. The OAuth scope is **`gmail.modify` only**: trash is recoverable, permanent delete is impossible *by scope*, even if a bug tried. Destructive tools (`gmail_send`, `gmail_reply`, `gmail_send_draft`, `gmail_trash`, `gmail_delete_label`) pop a confirmation dialog, individually bypassable per-instruction via the Safety dialog (each bypass logs a `⚠` audit line).

### Proton Mail / IMAP Integration

Sixteen `proton_*` tools mirroring the Gmail surface 1:1, implemented over **stdlib IMAP + SMTP**. Proton has no public REST API (E2E encryption — decryption is client-side), so the official path is [Proton Bridge](https://proton.me/mail/bridge), which exposes a localhost IMAP/SMTP pair per signed-in account with per-install app-passwords (MyAgent never sees your real Proton login). The mixin is IMAP-generic: the same tools drive **any** IMAP/SMTP account — a WebCentral/cPanel (dovecot) mailbox runs through the identical code path, which is why the editor checkbox is labelled **IMAP**.

Config at `~/.config/myagent-protonmail/accounts.json` — per account: `email`, `username`, `app_password` (Bridge-generated), `imap_host`/`imap_port`/`smtp_host`/`smtp_port`, optional `ca_cert_path` (Bridge's exported `cert.pem` for verified TLS; without it localhost traffic falls back to `CERT_NONE`, acceptable when the only MITM position is your own machine). `chmod 600` it. No OAuth dance — if Bridge is running, the tools work.

IMAP realities the tools absorb for you: UIDs are **per-folder** (tools take `folder` + `uid`; a Trash round-trip yields three UIDs for one logical message); `Labels/X` MOVEs are *additive* on Bridge (Proton labels are tags, not containers) while system folders are true moves; a label-removal eventual-consistency quirk is auto-retried transparently (`label_removal_retries` in the response); and search syntax is steered to explicit IMAP keys (`SUBJECT "..."`, `TEXT "..."`) because bare tokens work on Bridge but error on dovecot.

### Outlook / Microsoft 365 Integration

Sixteen `outlook_*` tools, again mirroring Gmail 1:1, via the **Microsoft Graph API** with **MSAL** OAuth — Microsoft killed Basic-Auth IMAP for personal outlook.com in late 2024, so Graph is the supported path. Mapping notes: Gmail labels → Outlook **categories** (managed by display name, not id); trash → a Graph *move* to `deleteditems` (which mints a new message id, like Proton's per-folder UIDs); Graph messages have a single body (`html` or `text`, no multipart); a draft *is* a message. Attachment cap is ~3 MB combined (Graph's single-request JSON limit).

Setup once: register a free Azure app (Personal accounts; platform *Mobile and desktop*, redirect `http://localhost`, "Allow public client flows" = Yes; delegated permissions `Mail.ReadWrite` + `Mail.Send` + `offline_access`), then:

```bash
pip install msal
mkdir -p ~/.config/myagent-msmail
# msal_app.json: { "client_id": "<app-id>", "authority": "https://login.microsoftonline.com/consumers" }
# accounts.json: { "accounts": { "outlook": { "email": "you@outlook.com" } } }
```

First use opens a browser sign-in; the token cache then refreshes silently — the same Azure client_id works on every machine (public client), so only the one-time consent is per-machine. Same destructive-op confirmation + per-instruction bypass pattern as Gmail/Proton; same soft-delete-only boundary.

### Excel Live-Workbook Integration

Nine `excel_*` tools (Excel checkbox) that drive the **running Excel application** via [xlwings](https://www.xlwings.org) — COM on Windows, AppleScript on macOS — rather than editing `.xlsx` files on disk: the agent attaches to the workbook you already have open, cells change live on screen, formulas actually recalculate, and existing VBA macros can run. That's the reason it's xlwings and not openpyxl — a file-level library stores formulas but can never evaluate them. `excel_open` attaches-or-launches and reports every open workbook (optional `password` for open-protected files — though attaching to a workbook the user opened themselves needs no password at all, keeping it out of the AI pipeline entirely); `excel_read` returns ranges as TSV labelled with the real row numbers and column letters; `excel_write` takes cells **exactly as you would type them into Excel** (`'42'` → number, `'2026-08-01'` → date, `'=SUM(B2:B9)'` → live formula — all-string cells also sidestep cross-provider JSON-schema quirks) and echoes back the recalculated result; plus `excel_format`, `excel_sheet`, `excel_find`, `excel_run_macro`, `excel_save`, `excel_close`.

Three battle scars from the first live run (2026-08-01) are baked in: `excel_close(quit_app=true)` quits Excel **only when no other workbooks remain open** — the agent may be attached to *your* Excel instance, and the first smoke test saved-and-closed the user's own open workbook; currency number formats change the COM **wire type** (`$#,##0.00` cells come back as `decimal.Decimal`, not float), so display and `excel_find` matching go through `numbers.Number`; and a just-quit instance lingers in the COM Running Object Table with a dead window handle, so attach probes liveness before trusting it. No COM handles are cached across calls (each run's tools execute on a fresh thread, and COM apartments don't cross threads) — every call re-attaches, which is also what makes attach-to-whatever-the-user-has-open the natural default. The attach helper is deliberately the single chokepoint all nine tools pass through: the per-thread COM init and the xlwings-missing check live once inside it (2026-08-03 cleanup — previously repeated at the top of every tool, with the friendly "pip install xlwings" hint reaching only `excel_open`). Verified two ways on Windows (2026-08-01): a direct-mixin smoke suite (create/write/recalculate, formula reads, formats including the currency-Decimal regression, sheets, find, save, quit-refusal with bystander workbooks, password open with wrong-password error path), and then a real MyAgent run — the model driving the tools through the full agentic loop — which built, formatted, and totalled a workbook first try. Setup: `pip install xlwings` (in `requirements.txt`) — Windows needs nothing else. macOS additionally needs Excel for Mac and a one-time Automation permission grant (System Settings → Privacy & Security → Automation).

**macOS live-verified 2026-08-01** on the M4 Mac Mini (Excel 16.111.2, xlwings 0.36.12 + appscript): all nine tools pass the same surface as Windows, and formulas survive a save→reopen round-trip as formulas rather than frozen values. The Mac run turned up three things the Windows one couldn't. **Excel must be activated** — unactivated, `save_workbook_as` fails `OSERROR -50` at every path, which looks like a path or password bug and isn't. Excel's sandbox **"Grant File Access" modal can stall a tool call for ~7 minutes** with no timeout on the first save into an unvisited folder; neither that dialog nor the activation prompt is clickable in a `--headless`/launchd run. And the sharp one: **a long-running Excel process can silently discard every cell write** while reads, formatting and sheet operations all keep working — no error raised, and Excel never even marks the document dirty. That is not an xlwings bug (raw AppleScript `value`/`value2`/`formula`/`formula r1c1` all fail identically), it survives neither launch method nor save order as an explanation, and **restarting Excel fixes it**. The trap is that the attach-time liveness probe reports such an instance perfectly healthy, so `excel_write` cheerfully announced *"Wrote 5x5 cells"* over a no-op. Every write is now verified: small ones against the read-back echo they already produced, larger ones via a bounded probe — closing the gap where writes over 200 cells had no verification at all. The check is deliberately conservative (it fires only when everything written reads back empty), so a formula legitimately returning `""` can't trip it.

**Unattended runs on macOS need two machine settings**, neither of which has a Windows equivalent — its Trust Center already trusts the location, which is why the same workbook "just opens" there. Both are `defaults` writes, deliberately *not* set from the mixin: an agent should not silently reconfigure your Office install.

```bash
# 1. Stop Excel's workbook gallery blocking the very first call
defaults write com.microsoft.office ShowDocStageOnLaunch -bool FALSE
# 2. Only if the agent must open macro-bearing .xlsm files
defaults write com.microsoft.office VisualBasicMacroExecutionState -string EnabledWithoutWarnings
```

The first is the one that matters, and it is the worst failure mode in this whole integration: the agent launches Excel with no document, so Excel shows its start screen — the template gallery — and that window blocks Excel's Apple Event queue **completely**. The open call never returns, even `activate` times out, and macOS Accessibility does not expose the window, so nothing can click it away. The only recovery is killing Excel. It hung a real agent run on its first `excel_open`; with the preference set, launching with no workbook returns in 0.5 s. Every other dialog below merely needs the right argument — this one is unrecoverable from inside the agent. The second is a genuine security trade rather than a recommended default: it spans Word and PowerPoint and makes *any* macro-bearing file run its macros silently (revert with `defaults delete`; the default is `DisabledWithWarnings`).

With both set, the whole unattended path was **verified end-to-end on 2026-08-03**: a one-shot launchd job (the same context a scheduled run gets) ran `MyAgent.py -l … --headless` cold — Excel not running — opened a real `.xlsm`, screenshotted it, described the live sheet contents, and exited cleanly with a `--result-file`, zero dialogs. The screen-capture half of that depends on the TCC identity of the *launching* process (see the scheduling gotchas below); the launchd identity is the bare Python interpreter, distinct from both the terminal and the Desktop-launcher applet. On the "Grant File Access" modal above: it is per-folder and **granting once is permanent** — clicking Select… for a folder ends the stall for every future save there, so pre-granting the scratch folder an instruction saves into (e.g. `~/Temp`) is worth doing before its first unattended run.

**Window position and size persist per workbook** (verified numerically 2026-08-03): Excel stores window geometry inside the file itself (`xl/workbook.xml` → `workbookView`), and a save → quit → cold-reopen round-trip restored every value exactly. So to pin a workbook's window, position it and save — every later open, agent or human, restores that spot, and the geometry travels with the file through OneDrive to Windows. Corollaries: a session that saves from a different position re-pins the file there (read-only agent runs never touch it), and a stale macOS Spaces record can still override the restore by parking the window on a display that no longer exists — the ghost-Spaces purge in the scheduling gotchas is the fix. One wart for scripts that *position* Excel windows via AppleScript: `set top of active window to N` and reading `top` back use different vertical origins (a QuickDraw bottom-left legacy — set 222, read 746 on a 1440-pt display; save/restore is internally consistent), so set, read back, and correct — never trust the set.

**Protected workbooks** can carry two independent locks, and it is worth knowing they are different things: `password` decrypts an open-protected file, while `write_res_password` claims write access on a **write-reserved** one — miss the second on a workbook that has one and Excel parks on a *"reserved by … enter password for write access, or open read only"* modal that nothing can answer headlessly. `excel_open` accepts both, plus `ignore_read_only_recommended` for the softer *"the author would like you to open this read-only"* prompt, which is a recommendation flag rather than a password. Most workbooks need only the first; check `write_reserved` before assuming otherwise.

**Read-only is the subtle one**, because it is silent and only bites at the first save — so `excel_open` probes for it and warns up front, and `excel_close` refuses to pretend it saved. The warning lists what to check (a sidecar `~$` lock file, a genuine write-reservation, disk writability, open-elsewhere or OneDrive checkout) rather than asserting a cause, because none was ever pinned down: one workbook opened read-only for an agent run and fully editable on three consecutive fresh-Excel runs minutes later — same password, file untouched — and neither a sidecar lock nor Excel session state reproduced it on demand. The remedy that did work is quitting Excel completely and retrying.

Two macOS-only defects were fixed in the same pass, both cases where code written against COM's *timing* of failure changed meaning under AppleScript. `excel_run_macro` reported success for a macro that doesn't exist — macOS returns `None` for a missing macro exactly as for one that ran and returned nothing, and Excel's dictionary offers no way to enumerate VBA members, so existence genuinely cannot be checked; it now says *dispatched* on macOS with an instruction to confirm the effect, while Windows keeps the confident wording COM earns it. And the friendly *"Sheet 'X' not found"* error never fired on macOS, because `book.sheets[name]` returns a lazy reference that only detonates later at use, leaking a raw `OSERROR -1728`; it now validates against the real sheet names, which also gives macOS the case-insensitive lookup Windows had for free.

### API Cost Tracking

Live cost accounting across Anthropic / OpenAI / Google / xAI / Moonshot: each streamed call's usage (including cache write/read tokens) is priced against the longest-prefix-matched tables in `myagent/constants.py` (documented in `MyAgent_Pricing.txt`) and shown as a running blue cost line.

**Prompt caching — the single biggest lever, and it was switched off (fixed 2026-07-31).** A cost audit found the same browser instruction costing **$2.15 on claude-sonnet-5 versus $0.30 on kimi-k3** — despite Sonnet 5 being the *cheaper* model per token ($2/$10 against Kimi's $3/$15). The entire gap was caching. Every provider here caches automatically except **Anthropic, whose caching is strictly opt-in** — and MyAgent had never sent a `cache_control` breakpoint, so every turn of an agentic loop re-sent the whole growing prefix (system prompt + full tool catalog + every prior screenshot and tool result) at the full miss rate, a cost that grows roughly quadratically with turn count. `_stream_anthropic_call` now places three breakpoints under Anthropic's ceiling of four: one static marker on the system prompt (which covers the tool array too, since the prefix is ordered tools → system → messages and a breakpoint caches everything before it) and two rolling markers on the newest turns, so turn N+1 reads turn N's prefix at 0.10× instead of re-paying 1.00×. History is never mutated — only breakpointed messages are shallow-copied, since stale markers would accumulate past the ceiling — and the wire copy is rebuilt inside the retry loop so the context-overflow trim still reaches the retry. Same treatment ported to SelfBot, where a duo self-chat grows without bound by construction and re-sends all of it every turn. Result on the same instruction: **$2.15 → $0.39**, with a fresh Kimi control run at $0.34 confirming the two models are now cost-equivalent within run-to-run noise (Kimi itself varies ±15%).

**Cached input is reported for OpenAI and Gemini too (2026-07-31).** Both cache automatically — OpenAI above ~1024 tokens, Gemini's implicit caching above a 4,096-token floor on the Gemini 3 tiers — so the discount was always hitting the bill; MyAgent just never reported it, overstating every OpenAI/Google line. The tables now carry a cached-input rate (1/10 of input on the GPT-5 and Gemini 3 families, **1/4 on GPT-4.1**; the OpenAI `-pro` tiers have no cached tier at all, so the key is *omitted* rather than set to zero — a zero would silently price cached tokens free). The load-bearing subtlety: unlike Anthropic's separate buckets, OpenAI's `cached_tokens` and Gemini's `cached_content_token_count` are **subsets** of their input totals, and the accumulator prices input and cache-read additively — so the normalizers subtract first, or every cached token would be double-charged. The same audit caught two accuracy bugs running the *other* way: Gemini's `thoughts_token_count` is its own bucket rather than part of `candidates_token_count` and bills at the output rate, so thinking-enabled runs had been *under*-reported; and eight OpenAI base rates were wrong (six sat at exactly half the Standard rate — Batch-tier numbers), with `gemini-3.6-flash` missing entirely and falling through to the bare `gemini-3` entry at a third of its real price. Live end-to-end: an OpenAI cache hit prices −89.8% against the old number and a miss ±0.0%; a Gemini hit −44.4%, a Gemini *miss* +6.0% — the thinking correction making the log more expensive and more accurate.

**2026-08-25 model & pricing audit.** Every provider's live catalog (`models.list()` with the real keys) and pricing page were re-checked against `constants.py`, and the parameter matrices were verified with a zero-cost probe — sending an *invalid* `reasoning.effort` makes each API enumerate what it accepts in the validation error, which is never billed. Findings: **Claude Sonnet 5's $2/$10 launch price is now permanent** — Anthropic's pricing page states the scheduled September 1 increase to $3/$15 "will not occur", so the table entry never flips; **`gpt-5.6-sol` was mispriced at gpt-5.5's $5/$30 and bills $4/$20** (cached $0.40) — corrected, and the bare `gpt-5.6` family row was dropped (no such id exists, so an unknown future 5.6 tier is unpriced rather than mispriced); all three GPT-5.6 tiers accept **`reasoning.effort: "max"`** (5.5/5.4 reject it), so the Reasoning combobox gains **Max** on 5.6+ (`_has_reasoning_max`, version-gated at minor ≥ 6; a saved Max/Xhigh above a model's ceiling now steps down to its top rung instead of to None); **`gemini-3.7-flash`** (the new stable Flash tier) was unpriced — it fell through to the bare `gemini-3` row at $0.50/$3.00 — and Google is running a launch promo on **both 3.6 and 3.7 Flash: $0.75/$3.75 (cached $0.075) through 2026-12-31, $1.50/$7.50 from 2027-01-01**, so the 3.6 row (entered at the sticker) had been *over*stating by 2x. Promo entries are now a **`DatedPrice`** (promo tuple + sticker tuple + inclusive end date) resolved per lookup by `_get_pricing(…, today=None)`, so the tracker flips itself on New Year's Day — a MyAgent left running across the boundary prices each call at the rate it is actually billed at, and the tests pin both sides of the boundary. The floating Gemini aliases were re-pointed (`gemini-flash-latest` → 3.7-flash, `gemini-flash-lite-latest` → 3.5-flash-lite, verified via `response.model_version`) and `gemini-3.7-flash` is the Google default. **kimi-k2.5** (full platform sunset 2026-08-31, never served to this account) is unpriced under the retiring-models policy. Verified unchanged: every Anthropic row (Opus 4.1 has now left `models.list()`), the xAI catalog, per-model prices and alias targets (`grok-latest` → grok-4.6, `grok-build-latest` → grok-4.5), the Kimi k3 / k2.7-code / k2.6 rates, and the Anthropic effort ladders straight from the Models API capability tree (Opus 5 / Sonnet 5 / Fable 5 / Opus 4.8 / 4.7: low…max including xhigh; Opus 4.6 / Sonnet 4.6: no xhigh; the 4.5 generation: budget thinking only). Haiku 4.5 reports `code_execution: unsupported` in that tree but accepts the app's server-tool set without error (probed), so no special-casing was needed. Instructions still pinned to ids that are gone or retiring — `GeneralChatAgent-gemini-3-pro-preview` (no longer served; the loader drifts it to the Google default with a warning), `GeneralChatAgent-gemini-2.5-pro` (sunset ≥ 2026-10-16), `Parallel_Test_4` on `gpt-5` and `Weather_Agent3_OpenAI` on `gpt-5-mini` (retire 2026-12-11) — were left alone for the user to re-point.

**2026-09-02 — Claude Fable 5.1 (`claude-fable-5-1`).** Anthropic's 2026-08-28 successor to Fable 5 in the same tier: 1M context, 128K output, effort low…max, adaptive-only thinking — all confirmed from the live Models API capability tree — and the same $10/$50 per MTok, except **cache reads at $0.25/MTok** (0.025× input: a quarter of Fable 5's rate and half of Opus 5's), which is why it needed its own `ANTHROPIC_PRICING` row — the longest-prefix matcher would otherwise have billed its cache reads at Fable 5's $1.00, 4× too high. The picker / thinking / temperature wiring needed nothing: `ALWAYS_ON_THINKING_PREFIXES` is prefix-matched, so `claude-fable-5-1` inherited the no-*Off* combobox, the hidden temperature and the Xhigh/Max ladder on arrival. What did need work were 5.1's API-level changes. (1) **Preserved thinking** — a 5.1 thinking block's signature is bound to the conversation prefix that produced it, so editing earlier history invalidates every later block: a 400 on accounts created on/after 2026-08-31, and on every account for future models. MyAgent's context-overflow trim *is* such an edit (keep-tail compaction, mid tool round), so every Fable/Mythos request now sends `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` under the `thinking-binding-controls-2026-08-01` beta: the API drops the stale blocks unbilled and proceeds, reporting each in the response's `input_transformations`, which MyAgent prints as an Activity line. Live-verified: a real thinking block replayed after a prefix edit came back HTTP 200 with `reason=prefix_binding_mismatch` and a lower `input_tokens`. A no-beta floor backs it — a 400 naming a thinking-block `signature` strips every thinking block from history (`strip_thinking_blocks`) and retries once. (2) **Forced tool choice** (`tool_choice: any` / `tool`) now 400s — MyAgent never sends it. (3) Thinking blocks are readable only by the model that produced them — MyAgent never switches model mid-run, and other models drop such blocks silently and unbilled. **Refusals** — the Fable classifiers can decline a request (HTTP 200, `stop_reason="refusal"`, possibly before any output), which ends an unattended run; Fable/Mythos requests now opt into **server-side fallbacks** (`fallbacks: "default"` under `server-side-fallback-2026-07-01`), which re-run a declined request on an Opus-tier model *inside the same call*. The serving model comes back in `message.model` and bills at *its* rates, so `stream_worker` prices each call by that id (a fallback-served call shows an Opus cost and a ⚠ line naming the server), and `strip_pre_fallback_blocks` applies the API's echo rule to a mid-output switch (only text and paired server-tool blocks from the declined partial go back; the declined model's `tool_use` blocks are neither echoed nor executed). Both surfaces are betas: a 400 naming either makes the session learn it off and retry without it. Two SDK facts shaped the code — the pinned `anthropic` 0.84.0 doesn't type `stop_details`, `fallbacks`, `block_binding` or `input_transformations`: the refusal category is captured off the `message_delta` event (the stream snapshot never copies it), `fallbacks` travels via `extra_body`, the nested `block_binding` key passes through the SDK's TypedDict transform untouched, and an unknown `fallback` content block parses into a text-block shell with `.type == "fallback"` (so the tool loop doesn't trip on it, but it can't be re-serialized — hence dropped from the echo). Harness helpers characterized in `tests/test_fable51_harness.py`; the model rows in `tests/test_anthropic_detect.py` / `tests/test_pricing.py`. SelfBot got the same surface the same day as in-file copies (its convention), plus the refusal handling it never had — a pre-output refusal used to leave an empty assistant turn that 400ed the next request; verified through its real `stream_worker` in-process.

**xAI is exact, not estimated**: the API reports the authoritative billed cost per call (`usage.cost_in_usd_ticks`, 1 tick = $10⁻¹⁰), which already includes its cached-input discount ($0.20/M on most families, $0.30/M on grok-4.5, $0.50/M on grok-4.6 — xAI caches aggressively) and the $0.005 server-tool invocation fees; MyAgent uses that figure directly and falls back to the table only if the field is absent (verified live: tracker matched the API to ten decimals). **Moonshot is exact from the other direction**: usage reports how many input tokens were cache hits and the tracker prices them at the per-model cache-hit rate (~⅙ of the miss rate) — which matters because Kimi's mandatory `reasoning_content` round-trip re-bills prior reasoning as input on every call, mostly at that discounted rate. When a run ends — GUI or headless, success or failure — one semicolon-delimited line `{timestamp};{provider};{model};{cost};{params};{secs};{instruction};{calls}` is appended to this machine's cost log (the `params` field — added 2026-08-10 — is the same compact parameter summary the title bar shows, comma-joined: e.g. `mode=Adaptive`, `reasoning=Medium, temp=1`, or `thinking=16K`, so the log records the thinking/temperature settings each run used; the `secs` field — added 2026-08-12 — is the run's wall-clock duration in whole seconds, `time.monotonic()`-measured across the whole agentic loop minus time the run sat waiting on user input (since 2026-08-13 the `user_prompt` dialog and every confirmation dialog suspend the clock, so TIME(sec) measures the agent working, not the user's response latency), surfacing as a TIME(sec) column right of COST(USD) in both viewers; the `instruction` field — added 2026-08-16 — is the name of the saved Agent Instruction the run was launched from, snapshotted at run start (blank for an ad-hoc run; a `;` in a name is written as `,` so it can never split the line), surfacing as the rightmost INSTRUCTION column (after PARAMETERS) plus a **By instruction** spend rollup in the viewers' SUMMARY (named runs only; since 2026-09-02 every rollup is also repeated for the current month under a THIS MONTH heading); the `calls` field — added 2026-08-16 — is the run's API-call count, i.e. the `Call #N` counter the output window shows, one per round-trip of the agentic loop — every call after the first exists because the previous one ended in `tool_use`, so it is effectively the run's tool-round count — recorded on the error path too (a run that dies on Call #3 logs `3`), surfacing as a CALLS column right of TIME(sec); pre-existing 4-/5-/6-field lines remain valid and show blank PARAMETERS/TIME/INSTRUCTION/CALLS columns, and SelfBot's lines carry an empty secs with its prompt name and session call total in the same 7th/8th positions) — since 2026-08-03 that is `APICostLog_<machine>.txt` in `<OneDrive>/MyAppShare` (each machine appends only to its OWN file, so syncs never conflict-fork, yet OneDrive mirrors every machine's log everywhere and the Cost Log viewers total ALL of them — the Mac's spend is finally visible from the PC and vice versa; repo-root `APICostLog.txt` remains the no-OneDrive fallback, both gitignored, and a legacy repo-root log is folded into the shared file at first launch via `datapaths.resolve_costlog()`). Because the per-machine files are read **cross-platform**, the lines are written LF-only on every OS (2026-08-03: all three write sites — MyAgent's `_log_api_cost`, SelfBot's, and the shared rotation-marker writer — open with `newline="\n"`; Python's default text mode on Windows wrote CRLF, which rendered as a `^M` after every Windows row in the macOS viewer and skewed its column alignment). The macOS viewer also strips a stray CR at its merge chokepoint, covering history written before the fix and any machine still on the old writer; the Windows viewer needs no equivalent since `Get-Content` strips both endings. Ollama runs are free but still logged (since 2026-08-12) as `$0.0000` lines whenever at least one call completed — local activity is visible in the viewers (with its thinking/temp params) without inflating any spend total; the zero-cost skip still applies to a paid provider's unmatched pricing prefix and to a STOP before the first result, where a fabricated `$0.0000` would claim "free" when the truth is "unknown". Like `heartbeat.log`, the cost log self-rotates: past ~100 KB the writer renames it to an `.old` sibling (one archive slot) and restarts it with a marker line — one shared helper (`myagent/helpers.py: rotate_log_if_needed`) serves every runtime-log writer (MyAgent, SelfBot, Heartbeat, UnreadSummary), and the Cost Log viewers skip the semicolon-free marker in their spend summaries. Rotation is checked only at the moment of an append — never on a timer or at launch, so an idle machine's file never churns (and OneDrive never re-uploads it idly); with cost lines at ~5 KB/month the ~100 KB cap is over a year away. Note the viewers aggregate the LIVE per-machine files only: a rotated-out `.old` archive stays synced in the share for manual reading but drops out of the summary totals, so once a machine rotates (~2,000 logged runs) the grand total stops being lifetime spend — raise `APICOST_LOG_MAX_BYTES` in `myagent/constants.py` if lifetime totals matter more than the cap.

**Cost log line format (reference).** One `;`-delimited line per MyAgent run (SelfBot: one per process, written on close), appended to `<OneDrive>/MyAppShare/APICostLog_<machine>.txt`. Fields are only ever *appended*, so older lines with fewer fields stay valid and simply show blank columns in the viewers:

| # | Field | Since | Meaning |
|---|-------|-------|---------|

### Other niceties

- **Parallel tool execution** — parallel-safe tools (`web_search`, `fetch_webpage`, `csv_search`, `get_skill`, `read_document`, `read_file`, `glob_files`, `grep_files`) run concurrently; results are reinserted in API order.
- **LaTeX → Unicode** — assistant text is post-processed (`\frac{a}{b}` → `a/b`, Greek letters, arrows, braced super/subscripts) without touching tool output.
- **Safety dialog** — every shell `COMMAND_CONFIRM` regex and every destructive mail tool is listed with a checkbox; unchecking bypasses that confirmation *for the current instruction only* (persisted per-instruction, with `⚠` audit lines at runtime). Essential for headless scheduled runs, which would otherwise hang forever on a dialog nobody can click. Patterns are stored as strings, so a cross-machine instruction can carry a **union** of Windows and macOS bypasses — each OS matches only its own `COMMAND_CONFIRM` list and the foreign patterns ride along inert (the dialog's per-checkbox toggles never rebuild the list, so visiting Safety on one OS can't strip the other's). The button label counts the two kinds separately, e.g. `Safety (2 bypassed, 4 other-OS)`.
- **Hard tool blocklist** — per-instruction `blocked_tools` names are stripped from the tools offered to the model AND refused at dispatch if called anyway — the deterministic complement to confirm-bypass for unattended runs, where a prompt directive is the only other guard and model compliance is probabilistic. For tools an instruction NEVER needs (a name-level block can't scope a tool the task legitimately uses sometimes — see CLAUDE_MYAGENT.md for the lesson).
- **Wrong-OS save-path guard** — all three mail `*_get_attachment` tools pass the model-supplied `save_to` through `normalize_save_path` (`myagent/helpers.py`): `~` expands, and on macOS a hallucinated Windows drive-letter path is redirected to `~/Temp/<filename>` with a note in the tool result so the model learns the real location. Added after a scheduled grok run saved an invoice to `C:\Users\...\Temp\` on the Mac, materializing a literal `C:/` directory tree inside the repo — models default to the OS they saw most in training, and Windows silently absorbs the same mistake.
- **State persistence** — `agent_state.json` (one per instance: `agent_state_N.json` for instance 2+) keeps provider/model/thinking/display toggles and the geometry of every window — the main window, including whether it was maximized, and all five dialogs — saved per monitor layout, so docked/undocked and multi-display arrangements each restore their own positions; a layout with nothing saved yet borrows the most recent one whose position is still on-screen, and off-screen or tiny windows fall back to sensible defaults (dialogs centre on their parent). Fixed 2026-08-29 for multi-monitor Windows: Tk reports a maximized window as its zoomed *size* at its normal *position*, which the restore used to reproduce as a giant un-maximized window straddling both monitors — the reason a MyAgent left maximized on the second monitor kept coming back on the primary. The same day added a defense against **external window managers** (PowerToys FancyZones' "open on active monitor" / "move to last zone", DisplayFusion, …): for ~1.5 s after launch the main window reclaims its restored monitor if such a tool drifts it cross-monitor right after it maps (why the dialogs, which already re-assert on show, were unaffected) — while any deliberate move you make is never fought. Prefer FancyZones to manage MyAgent? Add `pythonw.exe` to its excluded apps.
- **Retry & timeouts** — same 429/529 exponential backoff as SelfBot, plus a 180-s first-content timeout with elapsed-time ticker, OpenAI timeout retries, reactive caches for models that reject `temperature` or specific server-side tools.
- **Context-overflow compaction (Anthropic)** — a 400 `prompt is too long` mid-task no longer ends the run: the oldest conversation rounds are dropped in place (cutting only at real user-turn boundaries so `tool_use`/`tool_result` pairs are never orphaned, always keeping the last two rounds) and the call retries — SelfBot's sliding-window recovery, ported to `myagent/helpers.py`. Only when even the recent context alone overflows does the run end, with an actionable switch-to-a-1M-model message.

## Zero-token automation (UnreadSummary.py & Heartbeat.py)

Two production scripts that replaced AI-run agent instructions with deterministic Python, after the realisation that *polling and list-building need no judgment* — the LLM spend belongs in the work, not the trigger.

**UnreadSummary.py** (~940 lines) — the daily unread-mail digest. One pass scans **every configured account** (Gmail, Proton Bridge / IMAP, Outlook) for unread mail in Inbox and Spam/Junk, builds one continuously-numbered COMPREHENSIVE LIST (account, from, subject, date, first ~45 words of cleaned body), matches known bill/receipt senders against the rules in **`SpecifyingList.csv`** — which lives in the OneDrive folder `MyImportant/DeathFinances` shared by all three machines (found via `%OneDrive%`/`%OneDriveConsumer%`, `~/OneDrive`, or macOS `~/Library/CloudStorage/OneDrive-*`; repo-root fallback if no OneDrive copy exists, and the file is gitignored so the OneDrive copy is the single source of truth) — (semicolon-delimited, all fields quoted; columns `Type`, `Index`, `To`, `From`, `From email`, `Subject` — a *prefix* match — and `Determine`; `Type` and `Index` are display-only user references echoed as one `Type=…, Index=…` line under the entry's bare `SPECIFYING LIST EMAIL` marker, `Determine` a display-only reference note echoed under the entry; the `From email` column records each sender's actual address for reference and is not read by the parser, which matches by column name), saves matched PDF attachments idempotently to the `Attachments` subfolder beside the CSV (`MyImportant/DeathFinances/Attachments` — synced by OneDrive, so the saved bills appear on every machine; was the run machine's local `~/Downloads` until 2026-08-05), marks matches read, and emails the digest from the Outlook account. Replaced a ~$0.57/day Haiku instruction.

The AI version's "building the list is STRICTLY READ-ONLY" prompt guard holds here **by construction**: listing uses only read-only primitives (IMAP `EXAMINE` + `BODY.PEEK`, Gmail `messages.get`, Graph `GET`), and every mutation sits behind a flag (`SAVE_MATCH_PDFS` / `MARK_MATCHES_READ` on, `TRASH_MATCHES` off by default). `python UnreadSummary.py --dry-run` prints the would-be email with zero mutations and no send. Auth is silent-only — a dead token becomes an `ERROR:` line in the digest, repaired by running MyAgent once interactively. Logs: one line per pass to `~/Library/Logs/myagent/unread_summary.log` (repo-root fallback on Windows), preceded by one `ACCOUNT ERROR <account>: <reason>` line per failed account (since 2026-09-03 — e.g. Proton Bridge not running shows as a `ConnectionRefusedError` on 127.0.0.1:1143, so the cause is readable from the log without opening the emailed digest), self-rotating past ~100 KB to a one-slot `unread_summary.log.old` archive via the shared `rotate_log_if_needed`.

**Heartbeat.py** (~320 lines) — on-demand agent dispatch from anywhere you can send an email. launchd (Mac mini, short `StartInterval`) and Task Scheduler (Windows — `MyAgent_Heartbeat_8min` every 8 min on the desktop, `MyAgent_Heartbeat_5min` on the laptop) both run it against the **same** Gmail account; each pass checks for an **unread** message with that machine's exact subject — **`APD`** (the Windows desktop, DESKTOP-NAMOR), **`APL`** (any other Windows box, i.e. the laptop) or **`APM`** (macOS), derived from `platform.system()` plus hostname so the same file serves all three. The per-machine subject routes each trigger to exactly one executor — no tick-timing race, no machine-specific instruction landing on the wrong box:

- body line 1 → the name of a saved instruction; lines 3+ → the new prompt core
- the instruction's text between its **two** `*****` marker lines is rewritten (header and footer preserved; atomic temp-file replace beside the store — it edits the same OneDrive-shared `agent_instructions.json` the spawned MyAgent reads, resolved via `myagent/datapaths.py`; MyAgent-identical JSON formatting); fewer than two markers poison-pills the trigger instead of mangling the instruction
- `python MyAgent.py -l "<name>" --headless` is spawned detached, the email is marked read

Replaced an AI polling instruction that cost ~$14/day to decide, every 10 minutes, that there was nothing to do. Malformed triggers are poison-pilled (marked read + logged) rather than retried forever; one trigger drains per pass; auth never goes interactive; each pass logs one line to `heartbeat.log`, making timestamp gaps a liveness record. The log is self-rotating: a pass that finds it over ~100 KB (`LOG_MAX_BYTES`, roughly 2,000 lines) renames it to `heartbeat.log.old` — one archive slot, replaced each rotation — and restarts it with a marker line, so the tick log never grows unbounded (the mechanics are the shared `rotate_log_if_needed` in `myagent/helpers.py`, the same one-slot rotation that caps `APICostLog.txt`). A **watchdog** guards each spawn: if the previous run is under 15 minutes old the trigger defers to the next tick; anything older is killed and replaced — which also reaps runs parked on a forgotten dialog. On that note, **save trigger-target instructions with Convo off** (plus the confirm-bypasses they need): headless hides only the main window, dialogs deliberately stay visible, so a Convo-mode instruction finishes its work and then sits on a `user_prompt` dialog until the watchdog clears it. Windows port included (Task Scheduler + CIM process discovery) — note that spawned agents inherit the **scheduler's** environment, not your shell rc: on macOS the API keys must be embedded in the plist's `EnvironmentVariables` (chmod 600), on Windows `setx`-style user env vars work. That embedding must be maintained: **when a new provider is added, its key has to be added to every plist / scheduled task that embeds keys**, or instructions saved for that provider silently drift to whatever provider the child *can* reach — MyAgent warns (and re-posts the warning at run start so an `-l` launch's screen-clear can't erase it) and falls back to the drifted provider's curated default model rather than an arbitrary catalog entry, but the run still executes on the wrong model until the key is embedded.

## Scheduling background runs (launchd / Task Scheduler)

Any saved instruction can run unattended: macOS via a LaunchAgent at `~/Library/LaunchAgents/com.myagent.<slug>.plist` firing `python MyAgent.py -l "<Instruction>" --headless` on a `StartCalendarInterval`; Windows via Task Scheduler + `pythonw.exe`. Add `--result-file <path>` and the run writes a JSON outcome summary (`{status, error, final_text}`) when its loop ends — the same channel `run_instruction(wait=true)` uses, handy for any script that needs the run's answer rather than just its exit. The input half is `--extra-file <path>`: the file's text is appended to the instruction as an ADDITIONAL TASK CONTEXT block for that run only, so one saved instruction can be parameterized per scheduled run. A "Schedule Manager" pattern also exists: a conversational instruction with just `run_command` + `user_prompt` that lists, edits, lints (`plutil -lint`), loads and verifies the `com.myagent.*` jobs from plain-English requests — run it in the GUI, never headless.

Inspect from the terminal:

```bash
launchctl list | grep myagent                          # loaded jobs: PID, last exit code
launchctl list com.myagent.<slug>                      # what it runs (NOT the schedule)
plutil -p ~/Library/LaunchAgents/com.myagent.<slug>.plist   # the schedule lives here

# Find every time-scheduled job on the machine
for d in ~/Library/LaunchAgents /Library/LaunchAgents /Library/LaunchDaemons; do
  for f in "$d"/*.plist; do [ -e "$f" ] || continue
    plutil -p "$f" 2>/dev/null | grep -qE '"StartCalendarInterval"|"StartInterval"' \
      && { echo "── $f"; plutil -p "$f" | grep -E '"(Label|Hour|Minute|Weekday|Day)"|[0-9]+ => "'; }
  done
done
```

Hard-won gotchas:

- **`launchctl` ≠ the schedule** — the *when* lives only in the plist.
- **Missed runs fire once on wake**, not as catch-up replays (a 07:00 job firing at 11:17 after the lid opens is expected).
- **Never log to `/tmp`** (purged ~3-daily); use absolute paths under `~/Library/Logs/` — launchd does **not** expand `~` in plist strings.
- **Headless + destructive tools needs confirm-bypass** in the instruction's Safety list, or the run hangs forever on an invisible dialog. Same for the **Convo checkbox — save the scheduled variant with it off**: headless hides only the main window, so a Convo-mode instruction finishes its work and then parks on a floating reply dialog, never auto-closing and never writing its `--result-file`.
- **TCC permissions follow the launch chain, not the script** (verified 2026-08-03): the same venv python presents three different identities depending on who spawned it — the `My Agent.app` applet, the terminal, or (under launchd) the bare Python interpreter. Grant Screen Recording / Automation to the identity that will actually run; "it worked when I ran it" proves nothing about the scheduled version. A caveat for the launchd identity: it's the Homebrew Python binary, so a major Python upgrade re-orphans those grants.
- **Sourcing dotfiles beats embedding keys**: a plist that runs `/bin/zsh -c 'source ~/.zshenv 2>/dev/null; source ~/.zshrc 2>/dev/null; exec <venv-python> MyAgent.py -l "<Instruction>" --headless …'` picks up **every** provider's API key automatically — no per-provider plist maintenance, no silent model drift when a new provider's key is missing (the trap Heartbeat's embedded-keys plist fell into). Verified end-to-end 2026-08-03: a one-shot job in this shape ran an Excel screenshot instruction unattended with zero dialogs and a clean `--result-file`.
- **Ghost displays strand windows off-screen**: unplugging a monitor/TV leaves its Spaces record behind, and an app can restore its window onto that dead space — invisible on the real screen, hung automation. Purge with `defaults delete com.apple.spaces && killall Dock` (safe: the Dock lazily regenerates it from live displays).
- **Three layers prove a run worked:** `LastExitStatus`, the timestamped transcript in `saved_chats/`, and the real-world side effect. Exit 0 alone proves nothing about delivery.

## TodoList.py — Todo Manager

A single-file tkinter todo app (~660 lines): tasks have **priority** (High/Medium/Low), **category** (default set + any new name you type becomes a saved category), optional **due date** (DD/MM/YYYY validated), creation date, and a done flag. The list view highlights High-priority tasks in red, greys out completed ones, and gives **overdue** tasks a red background; click any column heading to sort (priority order is semantic, dates parse properly), filter by status/priority/category, and reorder with Move Up/Down. Double-click toggles done. `LaunchTodoList.bat` is the Windows one-click launcher; point the Desktop shortcut's icon at `desktop_launchers/icon_todolist.ico` (a clipboard with a googly-eyed pencil ticking the last urgent item — recipe in `desktop_launchers/README.md`). On macOS, `desktop_launchers/rebuild.sh` builds the matching `TodoList.app` (launch-or-focus, same icon) from `TodoList_launcher.applescript`.

**Cross-machine sync** — `todos.json` lives in **`<OneDrive>/MyAppShare/todos.json`** (the suite-wide shared dir, alongside MyAgent/SelfBot's stores; its own `<OneDrive>/TodoList/` home until 2026-07-19 — a leftover old folder is folded in automatically, merging as a conflict fork if both copies exist), auto-located per platform (Windows: the `OneDrive`/`OneDriveConsumer`/`OneDriveCommercial` env vars; macOS: `~/Library/CloudStorage/OneDrive-*`, legacy `~/OneDrive`), overridable with a `TODOLIST_DATA_DIR` env var, falling back to the script directory on machines without OneDrive (the title bar shows "— synced" when the shared file is in use). The first run to find the shared slot empty seeds it from the local file, so an existing list migrates rather than starting blank. Concurrent use is handled three ways: a 5-second mtime poll adopts another machine's synced write as soon as it lands (safe because every action saves immediately — there's no dirty state; paused while the edit dialog is open), saves that would overwrite a file that changed underneath ask **Overwrite / Reload** instead of silently clobbering, and writes are atomic (temp file + `os.replace`) so OneDrive never syncs a half-written JSON. `todo_state.json` (geometry/filters/sort) is deliberately per-machine and stays in the script directory; both files are gitignored — OneDrive, not git, is the sync channel.

**Native C++ port (macOS)** — `TodoList.mm` is a functionality-identical Objective-C++/Cocoa port; `./build_todolist_native.sh` compiles it to `TodoList.exe` (an arm64 Mach-O in the repo root, gitignored — the `.exe` name is just a name) with zero dependencies beyond the Xcode Command Line Tools. The data layer is Foundation-only C++ (same path resolution incl. the legacy-dir fold, same 5-second poll, conflict-fork absorption, Overwrite/Reload dialog, atomic writes) and goes through `NSJSONSerialization`, so **both implementations round-trip the same synced `todos.json`** — a Windows machine can keep running `TodoList.py` against the file a Mac writes natively, and they share the same per-machine `todo_state.json` schema (geometry/filters/sort restore across the pair). The build script first runs a headless characterization suite (`tests/test_todolist_native.mm`, ~90 checks: date-parsing strictness, Python-sort stability incl. `reverse=True` semantics, fork merging, legacy migration, state files) plus a Python↔native JSON interop round-trip. `TodoList (Native).app` (built by `rebuild.sh`) is its launch-or-focus Desktop launcher — it focuses a running instance of *either* implementation, since a native+Python pair would race the shared sync poll just like two Python instances.

**Native C++ port (Windows)** — `TodoList.cpp` is the Windows twin: the same functionality-identical port as a single C++/Win32 file (ListView with the app's colors via custom draw, Per-Monitor-V2 DPI with live rescale, modal edit dialog, the 5-second poll and Overwrite/Reload dialog), compiled by `.\build_todolist_native.ps1` to the same gitignored repo-root `TodoList.exe` name (an x64 PE here; the build needs any Visual Studio edition with the C++ workload, located via `vswhere` — no PATH setup). Win32 has no system JSON, so the port hand-rolls a reader/writer that reproduces `json.dump(data, f, indent=2)` **byte-for-byte** — ensure_ascii `\uXXXX` escapes, CRLF (Python's text mode on Windows), insertion-ordered keys, unknown-key preservation, raw number tokens passed through — making a native save indistinguishable from a Python save (the macOS port only guarantees data-level equality). The build script runs `tests/test_todolist_native.cpp` (~113 checks, the `.mm` suite ported plus a section locking the JSON format) and a Python↔native interop stage that asserts **byte-identical** rewrite before compiling. `desktop_launchers/TodoListNative_Win.ps1` is its launch-or-focus Desktop launcher (icon `icon_todolist_native.ico` from the committed C++-badged master): it focuses a running `TodoList.exe` *or* `TodoList.py` before launching, and shows a "build it first" dialog when the exe is missing. Two Tk behaviours are reproduced deliberately: the ListView's six columns **stretch proportionally** to fill the widget on every resize like the Tk Treeview (a user-dragged column becomes the new basis and the others refit, so the total always equals the widget width), and the status label is text-measured and right-anchored like Tk's `pack(side=RIGHT)` (a leftover-width STATIC word-wraps overflow into clipped garbage — the 2026-07-20 "gobbledygook" bug). And because Tk on Windows is DPI-unaware, the **shared `todo_state.json` geometry is kept in Tk's virtualized 96-dpi units**: the Per-Monitor-V2 exe converts at the boundary (×dpi/96 on restore, ÷ on save — verified drift-free at 150% scale), so both implementations restore the same visual window instead of the native one opening ⅔-size on a scaled display.


The script patches in the local repo path, renders each 1024-px icon master into an iconset with `sips`, compiles with `osacompile`, injects a stable `CFBundleIdentifier` (`com.roman.launcher.<slug>` — osacompile emits none), signs, and pastes the icon on via `NSWorkspace.setIconForFile` (which outranks macOS's stubborn IconServices cache). **Signing uses a stable self-signed certificate, and that's what makes permissions stick** (2026-08-03): macOS binds every TCC grant (Screen Recording, Automation, Accessibility, notifications) to the app's *designated code requirement*, and under the old ad-hoc signing that requirement was a hash of the exact binary — so every rebuild orphaned every granted consent. The failure is nasty because it's silent: the toggle in System Settings still shows ON, but `tccd` logs `Failed to match existing code requirement` and denies — which surfaced as MyAgent screenshots rendering other apps' windows as black while the Screen Recording toggle looked enabled (the orphaned grant also lists under the raw executable name "applet", since the old bundles had no identifier). Signing with the local **"Roman Launcher Signing"** cert makes the requirement `identifier + certificate leaf`, which survives rebuilds — grants are now one-time per machine per app. On a machine without the cert, `rebuild.sh` falls back to ad-hoc and the old re-ask-per-rebuild behaviour returns (cert recreation recipe in the launcher README). The built apps live in `~/Applications` with Finder **aliases** on the Desktop — an app *running from* a TCC-protected folder (Desktop/Documents/Downloads) triggers a consent prompt each time it becomes a "new" app, aliases don't. Completion feedback is deliberately a **dialog + chime, not a notification**: Notification Center permission was per-code-hash under ad-hoc signing, and `display dialog` needs no permission and isn't swallowed by Focus modes. The launch lines background via `cd X && (nohup … &)` — under `do shell script` a trailing `&` on a *compound* list does not detach, which used to keep the applet alive for the app's whole lifetime and swallow every second double-click (details in the launcher README). The MyAgent/SelfBot launch lines also source `~/.zshenv` **and** `~/.zshrc` first: GUI apps start with a bare environment, and `do shell script` runs `/bin/sh` — not zsh — so no dotfile is read automatically. The API keys are split across those two files, and when `OPENAI_API_KEY` moved to `~/.zshenv` the OpenAI provider silently vanished from GUI launches (terminal launches kept working) until the launchers sourced both.

**Windows** — `UnreadSummary_Win.ps1` is the AppleScript's twin: a desktop shortcut runs it via `powershell -WindowStyle Hidden`, the venv python executes the digest, and the feedback mirrors the Mac (chime + self-dismissing success dialog with the run's log line; blocking error dialog with the log tail on failure). The repo path is resolved from the script's own location, so any clone works unedited — only the `.lnk` shortcut is per-machine (icon: `icon_unread.ico`). A `-DryRun` switch passes `--dry-run` through for end-to-end plumbing tests. `CSVEditor_Win.ps1` is the matching twin of `CSVEditor_launcher.applescript`: a `powershell -WindowStyle Hidden` shortcut launches the editor with the venv **pythonw** (no console window) and focuses an already-open window instead of starting a second copy (icon `icon_csv.ico`, rendered from `icon_csv_master.png` — a googly-eyed comma perched on a spreadsheet, generated by `make_csv_icon.py`). `TodoListNative_Win.ps1` is the twin of `TodoListNative_launcher.applescript`: launch-or-focus across **both** TodoList implementations (a running `TodoList.exe` first, then a running `TodoList.py`) since either pair would race the shared 5-second sync poll, with a "build it first" dialog when the exe hasn't been compiled on this machine (icon `icon_todolist_native.ico`). `MyAgent_Win.ps1` and `SelfBot_Win.ps1` launch their apps with the venv **pythonw** and deliberately have **no** launch-or-focus — both apps are multi-instance by design: each MyAgent claims the lowest free lock number, and SelfBot's second press opens the self-chatting peer (SelfBot.py cascades the second window so the pair don't stack; `LaunchSelfBot.bat` does the auto-positioned side-by-side duo instead). Icons `icon_myagent.ico` / `icon_selfbot.ico`. `HeartbeatLog_Win.ps1` and `CostLog_Win.ps1` are the two **viewer** twins (icons `icon_heartbeat.ico` / `icon_costlog.ico`): unlike the launchers above they open a *visible* console, paging the repo-root `heartbeat.log` (meaningful events first, idle "nothing found" ticks filtered) or the cost log as a spend summary aggregated across every machine's `APICostLog_<machine>.txt` in the OneDrive share, plus any unmigrated repo-root file (grand total, today, this month, by machine, by provider, by model, by instruction — each rollup repeated for the current month only under a THIS MONTH heading since 2026-09-02 — then every run most-recent-first with its individual cost, a TIME(sec) column — the run's wall-clock duration, user-input wait time excluded since 2026-08-13, blank on pre-2026-08-12 and SelfBot lines — a CALLS column (2026-08-16: the run's `Call #N` API round-trip count, SelfBot's session total), a PARAMETERS column — the run's thinking/temperature settings, blank on pre-2026-08-10 lines — and a trailing INSTRUCTION column (2026-08-16: the saved Agent Instruction the run was launched from, SelfBot's active system prompt; blank on older and ad-hoc lines, and rolled up as a "By instruction" section in the SUMMARY) — the cost/time/calls columns sit before the model/params/instruction columns and are rendered with fixed-width format strings, not `Format-Table`, which silently drops trailing columns in a narrow console and hid the per-run cost the day the MACHINE column arrived), with explicit UTF-8 reads so Windows PowerShell 5.1 doesn't mojibake the logs' em-dashes.

Full details in [desktop_launchers/README.md](desktop_launchers/README.md).

## Cross-platform notes

A runtime `IS_WINDOWS` constant branches platform behaviour; Windows functionality is preserved exactly, macOS gets equivalents or graceful degradation:

| Feature | Windows | macOS |
|---|---|---|
| Shell tool | PowerShell | bash |
| Screenshots | `ImageGrab.grab(all_screens=True)` | Quartz `CGWindowListCreateImage` per display (pyautogui only sees the primary) |

| Instance detection | Lock files + `OpenProcess` PID + executable-name verification | Lock files + PID check |
| Dialog placement | `transient(parent)` works across screens | `transient()` skipped (WM confines transients to the parent's screen) |
| Monospace font | Consolas | Menlo |
| Launchers | `.bat` + PowerShell positioning | `.command` / `.app` (with Homebrew PATH injection so GUI-launched MCP `npx` resolves) |
| Scheduling | Task Scheduler (`pythonw.exe`) | launchd LaunchAgents |

**Privacy note — `.gitignore` is not retroactive.** A gitignore rule only suppresses *untracked* files; anything committed before the rule stays tracked and keeps being pushed. Two consequences in this repo, both from the era before the current rules:

- **`saved_chats/` is gitignored, and the legacy tracked files were pruned in 2026-07**: of the ~93 files committed before the rule, only the 39 SelfBot duo chats (the Shaun & Nigel self-conversations this repo exists to produce) remain tracked by choice; the other 54 — tool-test chats, one-off agent runs, and all 33 agent-run desktop screenshots — were untracked (`git rm --cached`). They still exist in *history* (and on disk locally), so a clone's old commits still contain them; chats saved since the rule are local-only, as intended.
- **`agent_instructions.json` / `skills.json` / `system_prompts.json` are gitignored and now live in `<OneDrive>/MyAppShare/`, but their pre-migration history is still in the repo** — instruction text of that era included personal email addresses, since the mail instructions needed them.

No API keys were ever committed (keys live in environment variables and `~/.config/` token files, both outside the repo; `mcp_servers.json` is gitignored with only `.example` tracked). If you fork or clone this, audit with `git ls-files <path>` for what's tracked *now* and `git log --all -- <path>` for what was *ever* committed — the gitignore entry alone proves neither.

**Conventions:** this is a testbed — keep code simple and focused. SelfBot, CSVEditor, TodoList and the bank extractor stay single-file (the native TodoList ports keep the convention as one file per platform, `TodoList.mm` / `TodoList.cpp`); MyAgent changes go in the appropriate mixin. Tests exist where the logic is pure: the characterization suite under `tests/` (run `python -m unittest discover -s tests -t .`), with `ruff check MyAgent.py myagent/` for linting — no mypy, and no build step for the Python apps (the `build_todolist_native.sh` / `.ps1` pair is the one compile in the repo, for the native TodoList ports). After editing a `.py` file, re-run it (closing any running instance first) — for the GUI apps, the running app is still the real test suite.
